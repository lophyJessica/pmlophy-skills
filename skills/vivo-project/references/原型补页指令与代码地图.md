# 原型补页：代码地图与指令骨架

评审 PRD 的「原型页面」列要出图，前置动作就是让本地 agent 把缺的页面补进 `99-产品原型prototype/`。

## 技术栈与约定（补页前先认这套，别引入别的）

- React 19 + TypeScript + Vite + react-router-dom 7；**没有 UI 组件库**，全部自写 CSS（`src/index.css` + 就近 `*.css`，如 `src/pages/engage/engage-steps.css`）。
- 弹窗统一用 `src/components/BusinessModal.tsx`（二次确认 `ConfirmDialog` 在同一文件）。
- 列表 / 分页 / 筛选的既有写法照 `TagManagementPage.tsx`、`PermissionUsersPage.tsx` 抄。
- 数据全本地 mock（`src/mock/*.ts`）+ Dexie（`src/db/cmsDb.ts`），不接真实接口。

## 文件地图（加一个后台功能页，只动这四类地方）

1. `src/config/menus.ts`——模块（顶部）→ groups（左侧组/叶子）。加叶子 = 在对应模块的 `groups` 数组末尾加 `{ key, label, path, implemented: true }`，并把新 path 追加进该模块的 `match` 数组。
2. `src/App.tsx`——import 新页面 + 加 `<Route>`。
3. `src/mock/<模块>.ts`——新页面要用的数据与下拉选项。
4. `src/pages/<Page>.tsx`——页面本体（可含同页弹窗）。

## ⚠ 口径已改：触达计划是**单页长表单**，不是向导

生产端实测（真系统截图 + 生产源码）是**单页长表单**：活动配置 → **受众筛选** → 内容配置（触达方式），**无步骤条**。原型原先的 `ChannelStepForm.tsx` 六步（活动设置 / 审批信息 / 受众圈选 / 内容配置 / 明细 / 预览）已改造为单页，旧 steps 定义**以注释保留**。

- 引用原型结构时，**别再说「第 N 步」「步骤条」「受众圈选」**——区块顺序写「活动配置 / 受众筛选 / 触达方式（内容配置）」，圈人区块叫**「受众筛选」**。
- **「明细」在生产端没有对应屏**，落点至今未定；写文档/做页面时一律写「明细（落点待定）」，**不许自己编一个落点**。
- 受众筛选区块的标签条件组实现落点是 `src/pages/engage/EngageTagFilter.tsx`（照生产端 `tag-filter` 复刻：快捷行、条件组最多 4 组、组间 且/或/非、组内 且/或、布尔运算符 为真/为假）——**往里加东西（如行为条件）时复用这一套组件与视觉，不另起一套**。
- 路由：复刻是 `/engage/create`，生产是 `/engage/engage-create`；原型已加 alias 路由对齐，两条都保留。

## 写补页指令前：先查原型现状，别重复造页面

用户会直接说「补 N 个页面」，但**先自己核一遍这些页面到底在不在**，否则指令会让 agent 重建已有实现：

```
find src -iname "*<关键词>*"            # 页面/组件是否已存在
find src -iname "*Behavior*" -o -iname "*behav*"
grep -n "权限中心\|用户行为" src/config/menus.ts   # 菜单叶子有没有
grep -n "behavior\|engage" src/App.tsx              # 路由注册了没
ls src/mock/                                        # mock 放哪、命名风格
```

结论写进指令的「落点约定」——把**已存在的东西**点名（如「权限中心分组已存在于 menus.ts，只加子项，不要新建分组」），把**新文件的落点**写死（如 mock 放 `src/mock/behaviors.ts`）。省掉一轮返工。

## 指令骨架（交给本地 Cursor / agent）

五段式，整段放一个 plaintext 代码块：

- **Context**：什么项目、改的是哪一层（复刻原型，不是生产端）、权威口径文件的路径（功能清单 / 字段清单详细稿 / Demo PRD / 已有对齐组件）。
- **落点约定**：菜单加在哪、mock 放哪、组件落在哪个文件——**逐条写死**，别让 agent 自己选位置。
- **Request**：逐条编号，写清改哪个文件、页面有哪些列/段/交互，字段名与 mock 值从 Demo PRD 逐字搬。
- **Output format**：改动文件清单 + `npm run build` 通过 + 自检截图路径（视口 1440，中文文件名）+ 「PRD 功能条 → 落在哪个文件 → 截图文件名」逐项自查表 + 字段与《字段清单详细稿》逐条对照 + **不 commit、不 push、不部署**。
- **红线禁止**：不新建项目、不装依赖、不引 UI 库、不动范围外页面、不删既有 UI（是否砍由用户定）、不做登录/权限实现、不改文档；**本轮明确不做的东西要点名禁掉**（例：V1 拍板不引入人群资产层，就写「严禁做任何人群相关界面（人群列表 / 人群包 / 选择人群）」——不写它就会「顺手」加上）。
- **Checkpoint**：分批做，每批做完截图停下等确认，不梭哈。

另：开头写明**执行位置**（`cms-project/99-产品原型prototype/`，跑在用户本机，不是 VPS）；遇到口径不明的地方（某块是替换还是新增、某 UI 砍不砍）在指令里写「本轮不许动」，同时在聊天里单独问用户，别让 agent 替你决定。

## 验收对方的 Checkpoint 交付：三先三后

1. **先答它的反问、再放行下一步**：agent 会列几条「请你确认的口径」（列顺序、控件形态、演示态怎么做）。答法＝**一条可直接粘贴的口径回复**（逐条编号、整段一个 plaintext 代码块），论证留在聊天正文里，别把分析写进要粘的块里。
2. **空/只读演示态用 URL 参数，不加页面开关**：`?demo=empty` / `?demo=readonly` 可接受；原型上加切换控件会干扰评审视线。约定「评审红框图只用有数据态那张」，其余留作备查。
3. **文案与列名逐字对齐 PRD**：agent 自查里冒出来的「停用按钮文案」这类出入，一律按 PRD 原文改，不让它自创说法；状态列用中文「启用 / 停用」。

## 坑

- 原型是**复刻**生产端、不等于生产端：说「原型里有 X」时要讲清是哪一层证据。
- 补完页面才能挂标注锚点、出整页红框图——链路顺序不能跳。
- 指令存 `05-提示词合集/NN-名称.md`（编号即版本），**先给用户看，用户点头再 push**；默认则是**聊天整段发**，不发文件。
