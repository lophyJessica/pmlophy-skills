# 用生产源码对齐复刻原型（cms-project）

复刻原型（`99-产品原型prototype/`）当年是照生产端“复刻”的，但缺口是被 AI 用常识补上的，导致结构级偏差（六步向导、页内渠道切换）。用户手上有生产前端源码后，「对齐」成为一条固定流程。

## 前提与位置

- 生产端源码在用户公司机本地：`E:\projects\源码管理\前端\cms-global\apps\content`（路由 `views/engage/router.js`）。**全程只读**——不改、不 git、不复制外传。
- 复刻原型在 VPS 仓库 `cms-project/99-产品原型prototype/`；Agent 跑在用户公司 ThinkPad（Windows）+ Cursor。
- **权威顺序：生产源码 > 真系统测试环境截图 > 复刻原型现状。** 冲突时以前者为准；任何结论必须能指出源码 文件:行号。

## 流程（四步，每步停下等确认）

1. **只读比对，出差异清单（不许改代码）**：定位生产端的相关页面（列表 / 创建 / 详情）、渠道定义、条件组件、预估人数接口，对着复刻原型的实现逐项比。产出 `08-相关资料/审计报告/<模块>-生产源码vs复刻原型-差异清单.md`，四节固定：
   - ① 生产端真实结构（页面清单与路由、入口与渠道怎么定、区块顺序与每区字段控件、按钮、涉及接口）——**这就是今后唯一口径**
   - ② 差异清单表：序号 | 类型（结构/命名/字段/控件/多出/缺失）| 生产端（文件:行号 + 摘录）| 复刻原型（文件:行号 + 摘录）| 建议改法
   - ③ **「生产端未找到」清单**：原型有、源码找不到出处的，逐条列出——这些就是当初被“补”出来的部分
   - ④ 影响最大的 3 条 + 自标的「需人工确认」项
2. **按清单只改一个页面**（先创建计划）：改完 `npm run build` 通过 + `npm run dev` 起本地预览，截图与生产端并排，停下等确认。
3. 验收后再推下一块（查看态 look / 列表其它部分 / 其它模块），一次一块。
4. 代码结构对完，才回去改文档口径（需求 list、PRD、Demo、UI 规范）。

## 反模式与坑（都踩过）

- **“补齐”提交是假现状的源头**：`git log -- <path>` 的提交说明常能看出某次走查把缺口用常识填了（六步向导、页内 6 渠道切换都这么来的）。缺口处优先找源码，找不到就写「生产端未找到」，**禁止反推**。
- **原型注释声称「对应生产端 xxxComp」没有证据力**（`activitySetting` / `audienceFiltering` / `contentWhatapp` 之类），不得当现状引用。
- **查看态的顶部区块最容易被误做成创建流程的步骤**：`planDetail`（执行报告）、`approvalInfo`（审批信息）被做成了“第 2 步 / 第 6 步”。判断法：看它在源码里挂在哪个组件、哪种态下。
- **枚举值 ≠ 展示文案**：源码里 `EMAIL` / `SMS` / `SMART_SMS` / `WHATSAPP` 是值，界面要显示中文文案（邮件 / 短信 / 富媒体短信 / WhatsApp）；按钮文案照源码（`提交` 不是 `确定`）、弹窗标题照源码（线上是「请选择触达渠道」，不是「新建触达计划」）。**从源码抄枚举一律取 label/文案字段，并全站扫同类问题**（列表筛选项、列表列、状态列、触达类型/推送方式、WhatsApp 三模式）。
- **给 agent 的红线要写「删掉的东西先注释保留，不要物理删除」**：不写就直接删。已删实现能从 `HEAD` 取回（未提交时原版仍在），但白多一轮。
- **验收必须看代码，不能只看截图**：截图只验外观；命名、字段、条件结构要用户 push 后我 pull 下来读代码核（「我 pull 下来核一遍才算数」）。
- **条件区块（受众筛选）不许用 mock 结构糊过去**：本期新功能（行为条件）就挂在这个条件结构上，地基简化必返工。要求逐项复刻：分组与顺序、筛选项取值文案、条件组的字段/运算符/取值域、条件之间的组合关系（交/并/非）在数据结构里怎么表达、区块按钮及其触发、漏斗人数字段对应的真实接口名。
- **「留项」不等于“可以不补”**：agent 自己列的留项里，凡本期需求要用到的（条件结构、筛选项），当场驳回、不算留项；只有真属范围外的（列表其它部分、查看态）才允许留下。

## 交付形式

- 指令**整段发聊天**（一个 plaintext 代码块），**不发文件**；不要让 agent 把指令写成附件。
- 每轮附一段可直接粘贴的**提交备注 body**（用户自己在 Cursor 提交，标题他定）。
- 让 agent 在汇报里固定给：改动文件清单 / build 结果 / 预览地址 / 截图路径 / 逐条对照表 / 留项——少一项就退回。
