# 内销 CMS「用户行为」配置字段全貌

内销把「事件配置」叫 **「用户行为」**（不叫事件标签）。外销做事件标签时这是唯一的对齐参照，用户会拿内销截图来对。

## 一、菜单位置

```
顶部导航：触达计划
  └ 左侧：IMS智慧运营 → 触达配置
        ├ 用户标签      ← 静态标签
        ├ 用户行为      ← 动态行为（= 外销的事件配置）
        ├ 机型分类
        ├ 内容模板
        ├ DMP人群
        └ 活动分类
```

「用户行为」与「用户标签」同级（都在「触达配置」下）。

## 二、列表页（很轻）

只有 4 列 + 右上「新建行为」+ 分页（共 24 条）：

```
行为ID   行为名称                        创建时间              操作
 39      X系列新品人群（短信通道补量）    2026-10-15 17:07:56   编辑
 36      预售标签                         2026-08-21 15:26:30   编辑
 35      用户剩余积分                     2026-08-31 15:47:46   编辑
 34      是否用户生日当月                  2026-08-31 15:46:58   编辑
 29      用户在朋友圈互动                  2026-05-07 15:52:25   编辑
```

**没有状态列，也没有启用/停用按钮**，行操作只有「编辑」。停用疑似靠后面的「使用范围 = 无」。

## 三、新建/编辑弹窗：11 个字段，按作用分三段

**第一段 · 这是什么行为**

| 字段 | 说明 |
|---|---|
| 行为ID | 系统生成，灰显不可改 |
| 行为名称 | 必填，**限 20 字** |
| 行为描述 | 必填，**限 500 字** |

**第二段 · 数据从哪来、怎么认人**

| 字段 | 取值 |
|---|---|
| 数据源 | 直接写数仓表名，**只读**。例：`cms_prd.da_yivominip_trade_presale_event_df` |
| 行为维度 | `imei` / `unionid` 单选 |
| 允许限制时间范围 | `允许` / `不允许` 单选 —— **这是开关：允不允许圈人时再加时间范围**。1029 实机取证已闭合：选「不允许」后，圈人侧「筛选条件2(行为)」里该行为的 开始日期~结束日期 **仍然展示、但置灰不可选**（不是隐藏）；且**行为定义弹窗里那两个单选项下方没有再加任何辅助说明文字** |
| 行为有效时间 | 生效区间 |

**第三段 · 行为怎么被使用**

| 字段 | 取值 |
|---|---|
| 行为触达时机 | **只有两项：`DELAY-延迟` / `AT_ONCE-立即`**，**`BEFORE-提前` 不支持**（1028 定稿，用户多次纠正：界面上内销弹窗虽然三个复选都显示，但业务只用两个）。外销弹窗只出现这两项，BEFORE 不出现；本期默认全选、置灰不可改 |
| 数据更新时间 | 每天几点刷新，如 `04:00` / `10:00` |
| 使用范围 | `全量使用` / `部分可使用` / `部分不可使用` / `无`，后三者需再选组织 |
| 行为属性 | 表格，带「更新属性」按钮，见下 |

**行为属性表的列**（决定圈人时能筛什么）：

```
序号 | 字段名称 | 字段描述 | 字段类型 | 是否可限制组织权限
 1   | user_type              | 用户类型   | 字符串 | □
 2   | presale_main_config_id | 预售活动   | 字符串 | □
 3   | order_status           | 预售状态   | 字符串 | □
```

字段描述限 20 字。

## 四、内销「预售标签」整条实样

```
行为ID            36
行为名称           预售标签
行为描述           预售行为
数据源             cms_prd.da_yivominip_trade_presale_event_df
行为维度           unionid
允许限制时间范围     不允许
行为属性           presale_main_config_id（预售活动）
                  order_status（预售状态）
```

**这就是内销「预售标签」的全部配置**：一张数仓表 + 两个可筛属性，跟外销方案的「预售订单事件」是同一个东西。

## 五、内外销字段差异（提方案时必须先摊开让对方选）

**内销有、外销方案没有的（5 项）**

| 字段 | 影响 |
|---|---|
| 允许限制时间范围 | **直接影响圈人交互**——设为「不允许」时圈人的时间范围要置灰 |
| 行为有效时间 | 生效区间 |
| 行为触达时机 | 事件发生后多久发（延迟/提前/立即） |
| 数据更新时间 | 每天几点刷新 |
| 使用范围 | 同时承担「停用」和「组织级可见」两件事 |

**外销有、内销没有的（2 项）**

| 字段 | 说明 |
|---|---|
| 事件编码 | 英文小写下划线、全局唯一、创建后不可改。**内销没有编码概念**，靠行为ID 关联 |
| 状态（启用/停用） | 内销没有状态列，靠「使用范围 = 无」停用 |

**不要默认照搬内销全量字段**——外销 V1 只接预售一条事件，把内销 11 个字段搬过来是过度设计。但「允许限制时间范围」必须补，否则圈人交互跟内销对不上。给用户两条路选：A 对外销做全（评审好对照、运营不陌生）vs B 保持精简 + 只补关键两项。
