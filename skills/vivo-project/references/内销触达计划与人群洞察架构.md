# 内销触达计划 · 人群洞察 · 社群运营（形态与架构参照）

内销（CMS 用户运营系统）是外销做「用户行为 / 受众筛选 / 触发型」时的唯一参照物。用户会拿内销截图来对，必须能一眼说清「内销怎么做、外销哪一层不一样」。

配套：字段级差异见 `references/内销用户行为配置字段.md`（那张讲「用户行为」这条配置本身）。本张讲**行为在触达链路里被用在哪、人群怎么成为资产**。

## 一、内销触达计划新建 = 节点式编排，不是分步向导

页面构成：基础信息（计划名称 0/50、活动分类、机型分类）+ 中央**流程画布** + 右侧常驻**人群预估**面板。

```
[ 触发条件 ]            ← 「点击设置触发类型、触发时机」
     │
     ▼
[ 目标人群 ]            ← 「选择目标人群」
     │
     +                    ← 可继续加节点

右侧：人群预估 · 圈选人数 / 可触达人数 / 开始预估
```

- 右侧预估**只有两层**（圈选人数、可触达人数）；外销真系统是**三层**（圈选人数 / 有手机号人数·邮件渠道为有邮箱地址人数 / 可触达人数）。**不要拿内销两层去改外销三层。**
- 判形态别只看截图：内销触达计划是节点/画布式；社群运营那条线是**分步（活动配置 → 受众筛选 → 内容配置）**；外销真系统触达计划是**单页长表单**。三条线三种形态，别互相套。

## 二、触发条件 → 弹窗「设置触发类型」

卡片式单选（不是下拉），三张卡 + 说明文案：

| 选项 | 说明文案 |
|---|---|
| 定时型-定时触发 | 在指定时间，对用户进行触达 |
| 触发型-完成A | 当用户完成某个行为或者满足某个条件后对用户进行触达 |
| 触发型-完成A未完成B | 当用户完成某个行为后，一段时间内未完成另一个行为后对用户进行触达 |

另有「推送时间」卡片：定时下发（根据所选时间，定时推送）/ 最佳时间下发（预测各用户最可能活跃的时间）。底部取消 / 保存。

**选「触发型」后弹窗内展开四个区块**：触发类型 / 触发事件 / 触发时机 / 推送时间。

- 触发事件：「在 [开始日期] - [结束日期] 期间，用户完成以下行为」，空状态左侧「添加用户行为」、右侧按钮「+ 添加事件」
- 触发时机：「延迟 1 天 对用户进行触达」
- 文案是业务语言（「完成某个行为」「一段时间内未完成另一个行为」），比内部字段名更适合抄进 PRD 描述

## 三、目标人群 → 引用「人群」资产，不自己圈人

弹窗「设置目标人群」只有三样：`选择人群 *` 下拉 + 刷新 + `新建人群`，加一句引导语：

> 需要先创建人群后才可选择人群绑定（**人群洞察是触达的核心**，系统将逐步培养您先洞察再触达的习惯）

**这是内销最值得引用的架构点**：条件不写在计划里，而是沉淀成**可命名、可复用的人群资产**（有「人群名称」「适用场景」字段），触达计划只引用；同一个计划可以换人群、同一个人群可以被多个计划引用。

## 四、人群洞察 / 新建人群（人群资产的建法）

区块顺序：

1. **选择组织机构**：组织架构下拉 + 「请输入要搜索的区域/门店」+ 组织树 + 「已选 N 个 / 清空」
2. **配置用户关系**：左侧「用户关系选择」（如「用户最近门店绑定企微」「在门店购买过手机的用户」）+ 右侧「已选」，带 + 号添加
3. **筛选人群**：提示「对已选的组织架构内人群进行筛选，至少填写一条筛选条件」；字段「用户范围 *」= 存量购机人群 / 已添加企微人群；辅助说明「可以通过标签或者用户行为进行人群筛选」
4. **条件页签三个**：`用户标签` / `用户行为` / `DMP标签`（用户标签下分组：社会属性、设备与网络属性、兴趣爱好、消费与价值、营销与转化、A/B测试、触达过滤）
5. **固定条件**：行式字段+运算符+值（如「所属门店属性 等于 全部」「关闭个性化广告用户 不包含」「添加导购企微 全部」）
6. 底部两个入口：`+ 添加标签筛选组` / `+ 添加行为筛选组`
7. **基本信息**：人群名称 *（0/20）、适用场景 *（0/200）；底部「人群估算 / 保存人群 / 取消」

要点：**标签、行为、DMP 是同一层的三类条件源**，各自出条件组，合成一个人群。

## 五、行为在内销被用在两个位置（同一个行为库）

| 位置 | 怎么用 | 对应外销 |
|---|---|---|
| 触发侧 | 触发条件 → 触发型 → 触发事件里「添加用户行为 / + 添加事件」 | 外销二期「生命周期触发型事件」 |
| 圈人侧 | 人群洞察 → 新建人群 → 条件页签「用户行为」（与用户标签、DMP标签并列） | 外销本期「受众筛选里的行为条件」 |

**推论（提方案时要讲）**：行为定义必须**一套、两处可引用**。只做圈人侧、把行为绑死在计划里，二期做触发侧时会出现两套定义 / 两套 JSON 语义。本期落点可以只做圈人侧，但结构上要让行为定义独立成对象、可被计划外引用。

## 六、社群运营那条线（圈的是「群」，不是「人」）

- 形态：**分步三步**——活动配置 → 受众筛选 → 内容配置（与触达计划的节点式不同）
- 第 1 步活动配置字段：计划名称（0/50）、活动分类、机型分类、触发类型（卡片：定时型-定时触发 / 触发型，说明「在某个时间点下发任务给导购」）、推送时间
- 第 2 步「受众筛选」实为圈群：
  - **选择社群**：选择组织（区域/门店）+ 已选 N 个 / 清空
  - **筛选社群**：左侧「社群标签」列表（可从列表**拖拽标签**到条件组），右侧「固定条件：门店所属类型 = 全部」+ 条件组「筛选条件N」（行内：标签 + 等于 + 值，可多个值）+ `+ 添加社群标签筛选组`
  - 底部预估：**覆盖群个数 / 覆盖群成员总数**（不是人数）
- 标签库管理（工具中心 > 标签管理 > 标签库管理）分**两个页签：社群标签 / 好友标签**，列 = 标签组名称 / 可见范围 / 标签名称。社群标签的标签组样例：工厂试点社群、门店默认群、渠道来源、TO-G 社群、是否需拉会话存档、iQOO试点社群、运营商厅店社群……

**结论**：内销有两条平行资产线——**人群**（人的标签/行为/DMP）与**社群**（群的标签）。行为与标签真正被归纳进的层级是**人群**，不是社群；社群只有「群」维度的标签。

## 七、对外销设计的取舍（别照搬）

> 取舍的**方法**（差异三分类：形态 / 能力 / 架构；「底子 vs 面子」切法；对外话术；拍板时的呈现方式）见 SKILL.md「三之三、内外销对标类产出」。

| 内销做法 | 外销要不要跟 |
|---|---|
| 计划只引用人群资产，条件不在计划里 | 本期**不立人群资产层**（成本高），但条件集要封装成可独立引用的对象，二期做人群库时直接复用 |
| 行为同时用于触发与圈人 | 本期只做圈人侧，**行为定义做成通用的**，二期触发侧复用同一套 |
| 触达计划节点式画布 | 不跟——外销真系统是单页长表单，形态照生产源码，不照内销 |
| 预估两层 | 不跟——外销真系统三层，且第二层名随渠道变 |
| 触发类型卡片 + 业务语言文案 | 可抄文案风格（「在 X 期间完成以下行为」「延迟 N 天触达」） |
| 固定条件 / 拖拽标签入条件组 | 可参照，非必须；外销现状是 select 树 |

## 八、位置对照与「能不能搬」（领导比对的第一层）

**菜单结构对照**

| 内销（门户）顶级 | 外销 CMS 顶级 | 是否一致 | 差异缘由 / 处理 |
|---|---|---|---|
| 首页 | 无独立首页，默认进业务域 | 不一致 | 外销为单系统直进业务；如需对齐可后补，低优先级 |
| 触达计划 | 触达计划 | **一致** | 同名 |
| 运营报表 | **数据报表** | 命名不一致 | 同类能力，建议统一命名口径 |
| 工具中心 | 工具中心 | **一致** | 同名；内销的标签管理挂这里，外销需把标签管理从权限中心移入 |
| 组织管理 | **组织架构** | 命名不一致 | 同类能力，建议统一命名口径 |
| 无 | 权限中心 / 配置中心 | 外销独有 | 门户由各系统自理权限；外销的配置类能力单独成域 |

命名不一致最容易被当成「两个系统不一样」，评审要主动说明；结构对照组来源：外销側 `99-产品原型prototype/src/config/menus.ts` + `01-全局背景信息/参考资料/CMS知识宝典_V3.0.md`，内销側为只读截图。

**「标签管理 + 用户行为移到工具中心」的可行性——必须分三层说，不能只说「可行」：**

1. **结构可行**：外销顶级菜单里已经有「工具中心」且已有内容（卡券管理 / whats管理工具下的账号列表·好友列表·欢迎语·模板）→ 是**换挂载点，不是新增顶级域**。
2. **机制可行**：归属是**菜单数据**而不是前端路由——标签管理生产路径 `/main/content/tag-management` 属 content 域、却挂在权限中心，**路径 ≠ 菜单位置**；生产有「菜单资源管理」（`/main/channel/channel/resource`）；角色数据里已有「工具中心,标签管理角色」这种**可独立授权的项**（说明它是能被授权、也能被移动的对象）。
3. **未核实的前提（拿不到就不要下结论）**：① 生产真实菜单树怎么挂的（原型/知识宝典是二手）② 移动影响面（角色授权记录、菜单资源、历史链接）③ 有没有后端逻辑按「菜单归属」判权限。

对外结论句式：**结构可行、机制可行、影响面待核实**。

## 九、圈人颗粒度 10 维对照（「对齐颗粒度」的具体抓手）

对齐颗粒度是链路的**第一步**（颗粒度→锁定人群→洞察→触达）。提到领导面前就是这张表，逐条标一致/差异 + 缘由：

| # | 维度 | 内销 | 外销（含本期新增） | 一致性 | 缘由 |
|---|---|---|---|---|---|
| 1 | 组织范围 | 组织架构树 + 已选N个/清空 | 组织架构 / **导入门店**（上传+下载模板） | 基本一致 | 外销多「导入门店」，适配跨国批量导入 |
| 2 | 用户范围（入口池） | 存量购机人群 / 已添加企微人群 | 全部用户 / 线下购机用户 | 部分一致 | 内销私域核心是企微、外销是 WhatsApp，池的命名与来源随渠道体系不同 |
| 3 | 用户关系条件 | 最近门店绑定企微 / 在门店购买过手机 | 无独立关系条件（近似能力在用户池） | **差异** | 外销无企微体系；「购买过手机」已有近似 |
| 4 | 标签条件 | 用户标签（7 分组） | 快捷标签行 + 条件组（≤4 组、且或非） | **一致**（形态不同） | 外销快捷行与内销固定条件作用相近 |
| 5 | 行为条件 | 条件页签「用户行为」 | **本期新增**（含/排除+属性+时间范围，≤5条） | **对齐中** | 本期 V1 核心交付 |
| 6 | DMP 标签 | 条件页签「DMP标签」 | 无 | **差异** | 数据源未接入，与二期 #5/#6 相关 |
| 7 | 固定条件 | 有独立层（与标签/行为叠加、恒生效） | 无（散在快捷标签行） | **差异（建议对齐）** | 内销这层分工干净，建议把「恒生效的过滤」独立成层 |
| 8 | 对象层级 | 人（人群）+ **群**（社群运营） | 人/设备（6 渠道） | **差异** | 外销业务未提群触达诉求，需业务确认 |
| 9 | 触发条件 | 定时型 + 触发型（完成A / 完成A未完成B） | 仅定时型 | 阶段差异 | 二期 #3 |
| 10 | 人群资产 | 保存人群（命名 + 适用场景 + 可复用） | 无（条件写在计划内） | 阶段差异 | 外销 V3 规划「行为条件保存为可复用人群包」 |

**结语句式**：10 个维度里**标签（4）与行为（5）是圈人主干**——一处已一致、一处正在对齐；差异集中在 **DMP 标签、固定条件分层、用户关系、群维度** 四项，前三项列入后续版本并给缘由，群维度需业务确认。
