# 内销对标取证口径（外销 CMS 项目）

用于「对外销方案做内外销一致/差异说明」这类任务。内销系统源码独立、只读、不外传；只能靠用户机器上的 Cursor 内置浏览器抓图/取 DOM。**没取到的不要断言**——写“未观察到”，不要写“内销没有”（曾据“没看到启停”推断内销无此功能，用户当场取证推翻）。

## 取证法

三证据对齐：源码证据（文件:行号）、页面截图证据、DOM 证据。缺一标「单证据·待核」；冲突以源码为准并单列一节。枚举一律取中文展示文案，不许拿枚举值当文案。

## 已取到的内销口径（可直接引用，引用前确认未过期）

**菜单位置（关键，且曾判错）**
- 「用户行为」在 **活动计划 > 触达配置 > 用户行为** 下；同级还有 **用户标签 / 机型分类 / 内容模板 / DMP人群**。即：内销把「圈人原料」这类配置统一收在**触达配置**下（靠触达/活动域）。
- 标签库管理（含社群标签/好友标签分页签）在**工具中心**——那是另一个页面，不要与「用户标签/用户行为」混为一谈（此处混淆过一次，把结论带偏）。

**用户行为列表形态**
- 列：行为ID / 行为名称 / 行为维度 / 行为描述 / **启用状态（开关）** / 创建人 / 创建时间 / 操作（只有「编辑」）；右上「新建行为」。
- **启停 = 列表里的开关**，不是「停用按钮 + 二次确认」那一套。
- **列表没有筛选区**（无搜索、无状态筛选）——样本仅几十条；外销是否保留检索要单独说明缘由，不要盲目对齐删掉。

**触达计划（内销）**
- 节点式编排：触发条件 → 目标人群，节点下方可继续加；右侧常驻「人群预估」（内销**两层**：圈选人数 / 可触达人数）。
- 触发型三态：定时型-定时触发 / 触发型-完成A / 触发型-完成A未完成B；推送时间：定时下发 / 最佳时间下发。
- 外销真系统是**三层**预估（圈选 / 有手机号 / 可触达，第二层名随渠道变）——不要拿内销的两层去改外销的三层。

**人群洞察（内销）**
- 新建人群页签三类条件：用户标签 / 用户行为 / DMP标签；另有组织范围、用户关系、固定条件。
- **同一套「用户行为」两处复用**：触发侧（触发事件里加行为）与圈人侧（新建人群的行为页签）共用同一行为库——这是“行为定义必须一套、两处用”的原始依据。

## 对标的写法

- 默认对齐；不一致的每条给**能说服人的缘由**（分「该改的 / 阶段差异 / 以我方为准」三类），不要只列差异不给原因。
- 判断主线：**原料 → 圈人 → 触达** 三段（外销口径更前置：先对齐圈人颗粒度 → 锁定人群 → 洞察 → 触达）。
- 文档里不写“与某同事已确认”当依据——只写事实性来源（“参考内销的事件与标签设计”）与目的（“满足业务灵活配置圈人”）。

## 事件 vs 标签（评审常被问到，可直接引用）

事件支持**动态属性筛选**（预售活动、订单时间、状态），标签只支持**静态画像且条件写死**——这是“为什么不能直接用标签圈预售人群”的标准答复。分工口径：大数据提供**事件数据表**，服务端**读取表**做圈选与触达（该口径需与开发确认时效）。
