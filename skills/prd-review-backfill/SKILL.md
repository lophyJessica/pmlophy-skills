# 评审PRD 变更回写（评审PRD → 权威源）

## 何时用
评审PRD 是活文档，开发中会持续更新；改动后要把变更**回写进权威源**（字段清单 / 主PRD / Demo），避免各文件漂移。用户说"回写 / 同步权威源 / 评审PRD改了要更新"时使用。与 `prd-backfill` 方向相反——那是"前端代码→回写PRD"（代码为准），这是"评审PRD→回写权威源"（评审PRD为准）。

## 核心原则
1. **权威性 = 评审PRD 为主**（用户定）：评审PRD是最新拍板结果，与权威源冲突时**回写覆盖权威源**，绝不反过来质疑评审PRD。评审中拍板改的规则，就是主PRD该有的。
2. **人为主动触发**（用户定）：不自动监听，用户说"回写吧"才跑。通常一天结束集中执行一次。
3. **靠 diff 主动找变更**（用户定）：不靠人记"我改了啥"，用 `diff_backfill.py` 对比评审PRD vs 权威源自动列出差异。
4. **回写后必须校验**（用户定）：执行完反向对比，确认权威源 = 评审PRD，不一致的项标记未完成。

## 回写映射（评审PRD 哪块 → 哪个权威源）
| 评审PRD 改的块 | 回写目标 |
|---|---|
| 字段六列（新增/删除/必填/来源/说明） | 字段清单 |
| 业务规则表（5.x） | 主PRD 核心业务规则 |
| 状态流转表（四） | 主PRD 状态机/状态流转表 |
| 页面和操作（六.x） | Demo_列表页/详情页/新增编辑页 |
| 流程图 / 验收 / 权限 | 主PRD 对应章节 + 监管清单勾选项 |

## 找变更（脚本 `scripts/diff_backfill.py`）
对比评审PRD 的字段表 + 规则表 vs 权威源，输出**三层差异**：
- **① 确定差异（必回写）**：权威源真缺该字段/规则，或必填性真变了。
- **② 需人工确认**：疑似同字段不同名 / 来源与说明详细度不同 / 规则措辞不同（语义可能一致，人看一眼决定）。
- **③ 一致**：不回写。

用法：
```bash
# 待回写清单（干跑，只列出，不改文件）
python3 scripts/diff_backfill.py --review-prd <评审PRD.md> --field-src <字段清单.md> --main-prd <主PRD.md> --only-diff --table
# 只给人确认的疑难项
python3 scripts/diff_backfill.py ... --confirm-only
# 全量三段对比
python3 scripts/diff_backfill.py ...
```
脚本内置：三页同名字段去重、字段别名归一（客户名称=关联客户、当前阶段=商机阶段、商品明细=关联商品）、来源详细度降噪（权威源通常比评审PRD详细）、必填性归一（系统自动/系统生成/只读视为一类）。

## 回写步骤
1. **跑 diff** 生成待回写清单（干跑，确认差异范围）。
2. **人确认** ② 需人工确认的项（判断是"表述不同无需改"还是"评审PRD真新增/真改"）。① 确定差异直接可回写。
3. **执行回写**：按映射逐条改权威源文件的对应处，**以评审PRD内容为准覆盖**。不改无关内容、不顺手重构。
4. **回写后校验**（用户强约束）：重跑 `diff_backfill.py --only-diff`，确认 ① 确定差异已清零；残留的项标记未完成，回报人。
5. **补修订记录**：权威源文件若有修订记录章节则追加（日期+改了啥+依据=评审PRD）。
6. commit + push，回报改了哪些权威源文件、依据是评审PRD哪块。

## 校验门（回写后必做）
- [ ] 确定差异（①）已清零？
- [ ] 需人工确认（②）逐条给了结论（改/不改）？
- [ ] 权威源与评审PRD关键内容一致？
- [ ] 只改了受影响的权威源文件，无无关文件混入？
- [ ] 修订记录追加、依据标注"评审PRD"？

## 红线
- **以评审PRD为准，不反向质疑评审PRD**（用户定权威性）。评审拍板改的，权威源就该同步。
- 回写是改权威源（字段清单/主PRD/Demo），**不动评审PRD本身**（评审PRD是来源）。
- 只改差异涉及的少数几处，不重排/不重构/不顺手改无关内容。
- 规则匹配弱化：评审PRD精简表述 vs 主PRD严谨规则措辞不同≠真差异，归为"需人工确认"，别自动改成评审PRD措辞。
- 字段别名归一后仍冲突的才算差异，别把同一字段两种叫法当新增。
