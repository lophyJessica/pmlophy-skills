# Mermaid 图表编写（交付档场景）

PRD / 方案里的图用 Mermaid 源码而不是导出图片：能回写、能 diff、跟文档一起版本管理。代价是渲染效果受渲染器版本限制，而**这些限制不报错，只会默默画错**——所以每张图写完必须真渲染看一眼，不能只核源码顺序。

## 写之前先定三件事

1. **业务流程图还是系统流程图**。业务流程图 = 谁在什么场景做什么、系统怎么响应；系统流程图 = 系统间交互与数据流转（谁向谁要什么、给回什么）。两者都要，缺一个评审就会问。
2. **方向**：线性步骤多用 `flowchart TD`，分支与回流多用 `flowchart LR`；同一套件内方向统一。时序图只在「跨两个以上系统 + 调用先后是表达重点 + 流程图会丢信息」三条同时成立时才用。
3. **能力边界**：确认要的效果 Mermaid 能不能做（见下方边界表），做不到就先讲清取舍再动手。

## 流程图（flowchart）

- **首尾必须有开始和结束节点**，缺了就是没头没尾。
- **开始节点必须出现在全图最前的位置**，不能落在中途。它属于哪条泳道就写在那个 subgraph 内第一行，指向该泳道第一个业务节点；结束节点写末尾。
- 形状：开始/结束用体育场形 `(["开始"])` / `(["结束"])`（两端半圆的胶囊/椭圆），**不要用 `(("开始"))` 正圆**；中间业务节点保持方角 `[...]`，评审才分得清出入口。
- **源码顺序 ≠ 渲染位置**：Mermaid 按连线关系自动布局，写在第一行也可能被排到中途（典型跑到判断节点左下方），有回流连线时尤其明显。判断标准只看渲染结果；偏离时按序试：① 精简或改写回流连线 → ② 减少跨 subgraph 连线 → ③ 仍不行就把该泳道拆成独立一张图。
- 分支条件写在箭头上 `B -->|条件| C`，不另起文字说明。

## 时序图（sequenceDiagram）

- **不用 `rect rgb(...)` 做背景着色分块**：旧版渲染器（Cursor 内置、部分语雀/Confluence）不认，会把 `rect [rgb(245,255,245)]` 当组合片段标签原样画成文字。要分段就写 `Note over A,B: ① 段名`。
- 删 `rect` 时**连对应的 `end` 一起删**，否则时序图多出一个无配对的 `end`，语法直接坏。删完核：块内 `end` 行数应为 0，Note 与箭头行数不变。
- **人物角色用 `participant` 而不是 `actor`**：`actor` 人形图标比方框高，旧版不给名称留间距，角色名会和第一条消息文字叠印。写 `participant BIZ as 业务 / 运营（人）`，靠名称里的「（人）」区分人机。
- `autonumber` 会占消息线上方的高度，拥挤时先去它试。
- 参与者超过五个时横排挤不开也容易叠，必要时合并同层参与方（如两个下发通道合成一框），并在图注里写清合并了什么。

## 泳道能力边界（先讲清再动手，别承诺做不到的效果）

subgraph 只是**分组框**，位置和尺寸全由布局引擎算：

| 想要的 | 能不能 | 说明 |
|---|---|---|
| subgraph 泳道分组 | 能 | 框内节点文字、连线完全可控 |
| 泳道高度/宽度一致 | **不能** | 没有设尺寸或最小尺寸的语法，`style` 只改填充与描边 |
| 竖角色列 + 横阶段行的矩阵式泳道 | **不能** | 那是 draw.io / Visio 一类绘图工具的产物 |
| 开始节点精确落在最顶 | **不保证** | 按连线自动布局，见上文 |

**取舍口径**：要矩阵泳道、泳道对齐这类效果时，**优先保留 Mermaid 语法、接受布局不齐**——可回写、能 diff、随 PRD 版本管理；换成绘图工具导出的图片虽然规整，但改一个节点就要重画重导，还会变成不能被 diff 的二进制。遇到这类要求先把边界和两条路摆给用户，不闷头做成图片再解释。

## 内容与文档的一致性

- 图里的每一个环节都要在正文有对应依据。**图里写了、正文没写**的环节（如“预估人数三层漏斗”这种真实存在的交互）要么补进正文，要么从图里去掉——评审看着图问正文，答不出就是缺口。
- 图上不能出现原型没有、正文也没有的步骤，尤其不能为了“看着完整”补节点。
- 系统交互里的每一跳必须有依据。不确定某一步到底调不调外部系统时，**不要自行补一条系统间连线**，先向用户或开发确认；只能写出确定的那一跳，并在图注里说明“其余交互待确认”。

## 验收

- 图写完**必须真渲染**给人看一眼，重点核三样：开始节点是否在最前、有没有文字叠印、颜色块/片段标签是否变成了文字。
- 交付档里图改完后，引用它的文档要重新生成（base64 发布版从引用版重生成，不在发布版上直接改）。
- 项目内若有 `06-产品方法论/流程图规范.md`，以那份为项目级权威，本 skill 是通用做法；两边冲突时按项目规范，并把新坑回写进项目规范。
