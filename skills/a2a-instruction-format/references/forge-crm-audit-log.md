# forge-crm 全局审计实录 (2026-07-17)

## 审计流程

```
PRD文档 → 用例数据推演 → P0死结发现 → 人确认 → 修正PRD → 前端开发 → 全局审计 → P2优化
```

## 两轮推演发现

### 第一轮:线索管理

| 级别 | 问题 |
|------|------|
| P0-1 | PENDING_ASSIGN无法废弃(动作矩阵禁止+状态机无流转线) |
| P0-2 | 公海认领流转冲突(状态机说回PENDING_ASSIGN,交互规范说直接ASSIGNED) |
| P1-3 | 列表列缺失(手机号/邮箱在字段清单标为展示但Demo未列入) |
| P1-4 | 展示列数不一致(清单说8列,Demo有11列) |

### 第二轮:商机管理

| 级别 | 问题 |
|------|------|
| P0-1 | CONTRACT阶段无法输单(矩阵禁止+详情无按钮) |
| P0-2 | 进入CONTRACT前置死锁(要求合同编号→但合同编号由推进后回写) |
| P0-3 | 看板拖拽阻断输单(仅相邻列可拖→OUT不邻接任何列) |
| P1-4 | 列表列SSOT不一致(合同编号/创建人) |
| P1-5 | 需求描述选填与流转前置冲突 |

### 第三轮:全局审计(前端完成后)

| 级别 | 数量 | 说明 |
|------|:---:|------|
| P0 | 0 | 前两轮死结全修 |
| P1 | 0 | 字段全对齐 |
| P2 | 3 | 客户→商机传参/订单号链接色/分页交互 |

## 关键教训

1. **用例推演不得跳过**——前端开发前的强制关卡。跳过一次被纠正,二次又跳再次被纠正。
2. **看板拖拽规则需特殊处理输单列**——日常流转"相邻列",输单是"任意非终态→LOST"。
3. **合同生成的时序**——先启动合同流程(入CONTRACT),后回写合同编号(出CONTRACT入WON)。
