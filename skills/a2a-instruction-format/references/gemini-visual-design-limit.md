# Gemini/反重力 视觉设计局限性

## 问题
反重力在 WMS 项目中连续换 4 次方案(ElementPlus→Indigo→Arco→AntDesign),每次在新地基上重画,结果始终不满意。

## 根因
- 反重力擅长原型速度、执行精确指令,但缺乏视觉审美能力
- 从零设计 UI 不是它的强项——它会用组件库但不会"设计"

## ERP 成功的模式
- 供应商档案单模块先行(改一个页面验证 antd 可行)
- 确认效果→基础资料推广→采购管理梭哈→全量完成
- 关键: 每次改动范围小,可快速验证回退

## WMS 失败的教训
- 从零重建多次,每次全量推翻
- 没有"先做一个小模块看看"的阶段
- 应该: 删光旧代码→只做 Login+Dashboard→确认风格→再铺 12 个页面

## 规则
1. 反重力做 UI 迁移: 小模块先行→验证→梭哈
2. 反重力做全新 UI 设计(从零搭项目): 不派给反重力,用 Cursor
3. 换皮/换组件库: 一个页面跑通再全量
