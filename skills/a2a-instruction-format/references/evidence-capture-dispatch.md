# 取证类任务（需本地浏览器 + 登录态）的派活与验收

适用：需要**在真实系统页面上取证据**的任务——生产/内网页面截图、整页红框图、DOM 结构抓取、并排对比图。这类任务只能派给**跑在用户机器上、且浏览器里已有登录态**的 agent；派之前先确认它的环境能力。

## 一、派活前先确认 agent 环境（三问）

1. **它能不能访问输入**？沙盒常只允许读指定的盘/目录 → 让用户把材料复制到它能读的位置，并在指令里给**文件清单**（文件 → 源路径 → 大小 → 谁需要）。
2. **它有没有登录态与内网？** 只有远程桌面、无内置浏览器、网络不在内网的 agent，做不了“打开系统页面看/截/点”的活——这类只能派给用户本机 IDE 里的 agent；反过来，**不需要登录态、不要浏览器、输入自包含的活（文档加工、代码、数据转换）才能派给它**。
3. **它能不能跑所依赖的运行时？** 截图/渲染脚本常需 Playwright、浏览器内核、Mermaid 渲染器等——先问/先查，别等它跑到一半才卡住。

## 二、截图类指令的必备写法

- **分段跑**：首轮只跑一页（3 张左右）停下让用户确认**命名与框位**，确认后再跑其余；一次全跑完，命名或框位错了就得整批返工。
- **虚拟页→真实 URL 映射**：标注/配置里的逻辑页路径未必能直接打开；弹窗类要映射到“触发它的页面”，页签类要映射到带参数的可展开地址。指令里把映射写死。
- **渲染等待**：给一个显式等待（如 2.5s），否则截图常拿到未渲染完的页面。
- **锚点缺失即失败**：取不到目标区域的坐标时**直接报错退出**，不许输出一张没有标记框的图——无框图混进交付比缺图更坏（后面没人看得出来它是废的）。
- **脚本允许小改，但要报账**：适配新项目的配置/路由时允许改脚本，要求交付说明里列清**改了哪几行、为什么**，且不得顺手扩展改动范围。
- **产物路径写进 Output format**（目录 + 命名规则），红线只用来防越界、不用来代替指定产物位置。

## 三、验收六查（不看自报，逐项跑）

1. `find <目录> -type f -size 0` → **0 字节图必须重截**。
2. 同批、同用途但不同页面/场景的图 **互比 md5**：相同值 = 把 A 场景的图写进了 B 场景的文件名（并排图会变成“左半 A、右半 B”的废图）→ 退回重截，并要求文件名带页面+序号+功能点。
3. **图数 = 锚点/角标数**，且与页面清单逐行对得上；对不上的让 agent 列出来，不许自己猜对应关系。
4. **抽 1–2 张用视觉确认**：只圈了目标那一个框、弹窗类图里弹窗确实打开、该出现的状态文案（如“待定”）在图里。
5. **代码侧只增不改**：页面与弹窗组件的 diff 应只有锚点属性与透传 prop；出现业务逻辑删除就是越界。
6. **正文零改动**：拼装交付档那一步，只允许把占位（如“待补”）换成图片引用；其余文字一个字都不能动——拿 diff 核。

## 四、常见坑

- **渲染器缺失**：让用户装（如 `mmdc` / `npx @mermaid-js/mermaid-cli`），不要让 agent 自行安装重依赖（会拉浏览器内核）；装好后要求它重新检测可用性再继续。
- **项目内已有脚本优先用**，不要让 agent 自己重写一套截图/内嵌逻辑——自带脚本才能与历史产物保持一致。
- **文档里的图引用用相对路径**（`./images/x.png`）：仓库维护用引用版，交付时才用内嵌脚本生成自包含版本，二者同源、不要手改图。
