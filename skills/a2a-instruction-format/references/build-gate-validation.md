# 构建门禁改动：先只报告，再阻断，必须反向验证

给项目加构建守卫、校验脚本这类门禁时，分两阶段做，别一步到位。

## 两阶段

1. **第一阶段只统计不阻断**：新规则只打印命中，不写 `process.exitCode`。目的是摸清全仓有多少存量违规，数量可控再转阻断。直接上阻断会当场卡死构建，你就分不清是「新规则太严」还是「存量真脏」。
2. **第二阶段并入阻断**：把命中计数并入 `process.exitCode = 1`，报错信息给「文件:行:列 [规则名] 命中值」，并附一句修复指引（去哪登记、用什么常量替代）。

## 转阻断必须反向验证

不能只让 agent 贴「构建通过」。三步一起交：

1. 正常构建通过（exit 0）。
2. 故意塞一个已知非法值（临时在某个源文件里写一个主数据里没有的值），跑构建确认被拦下、exit 码非 0、报错定位到该行。
3. 删掉探针再跑一次，确认恢复通过。

只测「不报错」等于没测——门禁能不能拦得住从未被证明。门禁类改动默认要求这三步一起交。

## 合法值清单别在守卫里再写一份

国家、组织、枚举这类合法值，**从权威数据源动态解析**（如从主数据模块读 `WAR_ZONES` / `SUB_TENANTS_BY_ZONE` 之类的结构），不要在守卫脚本里硬写第二份：那样新增一项要改两处，两处必然漂移；动态解析后新增只需改数据源，守卫自动跟进。

解析注意：JS/TS 对象键可能无引号（`东南亚战区:` 这种），正则只认字符串键会让合法集解析为空，进而把合法值全当非法、整库误报。

## 匹配用最长词优先

按关键词表去扫国家/地区名时，长词先匹：否则「印度尼西亚」会被「印度」命中、「中国台湾」会被「中国」命中，报出一堆假阳性。同理「中国香港」「中国澳门」。

## 命中词表的取舍

候选词表（哪些串看起来像国家名）宁宽勿窄，合法清单（哪些是真的合法）严格从数据源解析。两者职责不同：前者漏了就是漏检，后者宽了就是误拦。分开维护。
