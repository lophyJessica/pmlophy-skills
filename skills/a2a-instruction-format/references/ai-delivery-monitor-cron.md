# AI 产物提交监控 cron（no_agent 零 token）

2026-08-07 上线。用户痛点："老让我当传话筒，我又不是开发"——AI 提交要自动提醒，不能等用户催。

## 实现

- 脚本 `/root/.hermes/scripts/check-deliveries.sh`（no_agent cron 每 2 分钟，deliver=origin）
- 状态文件 `/tmp/jarvis-deliver-state.txt` 记录"已处理的最新报告名"
- 检测 `/var/lib/jarvis/files/ai-reports/` 是否有比状态更新的报告：
  - 有 → 输出 `📦 已检测到新的 AI 产物提交，杰西卡处理中（<报告名>）` 并更新状态
  - 无 → 空输出（no_agent 模式空 stdout = 静默不打扰）
- **报告是主信号**：incoming 的 zip 会因部署改名/残留旧包（`jarvis-voice-v136-*.zip` 永远躺在那）干扰判断——以 ai-reports 新报告为准，zip 只作参考

## ⚠️ 语义铁律：cron 提醒 ≠ 已处理

用户实测质疑过："这个显示杰西卡正在处理中，但是实际上你在处理了吗？"

- 脚本只做**检测 + 投递消息到会话**，是预声明（"我将处理"），不是处理完成
- 真正读报告/部署要等**会话激活**：agent 不常驻后台，没有对话轮次就不会处理
- 半自动架构：检测自动（2 分钟内）→ 处理靠会话激活 → 用户看到提醒说一声"处理"（或 agent 在下一轮主动做）
- **不要向用户宣称"已处理"**——诚实区分 已检测 / 待处理 / 已处理；被问"处理了吗"先查实际状态再答
- 提醒措辞别用"杰西卡处理中"这类预声明（用户会追问"你处理了吗"）；用"待杰西卡处理"更诚实

## 变体：定期提醒类 cron（用户要“每日提醒我 X”）

用户要一条每日/周期提醒时，**不要建 agent 型 cron**（每次跑都烧 token）——同一个 no_agent 机制即可，零 token：

1. 脚本写到 `/root/.hermes/scripts/<名字>.sh`，内容就是 `echo "【每日提醒】<那句话>"`（不加逻辑、不调模型）。
2. 建任务：`no_agent=true` + `script=<文件名>` + `schedule`（如 `every day at 9:30`）+ `deliver=origin`（回当前会话）。
3. 提醒文案只写一条事实 + 下一步动作；多条待办就一个脚本输出多行，不要为每条建一个 cron。
4. 同时把该事项落进笔记库 + 看板待办（提醒只是响应器，台账才算数）；告诉用户“不想要时说一声就停”，别把删除做成需要教程的操作。
5. 时间选用户上班后一点（如 09:30），并在交付时明确写出可改。

## 关联

- 部署审查门禁：检测只提醒，部署必须用户确认后手动 `--deploy`（见 ai-artifact-pipeline / a2a-instruction-format 自动部署管道）
- 已处理状态 = 读报告 + 汇报 digest + （用户确认后）部署，然后脚本状态自动被新报告覆盖
