## 写指令的五个必含要素

1. **信息源圈死 + 权威顺序**：主PRD + 模块PRD + **App.tsx 路由 / MainLayout 侧栏菜单（以代码为准）** + context 状态机；明确"PRD 与代码不一致以代码为准，差异列进文档'PRD 与代码差异'小节"
2. **状态/文案口径**：状态描述用用户可见态（displayStatus 映射后），不得出现"待审核/审核中"等预留态字样（审核字样隐藏口径延续到文档和导出文件）；允许一次性历史说明（"一期含管理员审核（已隐藏）"）
3. **诚实标注预留**：PRD 有但未实现的能力标"预留"+ 原因（如微信推送、定时采集、官方平台适配未验证）——禁止把预留写成已上线
4. **路由核对要求**：文档提及的每个页面路径必须与 App.tsx `<Route path>` 逐项对照，报告里列 36/36 式核对表
5. **验证要求**：Mermaid 实际 parse 通过 + 浏览器渲染验证 + 缩放控件测试 + 围栏奇偶数检查

## 部署（文档≠应用）

- 三件套是**静态文档**，不走项目 deploy.sh（rsync --delete 会把它排除在 dist 外，deploy.sh 本来也不带 docs/）
- 部署到**静态站点目录**（如 `/var/www/pmlophy.com/scrm-architecture/`），浏览器直接访问渲染页
- ⚠️ **先确认目标域名的实际服务主机再 rsync**：pmlophy.com 主站 = 旧 Lisa（CF 回源），scrm.pmlophy.com = 搬瓦工。曾把文件传到搬瓦工 /var/www/pmlophy.com/ 结果经 CF 访问 404（CF 回源的是另一台机）。判断方法：`nginx -T | grep server_name` 看目标机托管哪些域名 + `--resolve` 直连源站 vs 经 CF 对比
- CF 边缘缓存：刚上传可能几分钟内旧 404，强刷/等缓存过期

## 后续维护

文档是产品/路由快照，路由增删改后需同步更新三件套（指令自检报告里会留"快照日期 + 后续需同步"的遗留风险）。
