# 三种视频形态怎么选

做之前先定形态。形态选错，信息密度、节奏、时长全跟着错，改起来等于重做。

## 形态对照

| | 概念讲解 | 操作演示 | 系统时序 |
|---|---|---|---|
| 回答什么 | 这是什么东西、逻辑怎么运转 | 系统对操作怎么响应 | 系统之间谁向谁要什么、什么顺序 |
| 画面 | 抽象图形，一眼看出是示意图 | 真实产品界面 | 泳道 + 时间轴 |
| 主角 | 概念的各个组成部分 | 操作的人 | 系统 |
| 信息密度 | 极低，一屏只讲一件事 | 可以密，跟操作路径走 | 中，每条消息必须能对上 |
| 时长 | 单概念 60–120s；多分支组合 4–5 分钟 | 2–3 分钟 | 按消息条数，通常 2–3 分钟 |
| 主要失败 | 堆界面构件伪装成产品 | 找不到对应的真实页面 | 混进接口名和中间件名 |

## 判定问题

- 观众看完要能自己复述出一句话？那是概念讲解，画面为这句话服务。
- 观众要照着做一遍？那是操作演示，必须按真实操作顺序排。
- 观众要知道「我点了之后背后发生了什么」？那是时序，不能出现实现细节。

## 最常见的翻车

**拿产品界面的构件做概念讲解。** 左侧用户档案面板、底部明细表、四张统计卡、顶部流程导航——这些在产品界面里都得有，放到讲解视频里就是噪音，同一份数据在三个地方重复。观众眼睛不知道往哪放，看完一个都记不住。

**伪装成产品界面。** 屏幕上出现面板、表格、状态条，观众就会去真实产品里找对应页面——找不到，这个界面就是编的，专业感反而变成不信任。讲概念就用一眼看出是示意图的抽象图形；要讲界面就录真实产品。

**把逻辑图做成界面。** 逻辑流图和产品界面是两种东西。前者表达关系，后者表达一个可操作的场所，混做出来两头不像。

## 受众决定结尾

同一个功能，三类受众要的结尾不同：

- 评审/领导：逻辑对不对，组合机制说不说得通。
- 运营：圈出多少人、触达成功率、转化。**结尾停在「命中 1 人」等于没讲**，运营看规模。
- 研发：数据从哪来、什么条件触发、异常怎么办。

做给谁看先问清楚，否则做完发现讲的方向不对。

## 素材从哪来（复用链）

原型复刻 → 原型标注 → 视频。

原型刷新了真实页面结构和交互状态，原型标注已经写清了「这块点了会发生什么、为什么这么设计、字段从哪来」。这些内容直接变成解说带和弹幕文案，不用重新编。

好处是口径有出处：标注是评审过的，视频照抄不会自相矛盾，也不用来回跟你确认措辞。

所以视频的定位是**原型标注的另一种呈现形态**——标注给人一点点读，视频给人一次看完，内容同源。

反过来也成立：这个功能评审要出什么，决定标注写多细；标注写细了，视频几乎白送。
