来源：维他命实战篇 1/2/3 + 方法论沉淀 4 篇深度阅读 + **真实源仓库已 clone 到 `/root/repos/QS-JXC-Project/`（https://github.com/TopVitamin/QS-JXC-Project，2026-09-27）**。对齐/重构 structure 时以真实仓库为准，课程笔记只作方法论，不猜目录形态。用这套给 forge-crm 升级项目框架。

## 顶层结构（00-99 分层，产品知识库 + 前端原型，非纯代码工程）
- `00-草稿对话/`：讨论稿、历史输入，只作线索，不作为当前口径。
- `01-全局背景信息/`：公司业务背景 → 项目背景 → 系统级声明，三层从宏观到微观；含跨模块规则、单据目录/生命周期、默认字段校验规范的全局基线。
- `02-需求调研/`：各业务领域（主数据/库存/财务/采购/销售/全局/报表）的场景、痛点、一期范围、初步方案，按领域拆分文件。
- `03-产品设计/`：**版本化**（按日期，如 `20260803-第一版搭建框架`、`20260816-采购订单的迭代（支持导入、导出等）`，迭代新需求进新版目录，第一版留基线）。每版本内含**三个平级顶层目录**（真实仓库实证）：
  - `字段清单/`：**按模块独立目录**（如 `主数据的字段清单/`、`销售模块的字段清单/`，各含 `<模块>字段清单（初稿）.tsv` + `（详细稿）.tsv`）+ 一个 `README.md`（写明文件用途/维护规则：初稿=临时过渡、确认后只改详细稿、初稿保留作过程记录、TSV 内部不加说明行以免破坏列数校验）。字段清单是这个目录的唯一事实源，**不散落在各模块 PRD 目录里**。
  - `系统架构和流程/`：三个固定文件 `系统架构说明.md` + `业务流程合集.md` + `系统单据流程合集.md`（系统边界/模块关系/角色接力/单据关系，作为各业务PRD的上游依据，不复制进每张单据PRD，只作输入和关联入口）。
  - `需求文档与规则/`：**领域→单据两级嵌套**（领域如 `采购管理/销售管理/库存管理/往来管理/基础资料/工作台`，单据如 `采购订单/采购入库单`）。每个单据模块目录 = `annotations/` + `前端Demo_PRD合集/` + `<单据>_页面骨架.md` + `<单据>主PRD.md`（**没有字段清单md、没有用例推演平铺**——Demo 全部收进 `前端Demo_PRD合集/` 子目录，主PRD/页面骨架在根，标注随单据同目录）。
- `04-常用模版/`：业务上下文 / 流程推演 / 业务PRD（主PRD/状态机/主数据）/ 前端Demo PRD（**标准型**与**简单型**两套，各含字段清单/页面骨架/列表/新增编辑/详情模板）/ 全局字段校验规范。模板 = 结构骨架，非业务事实源。
- `05-提示词合集/`：PM 全局规则 / PRD输出 / 业务逻辑推演 / 字段清单 / 模块文档套件 / 页面骨架 / 项目初始化。
- `06-产品方法论/`：工作流与方法论 + 前端原型方法（Mock生成/页面生成SOP/验收Checklist/骨架基线）+ 通用方法论 + PM协作踩坑。
- `07-UI规范库/`：系统级Token基线 / 页面模板与实例映射 / 组件交互规则 / 状态权限异常 / AI协作模板 / 模块契约与原型复刻规范 / 单据页面复刻约定 / 轻量配置弹窗约定。
- `99-产品原型prototype/`：React+TS+Vite，`src/contracts/modules` + `src/app` + `src/pages`，`public/annotation-kit/`（runtime+bundle），自带 AGENTS.md。
- `AGENTS.md`：仓库定位 / 各目录资料职责 / **权威源与冲突处理** / 文档变更工作方式 / 前端原型命令 / 验证与提交（conventional commits）。
- `.cursor/rules/`：project-coding-rules + project-docs-rules；`.github/workflows/`：deploy + prototype CI。

## 方法论核心（对任何 Forge/PM 模块有效）
1. **标准链路**：系统架构/流程 → 字段清单初稿→详细稿(TSV) → 业务PRD → 页面骨架(可选) → 前端DemoPRD → 原型 → 交叉回归走查。
2. **三层各管各**（同字段分三层，不揉一起）：
   - 字段事实（类型/来源/必填/取值/字段级约束）→ 字段清单详细稿 TSV；
   - 业务约束（审核后不可改/入库不超未入库）→ 业务PRD；
   - 页面约束（控件/校验时机/错误反馈位置）→ 前端DemoPRD。
3. **每份产出物只回答一类问题**，不整段复制上游（字段表/流程/页面规格只做关联入口）。
4. **先给边界再给任务**：喂AI时给「输入材料 / 当前任务 / 权威边界 / 输出要求」，一次只产一个层次；发现冲突先列出，不自行补成事实。
5. **变化分层改**：字段/枚举→TSV详稿；状态/动作/规则→业务PRD；页面结构/控件/校验→DemoPRD或骨架；跨角色流程→业务流程文件；跨单据→系统单据流程。先找修改入口，再同步受影响下游，绝不只在聊天/页面层临时纠正。
6. **版本化迭代**：03 下按日期建版本目录，第一版留基线；新需求进新版目录，AI 默认读新版，不覆盖旧版。
7. **字段清单只留 TSV 一份**（不维护 Markdown 副本，避免"哪份最新"之争）；初稿是过渡，详细稿确认后唯一。
8. **交付前最小检查**：业务PRD字段都能在TSV找到 & 不重复改写枚举类型必填；Demo不造字段/不造操作矩阵外按钮；业务PRD不整段复制流程字段表；旧名称旧规则无残留下游。
9. **黄金页**：先做一个完整模块 PRD 套件走查确认作参照，再批量扩展其他模块（不给十个空模板，给一个完整参照物）。
10. **沉淀**：重复劳动收口为 模板 / 提示词 / Skill 三类资产。

## forge-crm 现状与升级差距
- 现状（2026-09-27 实测）：`03-产品设计/20260913-第一版-现有基线/` 下只有 `字段清单/`（仅线索模块有 TSV）+ `需求文档与规则/`（嵌套层混乱：`需求文档与规则/需求文档与规则/` 一层多余）；模块目录里 Demo/字段清单md/用例推演/评审PRD 全部平铺；无 `系统架构和流程/`；字段清单格式 md 与 TSV 并存（模块内 9 个 `*字段清单.md` + 顶层仅线索 TSV）。
- 对齐目标（2026-09-27 用户定稿，forge-crm 先行，勿梭哈、git mv 保历史）：
  1. **顶层三目录补齐**：`系统架构和流程/`（三件套：系统架构说明/业务流程合集[可取 01-全局背景信息/04-核心业务流程详解.md]/系统单据流程合集）+ `字段清单/` + `需求文档与规则/`。
  2. **模块内清理**：每模块 Demo 全部收进 `前端Demo_PRD合集/` 子目录，主PRD/用例推演留在模块根。
  3. **平级目录收纳评审PRD**：线索/商机的 `评审PRD*.md` 移出模块，进 `需求文档与规则/评审PRD/`（与模块平级）。
  4. **字段清单统一 TSV、单独管理**：模块内 `*字段清单.md` 移到顶层 `字段清单/<模块>/`（md 保留过渡）→ 下轮逐模块转 `（初稿/详细稿）.tsv` → 转完删 md（"不破不立"：字段清单只留 TSV 一份）。
  5. **重复模块合并**：拜访计划/拜访管理内容重复 → 合并成一个（保留有 annotations 的更完整目录）。
- 历史差距对照（2026-09-12 版）：无 01~99 分层；prd-docs 无日期版本化；无 TSV 初稿/详细稿体系；模板瘦；无 06方法论；无 07UI规范库；03产品设计缺系统架构/流程与业务PRD/DemoPRD 分层目录。用户待拍板点：迁移力度（真搬 git 路径 vs 新框架+索引映射）+ 试点范围（黄金模块 vs 全铺）。forge 系是方法论练习场，勿过度投入。
