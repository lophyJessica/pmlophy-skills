# 多语言导入：翻译稿合并进平台模板

上线前产品侧常见的一项活：翻译稿（在线表格）＋ 平台导出的配置模板 → 合并成一份可直接导入多语言系统的文件。**导入多为覆盖式且不可逆**，所以这活的核心不是“合并得快”，而是“别把线上已有的译文清掉”。

## 一、先问清三件事（不问就做，整批白干）

1. **导入到哪个项目**（如 `global-cms-sso`）——模板必须“按该项目导出”，导错项目等于白干。
2. **要不要版本号**——平台模板里 `label` 列就是**版本号列**，不是普通备注；不需要就**表头保留、值一律留空**。
3. **导入规则从平台帮助页抄，不靠猜**（通常有「批量导入配置项」一节）。重点四条：
   - **覆盖式**：文件里非空的值覆盖线上；导入成功后即为「审核通过」状态，**不可逆**。
   - **版本号必须存在**否则报错（不需要就留空）。
   - **语种列名必须与系统内语种名称完全一致**；该项目下未配置的语种不生效。
   - 侧栏语言筛选标签 ≈ 该项目已配置语种清单，可用来核列名。

由覆盖式推导出的安全策略：**A（平台导出）里已有的非空单元格一律保留原值、绝不写空**——这样“覆盖”只是覆盖成同一个值；真正的危险是把已有译文清空。

## 二、两份输入

| | 从哪来 | 作用 |
|---|---|---|
| **A 模板** | 多语言系统配置管理页 → 选项目 → 导出（导出全部时不能带查询条件） | **导入文件的骨架**，列顺序/表头以它为准 |
| **B 翻译稿** | 在线文档（WPS 等，URL 常带 `sheetIndex=N`） | 提供新增 key + 原有 key 缺失语种的译文 |

A 的典型列：`config_key / remark / label / zh_CN / en_US / … / in_ID / … / id_ID / kh_KH`（语种列按项目不同，以导出为准）。**注意 `in_ID` 与 `id_ID` 可能是并存的独立两列**。

## 三、执行顺序（分三步，中间必须停机）

**第 1 步：拿到 B 的机器可读副本**（见第四节取数法），报：路径 / 字节数 / 行数 / 首尾抽样值。
**第 2 步：只出「key 匹配明细」，不写任何文件**——B 的每个 key 在 A 中是精确存在还是不存在；不存在的**按前缀归类统计**（如 `guide.*` / `guides.*` / 其它），并列出 A 中“仅前缀或单复数不同”的成对项。报用户确认。
**第 3 步：确认后再生成导入文件 + 自检 md**；交付前把 A 另存一份「导入前备份」。

把“先报匹配明细”做成硬停机的理由：key 前缀/单复数若不一致，精确匹配会把整批词条判成“新增”，白添一套同义 key——这类错在生成文件后才发现，返工成本远高于先看一眼统计。

## 四、合并规则（逐条照做）

1. 按 `config_key` **精确匹配**（去首尾空格），不做模糊/相似匹配。
2. **已有 key：只填空缺**——A 中该语种为空才填；A 非空一律不动，哪怕 B 给了不同译文（只记进冲突清单）。
3. **新增 key（B 有 A 无）**：追加到末尾，填 `zh_CN` 与 B 的各语种译文；`remark` / `label` 留空。
4. **同一语种对应两列时两列都填**（如印尼语 `in_ID` + `id_ID`，用户口径“两个都填，保险”）。
5. B 没有的语种列**不动**。
6. **不删列、不改列名、不排序**；表头与 A 完全一致；产物**另存新文件**，不动 A 原件。

## 五、B 是在线 canvas 表格时怎么取全量

在线表格（WPS 一类）把单元格画在 canvas 上，DOM 读不到全文、逐格点选也不现实。

- **做法**：先用名称框/`Ctrl+End` 确定真实区域（如 `A1:I165`，别信光标所在位置），**整块选中 → 复制 → 本地脚本读剪贴板**（`pandas.read_clipboard()` 或 `win32clipboard`）→ 落成 TSV。
- **自检**：行数对得上；首尾各抽一行核对；**单元格内含换行会把一行拆成两行**，入库前转义或替换成空格。
- 顺序：有导出按钮 → 导出；没有但能整块复制 → 剪贴板；都不行才逐屏读，并明确标注数据不完整。**不要一上来就写“canvas 读不出，请用户导出”**。
- 抓取类指令的通用写法见 skill `intranet-data-capture`。

## 六、必交的自检（给用户看，不是自报“已完成”）

- 新增 key 数 / 追加行数
- 各语种填补的单元格数（逐语种）
- **冲突清单**：A 非空但 B 给出不同译文（位置 + A 现值 + B 值），只记录不覆盖
- 最终行数 / 列数，且列与 A 完全一致
- key 命名空间交叉扫描结果（前缀/单复数差异只列不改）

## 七、坑

- **key 拼写不能靠截图识读**：视觉模型读标识符字符串不可靠，曾据此误报“命名空间不一致”。以全量比对结果为准，不按猜测改 key 前缀。
- 导入前留两份底：A 原文件 + 线上当期导出，便于导入出错时对比。
- 一次性的合并/整理产物落用户本地下载目录即可，不要塞进项目仓库。
- 指令里不出现任何 git 命令；产物另存、不覆盖原文件。
