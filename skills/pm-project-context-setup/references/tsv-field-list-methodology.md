# TSV 字段清单方法论（PM Vitamin 项目实战篇 QS-JXC）

来源：维生素 AI 课程「项目实战篇」实战篇1/2/3（QS-ERP / QS-JXC 进销存项目）。
适用：给 AI 协作的 PM 项目维护字段清单时。用户当前把这套用在公司 CMS + 娜美上；forge 项目暂不改造（仅参考）。

## 核心：字段清单用 TSV，不用 Markdown 表、不用 Excel

TSV = Tab-Separated Values（制表符分隔的纯文本）。选它的原因：
1. **纯文本 → AI 可直接读写**（Excel 二进制，AI 处理费劲）
2. **字段多时比 md 表好维护**（md 表格列一多就对不齐、乱）
3. **配合 AI IDE 的预测性自动补全** → 填一列编辑器预测下一行，效率高

> 原文一句话：用 TSV 是为了方便快速编辑和确认，让 AI 能帮你做预测和走查确认，而不要用 Excel。

## 字段清单分两版

**初稿（5 列）** — 先确认"有哪些字段"：
`字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 字段说明/描述`

**详细稿（13 列）** — 再定义"字段在产品上怎么表现"：
`字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 必填性 | 新增页 | 编辑页 | 列表展示 | 可筛选 | 详情展示 | 字段说明/描述 | 取值说明 | 备注`

分两版理由：先确认范围（初稿，问题早暴露），再定义完整规格（详细稿）。一步到位容易乱。

**铁律：**
- 详细稿确认后 = 字段唯一事实源；初稿只留作过程记录，不再更新
- **只保留 TSV 一份，绝不维护对应的 md 字段清单副本**——否则出现"XX.tsv + XX.md 两份、不知道哪份最新"的混乱

## TSV 放什么 / 不放什么

**放（字段本身稳定信息）**：分组、名称、类型、来源、必填条件、取值/格式/枚举、说明、字段级约束、计算或回写说明。

**不放（这些属页面交互，进前端 Demo PRD）**：查询区位置、控件占几列、placeholder、下拉样式、远程搜索触发、加载/空态/失败反馈、错误提示位置、页面布局按钮排列。

## 三层分层（方法论核心，避免文档重复）

同一个"采购数量"：
| 层 | 内容 | 负责文档 |
|----|------|---------|
| 字段事实 | 整数、>0、来源用户填写 | 字段清单 TSV |
| 业务约束 | 提交审核时每个明细行必填；审核后不可改 | 业务 PRD |
| 页面交互 | 用 NumberInput；失焦校验；错误定位到明细行 | 前端 Demo PRD |

三层不是重复，是分别回答：字段是什么 / 业务怎么限制 / 页面怎么让用户完成操作。

## 标准产出链路

```
系统架构/业务流程/系统单据流程/相关单据PRD
→ 字段清单初稿（确认范围）
→ 字段清单详细稿 TSV（确认后 = 字段唯一事实源）
→ 业务 PRD
→ 页面骨架（可选，页面结构需走查时才建）
→ 前端 Demo PRD
→ 前端原型
```

每份文件只负责一类问题，不重复抢同一个职责。"少一份重复文件，反而更容易让 AI 做对。"

## 字段清单逐步丰富（6 步）

1. 找竞品/参考系统做参照起点
2. 手动填初稿骨架（5-10 个字段起）
3. 让 AI 辅助补全（预测补全）
4. **人工走查**（查编造字段/类型/取值，标记"已确认 vs 候选"）
5. 让 AI 输出详细稿（13 列）
6. **再次人工走查**（核对必填性/页面展示/取值，防止新增/列表/详情页表现对不上）

## 版本迭代法（已有模块迭代）

不覆盖第一版；在 `03-产品设计/` 下新建版本目录（`20260803-第一版` → `20260820-第二版`）。
- 第一版保留作基线和对照；第二版放本轮新增需求/PRD/字段/页面
- 给 AI 划定清晰上下文范围（默认读第二版），避免旧内容干扰
- 新增需求先写进第二版需求文件，不直接追加进第一版 PRD

## 给 AI 下任务结构（先给边界，再给任务）

```
输入材料：本次要读取哪些背景/流程/字段/相关单据PRD
当前任务：本次只输出 XXX（业务PRD / 页面骨架 / Demo PRD 之一）
权威边界：字段以TSV为准，业务规则以业务PRD为准，页面交互以Demo PRD为准；发现冲突先列出，不自行补成已确认事实
输出要求：说明产出了什么，影响哪些下游文件
```

**一次只让 AI 输出一个层次**，不要同时让它生成字段/规则/页面/原型（混在一起就乱了）。

## 变更时先找真正的修改入口

| 变化 | 第一修改入口 | 还要查哪些下游 |
|------|------------|--------------|
| 字段名称/类型/来源/枚举/字段级约束 | 字段清单详细稿 TSV | 业务PRD、页面骨架、Demo PRD |
| 状态/动作/业务规则/下游结果 | 业务 PRD（必要时回流程文件） | 字段清单、页面骨架、Demo PRD |
| 页面结构/控件/校验时机/反馈文案 | 页面骨架或 Demo PRD | 其他页面产出物、原型 |
| 跨角色流程/跨单据系统处理 | 业务流程/系统单据流程 | 受影响的单据PRD、字段清单、页面Demo |

## 交付前最小检查

- 业务 PRD 的字段都能在详细稿 TSV 找到，无重复定义/改写枚举类型
- Demo PRD 没用到 TSV 里不存在的字段，没创造业务 PRD 状态-操作矩阵里不存在的按钮/状态
- 页面骨架只含结构，没混入完整业务规则
- 业务 PRD 没整段复制完整业务流程/系统流程/字段表/页面规格
- 字段/状态/动作变化后，旧名称旧规则没残留在下游
