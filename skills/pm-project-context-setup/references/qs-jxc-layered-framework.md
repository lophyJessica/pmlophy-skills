# QS-JXC 完整分层项目框架（升级版结构）

三层六步骨架是入门门槛。项目一旦长出完整 PRD / 原型 / 模板 / 提示词，就应升级为维他命 QS-JXC-Project 的编号分层全框架。forge-crm 0913test 已对齐（2026-09）。

## 顶层结构（00~09 + 99）

```
00-草稿对话/          讨论稿·临时，只作线索
01-全局背景信息/     业务背景/项目范围/上下游/模块地图/流程/命名/规则/AI模型规则 等全局基线
02-需求调研/         各模块场景·痛点·一期范围·初步方案
03-产品设计/         正式设计产物，按版本分目录
04-常用模版/         新建产物用的结构模板（非业务事实源）
05-提示词合集/       AI 协作提示词
06-产品方法论/        产出顺序/文档分层/走查方法
07-UI规范库/         Token/组件/交互/状态/原型复刻规范
08-相关资料/         审计/走查/过程报告
99-产品原型prototype/ React+Vite 前端 Demo + 原型标注 runtime
+ AGENTS.md（权威源分层）+ README（框架地图）+ .cursor rules + CI
```

## 03-产品设计 → 版本化

- 按 `<日期>-<版本说明>/` 分目录（如 `第一版-现有基线/` `20260820-第二版内容迭代/`），第一版留基线，迭代进新版本目录，AI 只读当前版。
- 每模块 4 件套：`主PRD.md` + `页面骨架.md`(可选) + `前端Demo_PRD合集/{列表,新增编辑,详情}.md` + `annotations/`(原型标注)。
- 字段清单 TSV 单独放版本下 `字段清单/<模块>/`，初稿5列→详细稿13列，确认后详细稿为唯一源。

## 权威源分层（AGENTS.md 必写）

- 跨模块口径 → 01-全局背景信息
- 字段名称/类型/来源/枚举/字段级约束 → **字段清单详细稿 TSV**（唯一源）
- 模块内状态/动作/业务规则/异常 → **业务 PRD**
- 页面结构/控件/校验时机/反馈 → **前端 Demo PRD** + 07-UI规范库，不反向从 Mock 发明业务
- 冲突先列文件证据+影响范围，未确认标"待确认"，用户拍板后同步权威源与下游。

## 变更传播方向

- 字段变 → 改详细稿 TSV → 查业务PRD/骨架/DemoPRD/原型
- 状态/动作/业务结果变 → 改业务PRD → 查字段清单+页面
- 页面变 → 改 DemoPRD/UI规范/原型，不反向改业务口径
- 模板/提示词/方法论变 → 只维护对应资产，不批量改写既有业务文档

## 把已有项目升级到该框架

1. **独立分支承载升级**（用户偏好：不新建项目，拉分支如 `0913test`），main 保留旧结构不动。
2. 分支上先建骨架 + 重写 AGENTS.md。
3. **旧目录 git mv 进新家**（保历史）。
4. agent 报告"0 个可迁移文件、未执行 git mv"通常**正常**——内容早已在 git 提交里搬好（如 git 端已 rename），agent 只清了未跟踪垃圾（dist/node_modules/.DS_Store/zip）。
5. 批量升级先"黄金模块"走通闭环（主PRD+骨架+Demo合集+annotations+字段清单TSV）再铺其余。

## 并行跑两个本地 agent（Codex 合并 + 反重力产物）

- **同一分支两个 agent 必须用隔离工作副本**：主副本跑结构性 git mv 合并，另一个跑纯文档产出要在独立 clone（`git clone -b <branch> ... <dir>`），否则同一工作目录抢 git 工作区/同名路径冲突。
- 两个隔离副本**都未 commit** 而在同一分支 = 分叉，**必须收口到一个工作副本再单条 commit**：把隔离克隆的产物 copy 进主副本 → 主副本 one commit 提交全部 → push。
- 不要在两处分别 commit 后各自 push（会分叉冲突）。
- 产出隔离的 agent 指令要显式写：只在隔离目录落盘、不 commit/push、不碰主工作副本。
