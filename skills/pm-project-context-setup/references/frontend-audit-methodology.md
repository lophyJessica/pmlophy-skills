# 前端原型的 PRD 三向对齐审计

对 AI 生成的前端原型做"context 地基 → PRD 规格 → 前端代码"三向对齐审计的标准化流程。

## 触发场景

- 用户说"看前端""审前端""对齐PRD""深审"
- AI IDE（Antigravity/Cursor）生成了前端原型，需要检查质量
- 项目有完整的 context/ + PRD + 前端代码三套产物

## 审计流程

### 第一轮：Demo PRD → 前端代码（页面级）

1. 读每个页面的 Demo PRD（列表页/新增编辑页/详情页）
2. 读对应的前端 tsx 文件
3. 逐项对照：配色、列定义、控件类型、按钮文案、弹窗规格
4. 产出审计报告，按严重度分三级：

| 级别 | 标准 | 示例 |
|:--|:--|:--|
| 🔴 阻断 | 违反 PRD 硬约束 / 超出项目范围 | 导入按钮违反 Out of Scope |
| 🟡 中等 | PRD 写了但代码缺了/歪了 | 行内操作按钮不完整 |
| 🟢 低 | Demo 简化 / 措辞微差 | SelectWithSearch 简化成原生 select |

### 第二轮：context/ → PRD → 前端（三向对齐）

1. 读 context/04（功能清单）、context/06（业务流程）、context/07（业务约束）
2. 交叉对照 context 定义 → PRD 落地 → 前端实现
3. 重点查：功能范围边界、业务规则落地、术语一致性、场景覆盖

### 第三轮：输出 IDE 修复指令

1. 把发现的问题整理成结构化提示词（五段式模板）
2. 按优先级排序：阻断 → 中等 → 低
3. 分轮次提交给 AI IDE（每轮 4-7 个问题为佳）
4. 第一轮修 UI 层（配色/列/按钮），第二轮收尾（分页/前缀/文档术语）

## 审计维度速查

源自 强盛科技 AGENTS.md "AI 走查：过关再写前端"：

1. **字段完整性** — 字段清单是否 SSOT？下游 Demo 是否重复定义枚举？
2. **状态机闭环** — 有无到不了的态？执行层是否误加审核流？
3. **规则一致性** — 与 context/07 约束是否矛盾？
4. **术语一致性** — 对照 context/08（如用「现存」不用「账面库存」）
5. **场景覆盖** — context/06 关键异常是否进 PRD
6. **模块间一致** — 上下游字段来源是否存在

## 典型发现模式

| 问题类型 | 出现频率 | 根因 |
|:--|:--|:--|
| 状态标签配色错位 | 极高 | AI 不理解颜色语义，随机分配 |
| Import/Export 按钮越界 | 高 | AI 习惯性加 CRUD 全功能 |
| 行内操作不完整 | 高 | AI 只实现通用操作，忽略状态差异 |
| 确认弹窗文案统一 | 中 | AI 偷懒用一个 handler 处理所有弹窗 |
| 默认分页值偏差 | 低 | 常见默认 10 vs 规格 20 |

## 配合反重力（Antigravity）的指令写法

核心原则：**指令要堵死 AI 所有自由发挥空间。** 五段式模板 + 具体行号 + "不要改什么"红线。

```markdown
Context: 项目路径 + PRD 路径
Request: 逐一修复，编号 [P0-1] ~ [P0-N]
Output format: 直接改代码 + npm run build 验证
Constraints: 不改 types / API 层 / 其他页面
Checkpoint: 全部修完汇报结果，报错就停
```
