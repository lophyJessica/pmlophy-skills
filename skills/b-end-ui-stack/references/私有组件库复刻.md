# 私有组件库复刻案例：vivo VOS

当一个系统用的是**厂商内部私有组件库**（公共 npm 拉不到），复刻时最容易翻车的地方就是「换成通用库近似替代」。下面是完整案例，可当模板对照。

## 两侧现实

| | 原系统 | 常见错误替代 |
|---|---|---|
| 组件库 | `@vivo/vos-ui` 4.1.1-alpha.3.46（私有，内部源 `http://npm.vmic.xyz`） | Vant 4.9.21（开源、同风格） |
| 组件 | `FosButton` `FosToast` `nx-search` `nx-tabs` `nx-list` `nx-pull-refresh` `nx-button` `nx-icon` `nx-empty` `Empty` `Loading` | `van-button` `showToast` `van-search` `van-tabs` `van-list` `van-pull-refresh` `van-icon` `van-empty` `van-loading` |

Vant 和 VOS 看着都是移动端组件库、风格接近，但**不是同一个东西**。换完之后页面会被用户直接判为「完全是两个产物」「有源码都还是有很多问题」。

## 先验证私有包能不能装

不要假设装不上就直接替换。验证顺序：

1. 读 `package.json` 与 `.npmrc`，确认包名、版本、registry。
2. 测内部源连通性：`curl -s -o /dev/null -w "%{http_code}" http://<内部源>`。
3. 建最小工程实际装一遍，跑一个组件出来。

实测结论：私有包公共 npm 404、内部源正常 200 且能装能渲染、能构建 → **这条路是通的，没有理由替换**。配套问题：私有包常缺 TypeScript 声明，补一份本地 `shims.d.ts` 即可；pnpm 首次装可能拦 build script，批准即可。

## 组件样式的注入方式要照搬

原系统 `main.ts` 通常**只引 reset/基础样式**，组件库样式靠构建插件（如 `vite-plugin-babel-import` 配 `libraryName: '@vivo/vos-ui'` + `libraryDirectory: 'packages'`）按组件注入，不是手动 `import 'vos.css'`。原型保留同样的构建插件即可，别自己去找全局 css。

验收：浏览器里数样式规则数——`nx-search` 约 30 条、`nx-tab-bar` 约 51 条、`fos-button` 约 64 条。数得出来就说明样式真的加载了。

## 替换到 Vant 后的局部问题（说明为什么调不动）

| 现象 | 机制 |
|---|---|
| 按钮皮肤/多行文案对不上 | `FosButton` 的 `faceColor` / `textColor` / 多行内容与内部 DOM 结构在 Vant 里没有对应物 |
| Tab 出现省略号、不能滑 | Vant Tab 默认等分收缩；原库用 `.nx-tab-bar` / `.nx-tab-bar-ink` / `.nx-scroll-view` 一套横向滚动 + ink 覆盖 |
| 下拉刷新/上拉加载触发时机不对 | `nx-pull-refresh` 的 `v-model:value` 与 `nx-list` 的 `loadingType` / `finishedMode` / 自定义 loading 文案在 Vant 里属性名与语义都不同 |
| 搜索框形态不对 | `nx-search` 有 `isHasAnimate` / `type="frame"` / `searchWay` / `isShowCancel` 等专有属性 |
| 图标对不上 | `nx-icon` 的图标集不同名（`circle-select` / `right-arrow` 等），要么建映射要么拄 SVG |

结论：这不是样式值问题，是组件行为与 DOM 结构问题。调 css 永远调不到位。

## 移动端原型在桌面浏览器里看：375px 容器

| 要点 | 做法 |
|---|---|
| 容器 | `max-width: 375px` 居中，两侧淡灰；窗口窄于 375 时取消限宽直接铺满 |
| 单位换算 | 设计稿基准 1080 → PostCSS 转容器单位；组件库自己的组件按 375 基准单独配 |
| **`cqw` 的硬前提** | 容器必须声明 `container-type: inline-size`，否则 `cqw` 退回按浏览器窗口算（940px 窗口下 16.67cqw = 157px，页面全是巨字） |
| 验收一行 | `getComputedStyle(document.querySelector('.mobile-viewport')).containerType` 要返回 `inline-size` |
| 固定定位 | 页面里的 `position: fixed` 会相对浏览器窗口而不是容器——顶部会横跨整个屏幕；TabBar 改 `absolute` 钉在容器底部 |
| 滚动 | `body` 禁止整页滚动，内容区独立滚动 |

单位换算的验收方法：拿原系统一个已知字号（如 `48px` @ 1080 基准），在 375 容器里应约等于 16.67px；量出来对得上就说明不是单位问题，回头查组件。

## 可直接跑的源码是最好的参照

如果源码能在本地起 dev server（需内网 registry + 可选登录态），跑起来比读文件准得多：

- 能直接对真实 DOM 与 computed style，不用猜属性名含义。
- 缺登录态时页面照常渲染布局，只是数据空态——**看形态够用**；要看真实数据细节再单独补，或让用户截图。
- 别在原仓库里装依赖：用 `git worktree` 或复制分支副本，在副本里跑。

定位分工：**跑起来的源码 = 对照与写文档的参照**；**本地原型 = 脱离内网也能演示的版本**。两者不要互相替代。
