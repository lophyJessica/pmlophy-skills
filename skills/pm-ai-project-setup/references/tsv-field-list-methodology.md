# TSV 字段清单方法（PM Vitamin 实战篇，Source: min. word count 39）
- **建议：段落类型** —— "TSV 字段清单方法"，作为《PM AI Project Setup》的 reference。用户 2026-09-07 在维生素「项目实战篇」（QS-ERP / QS-JXC 进销存）中读到，正用它做公司 CMS 项目和喂娜美。

## 为什么用 TSV 做字段清单（不用 Excel / 不用 md 表格）
- **纯文本 → AI 能直接读写**（Excel 二进制，AI 处理费劲）
- **字段多时比 Markdown 表格好维护**（md 表字段一多就乱、对不齐）
- **配合 AI IDE 预测性自动补全**（你填一列，编辑器预测下一行；Cursor 有 TSV 插件）
- 一句话：TSV 是"给 AI 看 + 人快速编辑 + AI 能自动补全走查"的字段数据载体。

## 字段清单分两版：初稿 → 详细稿
**初稿（5 列）——先确认"有哪些字段"：**
```
字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 字段说明/描述
```
**详细稿（13 列）——再定义"字段在产品上怎么表现"：**
```
字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 必填性 | 新增页 |
编辑页 | 列表展示 | 可筛选 | 详情展示 | 字段说明 | 取值说明 | 备注
```
- 先确认有哪些字段（初稿快），再定义每个字段完整规格（详细稿），比一步到位稳。
- **铁律**：详细稿确认后 = 字段唯一事实源；初稿只留作过程记录、不再更新。
- **只保留 TSV 一份，绝不维护对应 md 副本**——否则出现"字段清单.tsv + .md 两份、不知道哪份最新"的灾难。

## TSV 放什么 / 不放什么
- **放（字段本身稳定信息）**：字段分组 / 名称 / 类型 / 来源 / 必填条件 / 取值格式枚举 / 说明 / 字段级约束 / 计算或回写说明
- **不放（属页面交互 → 进前端 Demo PRD）**：查询区位置、控件占几列、placeholder、下拉样式、远程搜索触发、加载中/空结果/失败反馈、错误提示位置、页面布局按键排列

## 三层分开（TSV 方法论核心）
以"采购数量"为例：
| 层 | 内容 | 放哪 |
|---|---|---|
| 字段事实 | 整数、>0、来源用户填写 | 字段清单 TSV |
| 业务约束 | 提交审核时每个明细行必填；审核后不可改 | 业务 PRD |
| 页面交互 | 用 NumberInput；失焦校验；错误定位到明细行 | 前端 Demo PRD |
三层不是重复，分别回答：字段是什么 / 业务怎么限制 / 页面怎么让用户完成操作。

## 字段清单逐步丰富（6 步）
1. 找竞品/参考系统做参照起点
2. 手动填初稿骨架（5-10 个字段起）
3. 让 AI 辅助补全（预测补全）
4. **人工走查**（查编造字段/类型/取值，标记已确认 vs 候选）
5. 让 AI 输出详细稿（13 列）
6. **再次人工走查**

## 版本迭代法（不覆盖，建版本目录）
已有模块迭代（如加导入/导出/打印）：
- **不覆盖第一版**，在 `03-产品设计/` 下新建版本目录（如 `20260803第一版` → `20260820第二版`）
- 第一版保留作基线，第二版放本轮新内容；给 AI 明确上下文范围（默认读第二版）

## 给 AI 下任务结构（先给边界，再给任务）
一次只让 AI 输出一个层次，不同时生成字段/规则/页面/原型：
```
输入材料：本次要读取哪些背景/流程/字段/相关单据PRD
当前任务：本次只输出 XXX（业务PRD / 页面骨架 / Demo PRD 之一）
权威边界：字段以TSV为准，业务规则以业务PRD为准，页面交互以Demo PRD为准；发现冲突先列出不自补
输出要求：说明产出了什么，影响哪些下游文件
```

## 完整链路（TSV 的定位）
```
系统架构/业务流程/系统单据流程/相关单据PRD
→ 字段清单初稿 → 字段清单详细稿 TSV（确认后=字段唯一来源）
→ 业务PRD → 页面骨架(可选) → 前端Demo PRD → 前端原型
```

## 应用方式（用户正这样用于 CMS 项目 + 娜美）
- CMS 每个业务对象建字段清单：用 TSV 不是 md 表
- 初稿确认范围 → 详细稿定规格（详细稿唯一来源）
- 字段事实只在 TSV，业务规则进业务 PRD，页面交互进 Demo PRD，三层解耦
- 不维护 md 副本；不用 Excel
- 一句给娜美的通俗版："字段清单用 TSV（初稿分范围、详细稿定规格、详细稿唯一来源、不维护md副本）；字段事实在TSV，业务规则在业务PRD，页面交互在Demo PRD——三层分开，一次只输出一个层次。"
