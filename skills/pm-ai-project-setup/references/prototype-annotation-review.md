# 原型+标注双栏评审模式 & AI 自动标注方向（2026-08-07 用户定）

## 核心理念（用户的产品方法）

模仿 Axure 时代的"原型 + 标注"模式，用现代化（AI）落地：

```
📐 左边: 原型页面（真实样子，前端可交互原型）
📝 右边: 标注面板（交互规则/逻辑规则/字段说明）
页签: 全部 / 页面 / 交互 / 规则 / 字段 / 待确认
→ 评审时页面和规则对照看，一眼看全
→ PRD 不需要赘述文字版交互说明/规则说明（标注就是规则）
```

## 为什么有效

- 传统 PRD 写大段文字（"点击X弹出Y，状态A流转到B"）——评审要脑补页面
- 双栏对照：左边看页面，右边看逻辑——评审效率高、不脑补
- 标注按"页面/交互/规则/字段/待确认"分类——结构化、可扩展

## AI 自动标注方向（2026-08-08 计划实践）

目标：用 AI 替代"人肉标注"的重复劳动（人在回路：AI 做标注执行，人做审核判断）。

调研结论（两条路径）：
- **纯视觉模型看图标注**（GPT-4o/Gemini 识别组件/布局）——适合页面级标注（组件/布局/字段），**局限**：纯截图无法识别无视觉特征的逻辑（校验规则/权限/数据流）。美团 KuiTest 证实：UI 组件识别需要语义信息补充
- **代码+截图双输入**（更准）——前端源码（React 组件/onClick/状态/校验）读真实逻辑 + 截图对照布局 → 交互规则/字段规则更准。forge 系有源码 → 可行
- 参考工具：Midscene（视觉驱动 UI 自动化）、KuiTest（LLM 遍历 UI）、TRAE+Figma 6A 工作流

落地流程（待实践验证）：
```
选一个 forge 页面 → AI 读代码+截图 → 生成标注（交互/规则/字段）
→ 人审核标注（补充/修正）→ 评审
→ 沉淀成可复用方法论（面试/作品亮点）
```
