# agent 指令开工前校验

给 agent 下指令前跑一遍。**指令里没写死的，agent 一定会按自己的理解走偏**——今天四个返工点全是指令缺口。

## 跑脚本（最快路径）

```bash
python3 ~/.hermes/skills/software-development/agent-instruction-preflight/scripts/check.py 指令文件.md
```

输出 PASS / FAIL + 缺失清单。FAIL 就不许发。

没有文件时把指令存成临时文件再跑：`pbpaste > /tmp/i.md` 或手工粘进去。

## 四层防护（缺一层，那一层就反过来坑你）

### 第一层：规格定死

开写前必须写清的八条，一条不空：

1 给谁看（评审/运营/研发，结尾完全不同）
2 目标概念或功能的精确定义，有哪些相邻易混概念
3 时长或工作量预期（按内容量算，不是拍数字）
4 术语口径（哪些专业词不许用）
5 对象称呼（真名还是编号）
6 数据基准（唯一数字来源 + 派生值 + 白名单 + 验算等式）
7 结构（分几段、每段讲/做什么）
8 交付内容全文（文案/字段/步骤，写死不留活口）

### 第二层：红线禁止

写明**不许做什么**，比写该做什么更能防走偏——agent 擅长完成要求，不擅长判断边界。

写法：每条红线后面接一句「违反会怎样」，它才知道严重性。

```
红线禁止:
- 不许出现「算子」这个词，观众是业务口的人
- 不许把「且」和「非」合并成「且非」，逻辑上只有且/或/非三种关系
- 不许新增任何无法从基准数据推导的人数，只用 1532/246/1286/842/444
- 不许切场景翻页，同一画面持续变形
```

### 第三层：自检要求

让它自己验，而不是嘴上说「已完成」。**每一条都要给可执行的验证方法**：

| 要验什么 | 验证方法 |
|---|---|
| 输出稳定性 | 取 8~10 个采样点，顺序跑一遍、乱序重跑一遍，比对哈希 |
| 无重叠/无越界 | 取边界前后各一帧，两两算交集面积，必须为 0 |
| 状态不可逆 | 扫全量，被销毁/关闭的东西不许重新出现，违规次数为 0 |
| 文案与时序对齐 | 逐条核对实际切换时刻与设定值，误差不超 1 帧 |
| 数据自洽 | 列出验算等式，跑一遍脚本验证 |
| 禁用词 | 全文搜索，命中数必须为 0 |

报告要它贴实测数字，不接受「已验证」「测试通过」这种话。

### 第四层：Checkpoint 必须在

分阶段停，每段结束必须停下来交人核。

**禁止写这种没有停止点的松句**：
- ✗「两项都交我一起看」
- ✗「做完报我一下」
- ✗「有问题告诉我」

**应该写**：
- ✓「写完先交 4~5 张关键预览，我确认布局再全量」
- ✓「方案报我确认，我过了再写代码」
- ✓「阶段一做完停下来，我核数据再进阶段二」

每道 checkpoint 后面写清验收判据（我看什么、合格标准是什么）。

## 五段式骨架

```
Context:
（背景、目标受众、前情、目标仓库与工作区绝对路径）

Request:
（要它做什么，分条列，每条带具体规格与示例）

Output format:
（交什么文件、写到哪个绝对路径、报告里必须包含哪几项）

红线禁止:
（不许做什么，每条接违反后果）

Checkpoint:
（分几段停、每段交什么、验收判据、遇不明停下问不许猜）
```

## 已知走偏模式对照表

这些是真实踩过的，新指令里必须有对应约束：

| 走偏表现 | 缺的是哪一层 | 补什么约束 |
|---|---|---|
| 用了专业术语，业务听不懂 | 规格第4条 | 术语白名单/黑名单表 |
| 对象用「一/二/三」编号 | 规格第5条 | 一律用真名 |
| 时长拍脑袋，内容塞不下 | 规格第3条 | 按内容量算的档位表 |
| 概念讲错（自创第四种关系） | 规格第2条 | 写清概念边界 + 红线 |
| 同一数据重复呈现三遍 | 规格第7条 | 一屏一事的结构约束 |
| 界面堆满面板找不到用户 | 规格第1/7条 | 受众明确 + 信息密度上限 |
| 数字凭感觉缩，对不上 | 规格第6条 | 基准数据 + 白名单 + 验算等式 |
| 文案和动画时间轴错位 | 规格第8条 | 逐条对齐，禁按平均时长估算 |
| 报告说「已验证」实际没验 | 第三层 | 指定可执行验证方法 + 要求贴实测数字 |
| 一口气跑完才发现方向错 | 第四层 | 分阶段 checkpoint |
| 开错目录改错文件 | Context | 开头标清目标仓库绝对路径 |
| 杀进程把自己的 shell 也杀了 | 环境坑 | 命令逐字写全 + 避坑写法 |

## 下指令后

1 agent 交回了东西，**先看它自己报的自检数字**，不要只看结论
2 **自己独立验一遍**：抽帧看图、curl 实际接口、读文件核对；它的自报不等于事实
3 发现问题时，先判断是它理解错还是指令没写清——后者占大多数，那样改了指令再重派，不要反复让它修
4 同类任务第三次要改同一个东西，说明规格层有缺，回头补 skill/清单，而不是继续逐个补
