# 业务补充收集表（背景 / 目的 / 价值 / 运营计划）

用途：需求评估做完、要拿缺口去找业务（需求方）补材料时，产出一份**可分发、可回收、填得进去**的表。目标不是文档齐整，是让业务十分钟内能补完，并且补回来的不是空话。

---

## 一、两版分发：对外版先发，内部版留底

用户明确的口径是「先看她给的第一版，先不指导她如何填」。所以同一份材料要出**两版**：

- **对外版（发给业务的第一版）**：只放 `原文已写`（照抄原文/分析档）+ `想请补充 ①②③`。**不放填表说明、不放「不合格的样子」判据、不放对需求的评断**。第一版带指导性内容，读起来像在教对方做事，也提前把验收标准摆到桌面上。
- **内部版（自己留底）**：带四块判据表、状态速览、结论三句真话——用来评第一版质量、决定下一轮追问什么。
- **对外沟通由用户自己管**：发什么、什么时候催、要不要指导怎么填，都归他。助手只产出材料，不替他判断对外沟通节奏，也不替他向业务解释要求。

---

## 二、对外版的写法

**结构**：每条需求一节 → 原文摘要（照抄一句）→ 四块 → 每块两行：`原文已写：…` + `想请补充：①②③`；结尾一句话汇总（缺的主要是价值量化与运营计划）。

**预填与提问纪律**：

- **能照抄的照抄**：原文里有的话直接进「原文已写」，注明出处；业务不需要重写他们已经说过的话。
- **原文只有一句笼统话的，标出来**：如「原文只列了要展示的四类信息，没有写为什么提」——这条本身就是最有价值的缺口信号。
- **缺失的写成编号问题，一条只问一件事**，且尽量具体到可以一句话回答：
  - 背景：现在的量级是多少 / 提需求的时间点和触发事件 / 合规具体指哪一条（决定要不要做成国家开关）
  - 目的：希望做到多少比例、现有比例是多少 / 举 2 个真实场景例子
  - 价值：考核看哪个指标 / 基线是多少 / 拉数责任人是谁
  - 运营计划：上线国家与范围与灰度节奏 / 谁宣导培训 / 每月产生多大量 / 重排到具体月份
- **术语要落到业务能看懂**：同一概念在原文里常有多种叫法（「已删除」到底是好友关系被删还是导购账号被删），把待澄清的那一层直接写成问题，不要写进正文当成已定。
- **问句要能被一句话回答**：写成「希望多少比例的活动访客转成私域好友」而不是「请描述私域建联的整体价值」。

## 三、内部版的四块判据（评回收质量用）

| 块 | 要回答什么 | 不合格的样子 |
|---|---|---|
| 需求背景 | 为什么现在提。触发它的是客诉、数据、竞品还是上级目标；涉及哪个国家哪个团队 | 「为了提升效率」「业务需要」这类没有出处的动机 |
| 需求目的 | 要解决的具体问题，一问一句，能被验证解决了没有 | 「优化体验」「增强能力」这类无法验证的说法 |
| 需求价值 | 对哪个业务指标有影响；有基线给基线，没有就写「待拉数」和由谁拉 | 「提升用户体验」这类无指标表述 |
| 运营计划 | 上线后怎么用：谁执行、多大规模、多久跑一次、考核什么；上线时间写到月 | 「上线后按需使用」这类没有执行主体的安排 |

另配一张**状态速览**：每条需求 × 四块，填 `原文有 / 部分有 / 缺（现为产品归纳） / 全缺 / 待量化`，附原文期望上线时间并注明「均已过期需重排」。

---

## 四、内部版结论段必须说的三句真话

收尾不写这三句，这张表就只是格式齐整：

1. **运营计划几乎全缺** —— 说明没人想过上线后谁去用；
2. **价值全部未量化** —— 只有「提升核销率」这种话，没有基线和目标，优先级只能按产品判断排，排不出业务收益；
3. **点名那种站不住的排期理由** —— 典型是某条 P1 排第一批的唯一理由写「改动小」，而它自己的验收条件还没定稿。

## 五、交付形态

- 默认给 md 文件（可直接转发）；用户拿去给业务填时，主动问一句要不要 Excel 版——md 转给业务，很多人不会填表格式。
- 文件放在该需求的调研目录下（与其他评估产物并列），不要散落在根目录。
- 提醒位置差：写进 VPS 侧镜像不等于用户机器上已有，要么发附件，要么等下一轮 pull。
