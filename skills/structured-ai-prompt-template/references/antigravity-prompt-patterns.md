# 反重力(Antigravity)前端生成提示词模式

> 三种已实战验证的提示词模式，用于让反重力生成/修复前端代码。

## 模式一：Bug 修复指令

适用场景：已有前端代码，对照 PRD 审计出问题，需要精准修复。

关键要素：
- 指定文件路径 + 行号
- 每个问题标注【问题N】编号
- 用 ✅/❌ 标注"规格要求 vs 实际代码"
- 涉及多个文件时明确列出所有文件路径
- Constraints 段写死"不要修改的文件"

示例结构：
```
Context: 项目路径 + PRD路径
Request: 【问题1】修复XX文件XX行...（逐个列出）
Constraints: 不要改types/xxx.ts / 不要改API层 / 不要新增依赖
Checkpoint: npm run build 通过后汇报
```

## 模式二：单模块新增指令

适用场景：基于已有参照物（如PO），生成同类型新模块（如PI）。

关键要素：
- 列出参照物路径（反重力会读来对齐风格）
- 用表格对比差异（状态数、字段差异、特殊规则）
- 逐页描述页面结构（列表/表单/详情各一段）
- Mock数据规格明确（最少条数、覆盖哪些状态）
- Constraints 写死陷阱（如"不加审核流""不要加新增按钮"）

示例结构：
```
Context: 项目路径 + 参照物路径 + PRD路径
Request: 【页面1】列表页...【页面2】表单页...【页面3】详情页...
  每页：路径/字段/状态配色/行内操作/Mock数量
Constraints: 执行层不加审核流 / 不加新增按钮 / 上游字段只读
Checkpoint: npm run build
```

## 模式三：批量模块指令

适用场景：多个结构同质的模块一起生成（如PR+PRO、基础资料四件套）。

关键要素：
- 先写共同规则（状态机、配色、交互模式）
- 每个模块只列差异部分（单号前缀、额外字段、特殊规则）
- 尽量复用"参照物"让反重力少猜

示例结构：
```
Context: 项目路径 + 参照物路径
Request: 
  【模块A】差异部分：单号前缀XX、额外字段YY...
  【模块B】差异部分：单号前缀ZZ、额外字段WW...
Constraints: 统一规则...
Checkpoint: npm run build
```

## 通用红线（每次都要写）

1. 不新增 npm 依赖
2. 不改 types/ 和已有 API 层
3. 状态枚举用英文（DRAFT/CONFIRMED/VOIDED）
4. 按钮不可用时隐藏，不渲染 disabled
5. 空值展示 `-`
