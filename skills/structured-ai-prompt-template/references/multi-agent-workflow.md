# 多 Agent 并行工作流 + 展示方法论

> 来源：2026-07-05 ~ 07-06 实战验证，8 线程 Codex + 反重力并行

## 多 Agent 并行原则

1. **文件隔离**：不同 Agent 不碰同一文件，避免合并冲突
2. **模块隔离**：Agent A 改采购模块，Agent B 改销售模块，物理上不可能撞
3. **红线前置**：多线程时人没时间逐行审查，质量靠指令里的红线禁止兜底
4. **封顶 3 路**：超过 3 路并行，人脑上下文切换成本超过并行收益
5. **依赖避让**：`npm install`、改 `package.json` 等有副作用的操作，单独跑一轮

## 展示金字塔

**文不如表，表不如图，图不如面。**

- 文 = PRD 文档、context 文字
- 表 = 字段清单、状态机表格
- 图 = Mermaid 流程图、ER 图、柱状图
- 面 = 可点开运行的系统（pmlophy.com）

面试技巧：先甩链接（面）→ 对方深入再展示 API 文档（表/图）→ 追问底层再给 PRD（文）。

## 四层约束体系

| 层 | 文件 | 管什么 |
|:--|:--|:--|
| 业务 | context/ | 做什么/不做什么 |
| 文档 | AGENTS.md | PRD格式/六维走查 |
| 视觉 | DESIGN.md（Google 格式） | 颜色/字体/圆角/组件 token |
| 执行 | 五段曲红线禁止 | 本次任务边界 |

## Codex 批量文档生成模式

适合 GPT-5.5 一次性生成多份 PRD/设计文档：
- 指令中列出所有需要生成的文件名和格式要求
- 每份文档指定"参照物"（已有同类型 PRD）
- 红线禁止中强调"不写代码、格式对齐参照物"
- 13 份 PRD 文档一次指令完成
