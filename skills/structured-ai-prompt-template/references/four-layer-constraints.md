# 四层约束体系

在强盛科技进销存项目实战中验证：四层约束全压，AI 零犯错空间。

| 层级 | 文件 | 管什么 | 放哪 | 何时读 |
|:--|:--|:--|:--|:--|
| 🏗 业务 | `context/` | 做什么/不做什么/规则/术语 | 项目根 | 任何任务前 |
| 📋 文档 | `AGENTS.md` | PRD怎么写/已知坑/六维走查 | 项目根 | 写 PRD 前 |
| 🎨 视觉 | `DESIGN.md` | 颜色/字体/圆角/间距/状态标签配色 | 项目根 | 生成 UI 前 |
| 🚦 指令 | 五段曲红线禁止 | 本次任务边界/不改什么 | 每次prompt | 每次调用 |

## DESIGN.md 集成

Google Labs Code 开源格式——YAML front matter（机器可读 token）+ Markdown 正文（人类可读 rationale）。

反重力指令中加一条红线：
```
- 配色/字体/圆角只引用根目录 DESIGN.md 中的 token，不自造
```

状态标签配色表（最重要的 DESIGN.md 内容）：

| 状态 | 底色 | 文字色 |
|------|------|--------|
| 草稿 | zinc-100 | zinc-800 |
| 待审核 | orange-50 | orange-700 |
| 待入库 | blue-50 | blue-700 |
| 部分入库 | sky-50 | sky-700 |
| 已完成 | emerald-50 | emerald-700 |
| 已作废 | rose-50 | rose-700 |

## 效果

进销存第一轮 PO 页面有 13 个配色 bug（待审核=蓝、待入库=琥珀、部分入库=橙）。加上 DESIGN.md 后，后续 PI/PR/PRO/FL/即时库存六个模块零配色问题。
