# TSV 字段清单 + 产出物分层方法论（维生素 QS-JXC 实战篇）

> 来源：维生素 AI 课程「项目实战篇」4 篇（QS-ERP / QS-JXC 进销存实战），2026-09-07 深读。
> 用户正在 CMS/娜美 试用，forge 日后升级可用。核心：**少一份重复文件，反而更容易让 AI 做对**。

## 一、TSV 是什么、为什么做字段清单

TSV = Tab-Separated Values（制表符分隔值），纯文本列。

**核心用意**：用 TSV 是为了"方便快速编辑和确认，让 AI 能帮你做预测和走查确认"，**不要用 Excel**。

三大理由：
1. 纯文本 → AI 能直接读写（Excel 二进制，AI 处理费劲）
2. 字段多时比 Markdown 表格好维护（md 表一多就对不齐/乱）
3. 配合 AI IDE 的**预测性自动补全**（Cursor 已装 TSV 插件，填一列预测下一行）

## 二、字段清单分两版：初稿 → 详细稿

**初稿（5 列）——先确认"有哪些字段"**：
`字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 字段说明/描述`

**详细稿（13 列）——再定义"字段在产品上怎么表现"**：
`字段所属分组 | 字段名称 | 字段类型 | 字段来源 | 必填性 | 新增页 | 编辑页 | 列表展示 | 可筛选 | 详情展示 | 字段说明/描述 | 取值说明 | 备注`

**为什么分两版**：先确认字段范围（初稿快、问题早暴露），再定义完整规格（详细稿）。一步到位易乱。

**铁律**：
- **详细稿确认后 = 字段唯一事实源**；初稿只留作过程记录，不再更新
- **只保留 TSV 一份，绝不维护对应 md 副本**——否则"字段清单.tsv + .md 两份、不知哪份最新"

## 三、TSV 放什么 / 不放什么

✅ 放：分组/名称/类型/来源/必填/取值枚举/说明/字段级约束/计算回写说明
❌ 不放（属页面交互，进前端 Demo PRD）：查询区位置、控件占几列、placeholder、下拉样式、远程搜索触发、空态/错误反馈位置、布局按钮排列

## 四、三层分开（核心，别混）

同一字段（例"采购数量"）：
| 层 | 内容 | 放哪 |
|---|---|---|
| 字段事实 | 整数、>0、来源用户填 | 字段清单 TSV |
| 业务约束 | 提交审核时每明细行必填、审核后不可改 | 业务 PRD |
| 页面交互 | 用 NumberInput、失焦校验、错误定位明细行 | 前端 Demo PRD |

回答三个不同问题：字段是什么 / 业务怎么限制 / 页面怎么让用户完成操作。forge 已有字段清单（11列）接近详细稿，只差载体是 md 表而非 TSV。

## 五、工作流链路中每份产出物职责（防重复）

`系统架构/业务流程/系统单据流程/相关单据PRD → 字段清单初稿 → 详细稿TSV → 业务PRD → 页面骨架(可选) → 前端Demo PRD → 前端原型`

- **字段清单 TSV**：字段事实（不放控件/placeholder/错误位置）
- **业务 PRD**：业务规则（不复制完整流程、不重复字段表、不描述前端组件）
- **页面骨架**：可选中间产物（页面结构不清才用，有 Demo 就跳过）
- **Demo PRD**：页面表现交互（不创造字段/状态/动作，按钮显示必须来自业务PRD状态-操作矩阵）

## 六、字段清单逐步丰富（6 步）

1. 找竞品/参考系统做参照
2. 手动填初稿骨架（5-10 字段起）
3. AI 辅助补全（预测补全，新增先当候选）
4. 人工走查（查编造字段/类型/取值，标已确认 vs 候选）
5. AI 输出详细稿（13 列）
6. 再次人工走查

## 七、版本迭代法（已有模块加需求）

**不覆盖第一版**，在 `03-产品设计/` 下新建版本目录（`20260803第一版` → `20260820第二版`）。第一版保留作基线，第二版放本轮新内容。作用：看清版本变化、给 AI 明确上下文范围（默认读第二版）、防止版本边界混。

## 八、给 AI 下任务结构（先边界再任务，一次一层次）

```
输入材料：本次读哪些背景/流程/字段/相关单据PRD
当前任务：本次只输出 XXX（业务PRD / 页面骨架 / DemoPRD 之一）
权威边界：字段以TSV为准，业务规则以业务PRD为准，页面交互以DemoPRD为准；冲突先列不自行补
输出要求：说明产出什么、影响哪些下游
```
一次只让 AI 输出一个层次，不要同时生成字段/规则/页面/原型。

## 九、变更时先改哪份（第一修改入口）

| 变化 | 第一入口 |
|---|---|
| 字段名/类型/来源/枚举/字段级约束 | 字段清单详细稿 TSV |
| 状态/动作/业务规则/下游结果 | 业务 PRD（必要时回流程文件） |
| 页面结构/控件/校验/反馈 | 页面骨架或 Demo PRD |
| 跨角色/跨单据系统处理 | 业务流程/系统单据流程 |

## 十、沉淀方式（实战篇3 总结）

重复多遍且要每次一致的关键步骤，从"手动描述"沉淀成三形式：**模板**（结构）、**Skill**（走查审查思路）、**Prompt**（常用提示词）。这比每次手写强。
