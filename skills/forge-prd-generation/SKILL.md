# Forge PRD 生成工作流 —— AI 辅助

> 2026-07-29 供应商报价单(BJ)实战验证：Workbuddy + Kimi K3 一次生成主PRD(302行)+字段清单+2份Demo，全程 <2h。

## 触发条件

当用户说"现在 PRD 太简单/颗粒度不够/达不到可评审规格"时，这不是"加内容"的事——先做**颗粒度达标审计**（spec-alignment）：拿维他命 QS-JXC 规格当参照，产一份逐模块达标度对照表（✅已达标/⚠️部分缺/❌整套没有），定位真缺口再定返修边界。核心判断点见下。

QS-JXC 规格的本质不是内容多，是：① 七件套+权威源分层（主PRD管规则/字段清单管字段/Demo是生成物不反定义）② 三层分开（字段事实→TSV、业务约束→业务PRD、页面约束→DemoPRD）③ 字段清单用 TSV（初稿5列→详细稿13列）单一事实源，不维护 md 副本 ④ 下游只引用上游不重复定义。

审计的经典缺口形状：
- 主数据档案常只有"主PRD+字段+Demo"三件，**缺业务流程推演 + 用例数据推演**（主数据虽 CRUD 简单，但"被哪些单据引用、引用时固化哪些字段"仍需链路推演）。
- 有前端页面的模块可能**只有原型标注、连 PRD 都没有**（销售/往来/零售/Portal）。
- **真短板常是字段权威源的形态**：md 11列表格 vs TSV 13列单一事实源——md 每列各管一摊(必填/展示/筛选/详情)，改一个字段要同步 5 处。审出"形式"问题才是审到位。
- 别误判：最成熟的单据(如采购订单)往往已完整达标(状态机+动作矩阵+权限+边界+验收全齐)，别说成简单。

返修边界照"先试点→模块→全局、禁梭哈"定：先拿一份已达标单据当样板间，把字段清单从 md 表格升级成 TSV 13列详细稿，**用户审一遍确认规格后再批量**。缺件补件、整套没有的从无到有是另外两批活，别一次全揽。

## 触发条件

用户在 forge 项目中需要为**新业务单据**生成 PRD 套件时使用。新单据指 context/ 中尚未定义的单据类型。

## 标准流程

### 第一步：喂 AI 地基

给 AI 的指令必须包含以下四层：

```
Context:  context/07(项目边界) + context/05(编码规则) + context/08(术语字典)
模板:    templates/业务单据PRD模板.md + 字段清单模板.md + Demo PRD模板.md
参照物:  forge-erp/prd-docs/采购管理/采购订单/ 套件（同类型、已走查）
Request: 输出主PRD(≥300行) + 字段清单(SSOT) + Demo列表页 + Demo新增编辑页
红线:    单号前缀按context/05、术语按context/08、不动context文件
```

### 第二步：人类走查三步

| 步骤 | 内容 | 结果 |
|------|------|------|
| 1 | **检查点核验**：行数/SSOT/状态机/红线 | 不到标准的打回，不确认内容 |
| 2 | **三处决策**：新前缀要回写context吗？术语统一了吗？自动生成vs手工填？ | 人定，AI执行 |
| 3 | **回写context + SSOT同步**：新前缀→context/05、新模块→context/04、删"待回写"标注、字段清单改手工→自动 | 人授权后AI改 |

### 第三步：git 纪律

- AI 只产 PRD 不 commit。
- 人在反重力中 `git add + commit + push`。
- VPS 端 `git pull --rebase` 做全量检查。

## 关键教训

1. **PRD 定位门禁（最高优先级）**：PRD 生成后、出前端指令前，必须让用户确认定位。问："这个模块是谁用的?他做什么?流程图对吗?"。2026-07-29 供应商报价模块从"采购员录入版"→"供应商工作台"重写三轮前端，根因就是跳过了这步。
2. **AI 会自觉标"待回写 context/05"**——这是好事，说明它尊重地基权威。但评审通过必须立即回写，否则重蹈"单号体系自创"的坑。
3. **询价单号等关联字段必须指定自动生成规则**（如 `INQ{YYYYMMDD}-{2位序号}`），不能留"手工填"。
4. **字段清单 SSOT 矛盾是走查阻断项**——Demo 与字段清单不一致，先修 SSOT，再同步下游。
5. **AI 一次输出全套更高效**——不要分多次让 AI 产主PRD→Demo，一次给全指令，一次输出4份文件。
6. **Workbuddy + Kimi K3 作为 PRD 生成工具**，反重力 + Gemini 作为前端编码工具。不要交叉——Workbuddy 写 PRD 给反重力当输入，反重力不改文档。

## TSV 字段清单方法论（维生素 QS-JXC，日后 forge 升级用）

完整版见 `references/tsv-fieldlist-productdoc-methodology.md`。要点：字段清单用 **TSV**（纯文本 AI 可读写 + AI IDE 自动补全）不用 Excel/md 表；分**初稿5列**（范围）→**详细稿13列**（规格），详细稿确认后=字段唯一事实源，**只留 TSV 不维护 md 副本**；字段事实/业务规则/页面交互**三层分开**（TSV/业务PRD/DemoPRD）；已有模块迭代用**版本目录**不覆盖；给 AI 任务一次只输出一个层次。用户正在 CMS/娜美试用。
