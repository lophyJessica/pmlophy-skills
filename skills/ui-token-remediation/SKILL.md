# UI 规范整治：先审计、再分刀

用户说"按 UI 规范整治一下/样式太脏/对齐设计稿/强迫症犯了"时，**不要直接给改造指令**。顺序固定：审计 → 定映射 → 分刀执行。

## 一、先审计，只出数据不出结论

分八类统计代码现状：颜色 / 圆角 / 字号 / 字重 / 间距 / 边框宽度 / 阴影 / 组件覆盖。每类给取值 + 出现次数 + 所在文件。审计指令里写死命令，禁止 agent 归纳，禁止出现"建议/应该/不合理"。

必补一节"未扫到"：内联 `style={{}}` 多少处、CSS 变量间接引用多少次、模板字符串拼接多少处。这些正则抓不到，不写清楚会被误判成"已经干净"。

**关键判据不是"有多少种值"，而是频次分布。** 实测 cms：204 个色值里只出现一次的 109 个、10 次以上的仅 16 个；阴影 19 种里 17 种各只出现一次。一次性值就是噪音，可放心归并；高频值才是需要对齐设计稿的。

## 二、判定层由助手做，执行层给 agent

agent 不参与判断。目标色板、归并映射表、分类规则由助手逐条写死在指令里，agent 只照表替换。
**写"归并到最近的标准色"等于没写**——它会拿蓝的归到灰的。
色差大的必须留人工：只有 rgba(0,0,0,x)、主色透明、大小写归一这三类可以机械处理；其余色值一律不改，列「未处理清单」逐条给原值、次数、文件。

## 三、三刀排序，风险递增

1. 噪音归并（一次性色值、阴影收敛、圆角野值）——视觉几乎无变化，风险最低
2. 高频值对齐设计稿——会真的改变颜色深浅，必须逐页截图看
3. 抽公共组件——改结构

第 2 刀和第 3 刀**不许并行**：抽组件改 tsx、洗值改样式，撞同一文件必然打架。
间距通常不纳入整治：中间值（10px/14px）一动几十个页面布局就变，收益抵不上风险，在规范里承认它们存在即可。

## 四、组件复用度诊断

比组件文件数与路由页数：实测 cms 7 个 React 组件 / 19 个路由页，真正多页复用的只有 Icons 和 BusinessModal，其余各 1 次。比值低就说明页面各写各的。典型症状：同类控件有 N 套实现（分页实测 7 套：permission-/config-/org-/tool-/demo-/cms-/private-detail-pagination）、控件一挤就折行。
抽组件时清点重灾区：分页、单选组、筛选区、表格、空态、确认弹窗、表单字段容器。

## 五、给反重力/Cursor 下批量命令的写法（转义地狱）

**不要把管道链塞进指令。** 实测把 `grep -rhoE '...' | tr | sort | uniq -c | sort -rn` 直接写进指令，反重力会在引号嵌套上来回折腾十几轮（node -e 套 sh -c 套 grep，每层吃掉一层转义），出不来结果。

正确写法：让它先用 write_file 建一个 `.sh` 脚本（命令逐字给定，写明"一个字都不许改"），再 `bash 脚本 > 输出.txt`，最后读 txt 填表。零转义问题。
色值定位用 `grep -rlF`（固定字符串），不能用 -E——色值里有括号和逗号。

## 六、控件被压扁折行的通用根因

中文被逐字折行 = 容器宽度不足 + 缺 `white-space: nowrap`。三个典型：
- `.radio-item { display: inline-flex }` 没设 nowrap，父容器 `flex-wrap: wrap`，两列表单一挤就逐字折行；一行 nowrap 修全站所有单选组
- `.pager-btn { width: 32px; height: 32px }` 是给图标设计的固定方块，塞「上一页」三字必折行，需文字变体宽度自适应加左右内边距
- 总条数不超过一页时仍渲染完整分页（页长选择器、1/1 页码、上下页全死），缺条件渲染

## 七、规范文档常常是错的

审计表一行一个 token，四列：**Figma 权威值 | 规范文档写的 | 代码实际用的 | 处置**。整治指令从「处置」列生成。
别默认规范是对的：实测文字色规范写 #33373b，Figma 是 rgba(0,0,0,0.8)，代码用的是 0.8/0.65/0.45/0.35/0.25 五档，其中四个在 Figma 里不存在——规范只是把代码现状抄了下来。

## 九、从代码反抽规范 → 抽公共组件：两批走，批一零风险

用户抱怨「每次复刻都要重新描述一遍形态，太累」时，根因不是没规范，而是**规范已经存在、只散落在各页 CSS 里没人抽出来**。顺序固定为两批：

**批一：只新增，不改旧页。** 先出一份 UI 规范文档 + 一套 `components/<前缀>/` 公共组件，**一个已有页面都不改**。新组件一律复用现有类名与现有 CSS，不新造样式体系（视觉零变化，旧页不动也不会有回归）。跑完只验构建。

**批二：逐页迁移，一页一提交、一页一验。** 不做一次性全迁——已验收的页面被顺手改坏，排查成本远高于省下的时间。

### 规范文档必须从代码里读，每条带出处

取值不能凭印象、也不能照旧的规范文档拄——写下来每一条都要能指到具体类名或文件:行号（颜色、字号、间距、按钮形态、表格内边距、空态、弹窗宽度、必填星号色值）。写不出出处的条款直接删。收尾时抽查两个值回代码比一眼，错一个就是整份规范不可信。

### 两套类名前缀并存时的收敛方向

实测常见状态：旧页用 `sales-shop__*`、新页用 `shop-*`，取值差不多但类名不同。
**新页面与新组件一律用新的那套，旧页在迁移时改过去；不反向扩散**（不要为了“统一”去改新页适配旧名）。这条写进规范第二节，否则两边会各长各的。

### 组件清单从痛点反推

不要按“应该有什么”列，按**当前重复最多的结构**列：筛选区（字段配置数组 + 查询/重置）、状态页签、表格（列配置 + 空态 + 横向滚动）、分页、弹窗外壳、表单字段容器（标签/必填/字数统计）、状态圆点、图片占位。抽之前先数一数每个页面重复了多少次同一段 className。

## 十、并行执行前先算工作区风险

用户问「这可以并行吧」时，不要直接答可以：多个执行方在同一台机器、同一个仓库工作区里并行改，会互相踩构建产物、git status 和文件锁，报的错还查不出来。要么串行，要么给每个执行方一个独立工作区（如 `git worktree add ..\<repo>-<子任务> main`，共用同一个仓库、文件互不干扰）。**并且给出并行的代价**：期间不能随手提交、合并时要 rebase——很多时候用户听完会选串行。


## 十一、接完分页组件后的三个连带问题（必查）

抽完公共分页只是第一步，接上去之后这三处几乎必然同时出问题：

1. **翻页列宽跳动**：`table-layout` 默认 `auto`，列宽按当前页内容重算，翻到第二页表头就位移，看着像页面在跳。修法两件套——表格加 `table-layout: fixed`，同时用 `<colgroup>` 按列内容分配百分比（每页合计 100%），并给单元格配 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`。**只加 fixed 不配 colgroup 是错的**：所有列平分，长文本列被压扁，比改前更难看。同一个项目里先 grep 一遍 `table-layout`——往往一部分表已经设了 fixed、另一部分漏了，漏的就是报障的那张。
   验收：翻到第 2、3 页读 `th.offsetWidth`，三页数组必须完全相同。

2. **禁用态视觉不可辨**：`disabled` 属性只挡点击，`.link-btn` 这类链接式按钮通常没有任何 `:disabled` 样式，看着跟可点的一模一样，用户会直接说「没有不可点击的样子」。必须补 `:disabled { color: rgba(0, 0, 0, 0.25); cursor: not-allowed }`，并让 hover 规则排除 disabled（`:not(:disabled):hover`）。
   验收：读禁用与可点两个按钮的 computed color，必须不同；cursor 必须是 not-allowed。

3. **mock 不够一页 = 分页组件根本不渲染**：组件在 `total <= pageSize` 时只留「共 N 条」，接完分页却看不到控件，等于没验。凡是接了分页的页面，mock 数据都要补到**超过默认 pageSize**（至少能翻到第二页）；注意各页 pageSize 不同（有的 10 有的 20），按页面实际的默认值补。补完后在 mock 文件顶部留一行注释说明这条规则，后来人才不会又删回几条。
