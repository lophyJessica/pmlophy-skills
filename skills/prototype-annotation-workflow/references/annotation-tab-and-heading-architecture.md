# 标注 Tab 机制与"空 tab 反推缺口"审计

## 两边的 tab / 标题机制（实证，不猜）
- **维他命**：没有内容 tab。runtime 里的 "Tab" 是键盘 `Tab`（无障碍焦点陷阱），"全部"是阅读器"全部页面目录/查看全部/复制全部"。阅读器 = 全屏 + 左侧 TOC 目录（从 markdown `##`/`###` 标题自动生成）+ 渲染正文。标题来源全动态：块标题 = 标注 markdown `## ` 首行；config 的 `moduleName`（如"本页规则"/"示例区域"）+ `title`（"原型业务标注"）。→ 通用、任意项目可看，但无固定评审结构。
- **我们（forge-crm）**：6 个 tab 标签**写死在 runtime.js 常量**（`{key,label}`：page=页面内容 / interaction=交互说明 / rule=业务规则 / field=字段说明 / pending=待确认，+「全部」合并 tab，+ 待确认子筛选 全部/未解决/已解决）；内容运行时按标注 markdown 的 `### 页面内容/交互说明/业务规则/字段说明/待确认` 标题解析填充。`compile_annotations.py` 里没有这些标签 → **标签写死，内容靠 `###` 命名约定**；改标注写错 `###` 名，tab 就空。→ 结构化、评审逐点看，代价是标签写死不通用。

## 空 tab = 真缺口（反推补齐点）
- runtime 空 tab 也展示（"0 项"）→ "没读到的"能反推成补齐点。**前提：`###` 标题必须齐全**，否则"缺标题"会被误判成"没内容"。
- 审计标注完整性方法：按 `<!-- anno:start id=X -->` 切成块 → 块内按 `^###\s+` 切段 → 对 5 个标准标题各自检查段内有无内容。
- **坑：判空必须先剔除 HTML 注释**（`<!-- anno:end -->` 等）——块尾注释会被 `[^\s]` 误判为"有内容"，漏报空 tab。剔除 `<!--.*?-->` 后再查列表项/表格/文字。
- **待确认 tab 初始为空是设计**（它是评审手动输入的问题追踪器，非 PRD 提取）→ 不算缺口。页面内容/交互/规则/字段四类空才是真缺口。
- 动手"补全标题"前先审计——曾实测 17 个标注文件、每块 `###` 五标题全齐、空 section 全为设计性待确认 → 无活可补，别为了流程造一轮无意义补全。
