# 从 Figma 组件库取证，落到项目 UI 规范库

适用：设计侧给了 Figma 组件库（登录态页面，只能靠 agent 浏览器进），要把它抓成结构化数据，用来补齐/校准项目自己的 UI 规范库。

## 顺序（不可颠倒）

1. **结构勘察**：Pages 列表 + 每个 page 下的组件分组 + 批次/Done 标记。只要名字和层级，不展开内容。
2. **两件取样**：一个表单控件（输入框/下拉/单选）+ 一个数据展示（表格/列表）。先出格式给用户确认。
3. **gap 对照**：设计库有什么 vs 项目规范库有什么，各自缺什么。先出对照再落笔，不要直接开抓全量。
4. **全量取样**：确认格式后再批量，并按价值排序——**先抓「设计原则」「颜色/Token」这类基线页，再抓具体控件**。基线决定其他一切，控件数值只是它的实例化。

## 核心原则：读主组件，不读画板实例

- 画板上的**实例**只带当前那一份取值：通常只有一个状态（默认），没有 hover/禁用/错误/只读。
- **主组件**才有完整 Variants 属性面板（类型 × 状态 × 尺寸），token 名字也在那一层。
- 让 agent 明确「点进主组件再看右侧属性面板」，不要停在图层树上看到组件名就当取到了。

## 三个「假数据」识别特征（拿到结果先扫一遍）

| 现象 | 说明它抓错了地方 |
|---|---|
| 正文类控件的字号/字重异常大（如 20px / 700） | 抓到了标题或分组标签图层，不是控件正文 |
| 组件尺寸是超宽超高的整数（如 1680×2360） | 那是画板尺寸，根本没选中组件本体 |
| 同一方法下部分字段整片「未取得」，而别的组件拿到了 | 结构不同就放弃了，没换方法（该组件可能不是组件的组件，或要展开子图层） |

发现任何一条，先让它复核，不要把这些数值写进规范。

## 红线（写进指令）

- 只读，不做任何写入类操作（重命名、移动图层、删除、发布组件库都禁）。
- 不许用截图目测代替读数值；取不到写「未取得」，**禁止套通用设计规范补值**。
- 第一轮不许改项目规范库文件。

## 落规范库时的分工

设计库和项目规范库不是包含关系，别指望一边补齐另一边：

- 设计库通常有：组件全集、状态变体、设计 token、推导原则。
- 项目规范库通常有：技术栈约束、Token 基线、**页面模板与实例映射**、组件交互规则、状态/权限/异常规则。
- 设计库里一般**没有**页面模板（那是项目侧沉淀的），不要因为设计库没提就把它删掉或忽略。
