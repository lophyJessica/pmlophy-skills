## 一、任务范围

- Cursor 内置浏览器中当前已打开、已登录的参考环境页面是唯一视觉真源。
- 用户可指定一个页面、多个页面清单，或明确要求「复刻当前打开的全部业务页面」。
- 不设置固定页数上限，每个指定的参考页面对应一个本地业务页面及路由。
- 不因页面中存在菜单、链接或按钮而自行扩展范围；只有用户明确纳入的关联页面才需要复刻。
- 页面范围、目标名称或参考 URL 存在影响实现方向的冲突时，先说明冲突，并只问 1 个关键问题。
- 目标页面未在内置浏览器中打开、无法读取，或用户未说明页面范围时，不要猜测并开始实现。

## 三、技术栈与项目约束

### 3.1 技术栈选择

- 已有项目：优先遵循现有项目的技术栈、目录结构、路由方案、代码风格和依赖管理方式，不擅自重构或替换现有架构。
- 全新项目：使用 React + Vite + Tailwind CSS，在用户指定的项目路径创建项目。
- 仅安装实现当前任务必需的依赖，不引入无关的 UI 组件库、状态管理框架或工具包。
- 不使用 CDN 或外部字体等运行时网络依赖；图标优先使用参考页面的真实资源或 SVG，禁止用 Emoji 或 Unicode 字符替代图标。
- 禁止将整张参考截图作为背景图、Canvas 或页面图片直接展示。

### 3.2 项目结构与路由

- 仅在用户指定的项目目录内创建或修改文件。
- 已有项目沿用现有目录与路由组织方式，不重复创建工程。
- 单页面使用默认入口路由 `/`；多页面使用前端路由，每个业务页面独立路由，按页面语义命名。
- 用户指定的入口页面对应 `/`，不要额外创建虚构的导航首页。
- 页面之间应支持正常跳转、浏览器前进后退，以及直接访问和刷新对应路由。

### 3.3 代码组织原则

- 优先保证视觉还原和功能可运行，不为追求架构完整度而过度设计。
- 两个及以上参考页面证实存在一致结构时，才考虑提取共享组件。
- 页面特有的布局和业务逻辑保留在对应页面中，避免过度抽象。
- 保留参考系统的设计风格，不套用通用后台模板或擅自建立新的视觉规范。

## 四、内置浏览器读取要求

对每个目标页面，读取并还原：

- 页面标题、最终 URL、当前视口尺寸；
- 整体布局、导航层级、内容区域和滚动方式；
- 文字、字体、颜色、尺寸、间距、边框、阴影和信息密度；
- 表格、表单、Tab、分页、弹窗、状态和可见操作；
- 页面之间已观察到的安全跳转关系。

只允许执行浏览和观察所需的安全操作，例如打开列表、详情、筛选项、分页、Tab、弹窗、展开收起。
**不得执行保存、提交、删除、导出、退出登录、切换账号或其他会改变真实系统数据的操作。**

## 五、视觉还原原则

- 每个本地页面必须以对应参考页面为准，优先还原整体比例、壳层尺寸、内容结构、表格或表单密度、主色和主要操作区。
- 尽可能还原真实页面的文字内容、字段名称、表格列、操作按钮及数据展示形式。
- 保留参考系统原有的固定宽度、横向滚动、控件密度和视觉风格，不要擅自进行「现代化」改造。
- Tailwind CSS 仅作为样式实现工具，不得以默认间距、配色、圆角或组件风格替代参考页面的真实设计。
- 优先适配参考页面当前视口，不凭空增加移动端或响应式设计。
- 宽表格可以在自身容器内横向滚动，避免破坏页面整体布局。

## 六、交互与 Mock 数据

- 不接入真实业务接口，使用本地状态和少量 Mock 数据模拟业务交互。
- 搜索、筛选、分页、Tab、下拉、弹窗和行操作等，应根据参考页面实现可演示的交互。
- 列表、详情、编辑等关联页面应共享同一份 Mock 数据，确保跨页面跳转、数据回填和状态变化保持一致。
- 可以使用 React State、Context 等轻量方式管理共享状态，必要时使用 localStorage 保持刷新后的演示数据。
- 对于新增、编辑、删除等操作，只能修改本地 Mock 数据，不得影响真实系统。
- 表单应根据参考页面还原必填校验、错误提示、禁用状态、操作反馈等可观察到的行为。
- 只实现参考中能够判断且有意义的交互；无法确认的次要控件提供最小反馈，不自行补全复杂业务流程。
- 页面间跳转关系必须与参考页面中已经观察到的真实关系一致，不虚构业务流程。

## 七、执行流程

### 1. 检查项目与页面范围

- 检查用户指定的项目路径，判断是现有项目还是全新项目。
- 现有项目读取技术栈、目录结构、路由和依赖配置，确定实现方式。
- 确认目标页面范围，建立「参考页面标题 / URL → 本地页面组件 / 路由」映射。

### 2. 读取参考页面

- 逐页观察内置浏览器中的目标页面。
- 识别已验证的公共布局、特有内容、交互行为和页面跳转关系。
- 记录影响视觉还原的关键尺寸、布局关系和样式特征。
- 需要展开节点才能看到完整结构时，展开后记录，查看完恢复原状。

### 3. 制定计划并实现

- 输出不超过 3 条的实现计划和关键假设，然后直接实施。
- 已有项目在原有架构中增加或修改页面。
- 实现页面布局、样式、Mock 数据和交互。
- 按需提取已验证的公共组件，避免过度封装。

### 4. 浏览器视觉验收

- 启动本地项目，在与参考页面相同的 CSS 视口下打开本地页面。
- 逐页对比参考页面与本地页面的实际渲染效果。
- 优先修复整体布局比例、壳层、内容结构、信息密度、颜色和关键操作区的明显差异。
- 不以代码编写完成作为任务结束标准，必须检查实际渲染结果。

### 5. 功能与质量检查

- 检查文字溢出、元素遮挡、图片加载失败、异常横向滚动和控制台错误。
- 验证页面间跳转、浏览器前进后退、路由直接访问及刷新。
- 验证核心筛选、分页、表单、弹窗和其他已实现的交互。
- 确认页面能够正常启动，必要时执行构建检查。
- 达到当前参考视口下的明显一致后停止，不做无止境的像素级微调。

## 八、完成后输出

1. **页面映射**：已读取的参考页面标题、URL、视口，以及「参考页面 → 本地组件 / 路由」映射。
2. **实现结果**：已完成页面、页面间跳转和核心交互。
3. **文件变更**：新增或修改的主要文件，逐个说明改了什么。
4. **运行方式**：项目路径、必要的安装命令、启动命令及本地访问地址。
5. **遗留问题**：未实现项、仍有差异和采用的最小假设。
