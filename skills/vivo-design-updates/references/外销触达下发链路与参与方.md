# 外销触达下发链路与参与方（产品口径）

画系统流程图（时序图）、写触达相关 PRD 时用。只写产品认得的东西；服务名留在最后一节给研发看。

## 一、四参与方

| 参与方 | 承担什么 | 关系 |
|---|---|---|
| 外销CMS | 建计划、配受众、存名单、到点触发下发 | 本方 |
| 大数据平台 | 维护行为数据表、按约定时间写入、提供标签与会话字段 | 上游数据源，外销CMS 是它的需求方 |
| vivo 短信中心 | 短信、邮件、富媒体短信、WhatsApp 官方号的实际发送 | 外部通道 |
| 牛信云 | 导购号直发 / 导购号转发的实际发送（经员工服务调 SDK） | 外部通道 |

**不存在的外部系统**：SMP、BSP。`smp` 只是外销CMS 内部的命名前缀（表名 `smp_plan_*`、类名 `Smp*`），全仓库检索 SMP 仅十余处注释；BSP 零命中。旧文档把「SMP 触达引擎」当外部系统是错的。

## 二、六渠道实际出口

| 渠道 | 分类 | 出口 |
|---|---|---|
| 短信 | 公域 | 短信中心 |
| 邮件 | 公域 | 短信中心 |
| 富媒体短信 | 公域 | 短信中心 |
| WhatsApp 官方号 | 公域 | 短信中心 |
| 导购号直发 | 私域 | 员工服务 → 牛信云 |
| 导购号转发任务 | 私域 | 员工服务 → 牛信云 |

短信中心内部把 WhatsApp 官方号最终交给哪家供应商，看不到（短信中心是外部依赖），只能确定官方号不进牛信云。

## 三、链路上的产品事实

1. **名单固化是真实环节**：提交人群 → 固化出名单 → 就绪后按渠道分发。产品方案里「保存人群时生成名单并冻结」与它天然对齐，只需把**名单生成时间**暴露给运营，不需要另造机制。
   - **外销 MVP 定稿**：不做人数缓存（内销是 8 小时）、不做独立人群分析入口、不做 day 分区；保存人群时一次性生成名单并冻结，重新保存才能拿新数据。这几个优化是为大数据量与多人并发服务的，MVP 阶段用不上，照搬会把版本排不进去。
2. **发送结果能回传**：计划执行详情可展示成功、失败量。
3. **触发是「到点执行」不是「实时监听」**：立即与延迟的区别是触发时间怎么定，产品文案不能写「实时」，否则运营以为秒级发出。
4. **取数是 CMS 主动去拉**：按与大数据约定的取数时间去拉当日数据，系统不校验数据是否已写完；大数据晚写会静默取到旧数据，属运维约定不是系统能力。结果为空时提示「无匹配人群，若刚发生行为请次日再试」，不要写「条件有误」。

## 四、立即 / 延迟的产品定调

- **立即和延迟都做**，这是产品要求；实现路径（新增计划类型 / 触发时间填当前时刻 / 其他）归开发选型。现有源码里只有定时型，只是「现在长什么样」的佐证，不是缩需求的理由。
- 事件类型会影响可选时机：立即类事件可选立即或延迟，延迟类事件的「立即」置灰；不做「提前」。
- 降级只在排期阶段讨论，三条同时成立才砍（开发给出成本量级 + 业务不急 + 有「现有场景用不到」的具体场景），且砍「立即」保留「延迟」。

## 五、牛信有两个身份，别混

牛信云既是**国际短信通道商**，也是 **Meta 官方授权的 WhatsApp BSP**。

| 对象 | 现状 |
|---|---|
| 国际短信 | 正在做「牛信 → 短信中心」迁移，先挑一个国家灰度全走短信中心，再切双通路兜底 |
| 富媒体 / 邮件 / WhatsApp 官方号 | 已走短信中心 |
| 导购号直发 / 转发 | 不在迁移范围，仍走牛信 |

所以代码里「短信调短信中心、导购 WhatsApp 还调牛信」不是矛盾，是两条线。灰度期如果出问题，表象是「短信没发出去」，不是行为圈人错了——评审 PRD 里值得列成风险项。
