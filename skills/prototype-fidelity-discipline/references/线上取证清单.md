# 线上取证清单

对一页真实系统页面取证时，按这份清单逐项抄，抄不到就写「未检出」，不要留空也不要猜。

## 页面结构

1. 页面 URL、来源站（生产 / 测试 / 内销 / 外销）、取证时间
2. 面包屑或页面标题原文
3. 区块自上而下的顺序，每个区块的标题原文
4. 页脚按钮：逐个列，含顺序（查看态与编辑态分别记）

## 表单字段

对每个字段逐行记：

| 项 | 说明 |
|---|---|
| 标签原文 | 照抄，含必填星号的有无 |
| 控件类型 | 单行输入 / 多行 / 下拉 / 单选 / 多选 / 日期 / 日期时间 / 开关 |
| 占位符 | 原文 |
| 默认值 | 实际选中项，不是推测 |
| 可编辑性 | 编辑态可改 / 置灰只读 |
| 计数与上限 | 形如 4/20 的真实值 + 上限数字 |
| 选项 | 逐条抄原文，含顺序 |
| 辅助说明 | 字段下方有没有说明文字，有则抄全文——这决定了原型要不要带 |

字段内部布局也要记：标签在左控件在右，还是上下排列；字段是一列往下排还是两列并排。

## 列表页

- 顶部筛选区：有哪些控件、占位符原文
- 表头：逐列抄列名与顺序，标出哪些列头带筛选入口
- 行操作：有哪些按钮/链接，文案原文
- 分页：每页条数与可选项原文
- 空态文案原文

## 表格内的可编辑控件

- 列顺序
- 哪些列是开关/下拉/输入，哪些是纯文本
- 只读态下这些控件是 disabled 还是整列不渲染
- 互斥逻辑：是否存在"全表只能选一个"这类约束，如何表现

## 树 / 分类结构

- 节点前有没有 checkbox，是单选进详情还是多选圈选
- 每个节点一行显示什么（名称、右侧标签、计数）
- 展开收起形态、默认展开层级
- 点击节点的行为

## 交互态

- 组/条件类控件：默认几组、单组最多几条、新增入口文案与位置、组内关系控件有哪些选项、组间关系控件有哪些选项
- 查看态与编辑态的差异：哪些控件消失、哪些置灰
- 切换某个选项后，其他控件的出现与消失（例如选"部分"才展开多选下拉），以及切回后已选值是否清空

## 记不下来的部分

单列一节写「未检出 / 待补证」，写清为什么取不到（未展开下拉、页面需登录、值渲染在 canvas 里等）。这一节宁可多写，也不要让下游把缺失部分脑补成结论。
