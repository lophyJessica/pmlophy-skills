# 接任务前 5 秒自检

> 触犯任何一条 = 做完再犯同类错误 = 用户浪费时间+token

| # | 检查项 | 做 |
|---|--------|----|
| 1 | **路径对了吗** | 部署前先问清楚目标路径,不猜 |
| 2 | **DB名/配置对吗** | 不确定就 git pull 看源码,不靠记忆 |
| 3 | **步骤跳了吗** | 用例推演在前,前端在后;审计在前,部署在后 |
| 4 | **擅自动手了吗** | 用户没明确说"你来部署/你改",只给指令不执行 |
| 5 | **重复发了吗** | 先 git pull 确认远程状态,不发已经 push 的内容 |
| 6 | **收到东西先问不是先做** | 文件/压缩包/链接发来→先问"要部署到哪/做什么"再动手 |
| 7 | **时间查了吗** | 提到日期/星期/时间→先跑 `date`,靠系统不靠记忆 |
| 8 | **输入全了吗** | 结构化输入→结构化输出。用户没说完就不脑补,不多问 |

| 9 | **3轮修不好别硬撑** | 同一bug修复超3轮→停手,交Codex全量诊断(读两边完整代码对比),不手工patch循环 |

## 反向自检：哪些事不该问用户

「擅自动手」的反面同样成立——**把本该自己闭环的决策上报，也是在浪费用户时间**。合作久了，用户原话是「不是所有决策都需要我来拍，你自己经验也很多」。

| 自己拍板，直接做 | 必须问 |
|---|---|
| 技能库内部整理（查重、合并、补充、删除重复项） | 动用户的真实资产（代码仓库内容、文档定稿、记忆条目批量删改） |
| 已授权仓库的常规提交与 push（库同步、看板、交接） | 对外交付物发出去、发到群里/领导面前 |
| 清理可再生数据（缓存/中间帧/旧备份/日志） | 删任何不可再生的东西（原始素材、成片、唯一副本） |
| 重跑验证、补跑失败步骤、换实现路径 | 口径拍板、范围变更、排期与优先级 |
| 修自己上一轮做错的东西 | 花用户的钱、动凭据、影响其他 agent 的隔离环境 |

判据：**做错了能不能自己恢复**。能——自己做，做完一句话报告；不能，或影响用户资产与对外口径——先问。问的时候给结论+选项，不问「要我干吗」。
