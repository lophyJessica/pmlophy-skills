# Excel 报表交付件生成

用 openpyxl 出“能让领导直接打开就看得懂”的 Excel：矩阵表、组合图、嵌入截图、分组合并。适用于功能盘点表、运营数据快照、对比表这类交付件。

**核心原则：交付件不是数据 dump。** 能让人一屏看懂结构、一眼看出数，才算完成。自己读不到渲染结果时，必须按下面的硬参数写完再交给用户验。

## 一、openpyxl 图表的四个必踩坑

openpyxl 生成的图表在 Excel / WPS 里能打开但显示不全，九成是这几条：

### 1 分类轴必须显式设到底部

默认写出的 `catAx` 是 `<axPos val="l"/>`，与左侧数值轴同侧，Excel 渲染时会把分类标签吃掉——图表能显示、柱子也有，就是 X 轴空白、月份/名目标签全没。

```python
chart.x_axis.axPos = "b"
chart.x_axis.delete = False
chart.x_axis.tickLblPos = "nextTo"
chart.x_axis.majorTickMark = "out"
chart.y_axis.axPos = "l"      # 左轴
line.y_axis.axPos = "r"      # 右轴
```

### 2 分类与数值都要带缓存，不能只给区域引用

`set_categories(Reference(...))` 默认写成 `<cat><numRef>`；若单元格存的是文本（`2026-01`、「首页」这类），写 numRef 会让 X 轴变成 1/2/3 或直接空白。就算写成 `strRef`，跨表引用不带缓存时 Excel 也不主动去算，一样显示不出来。

正确做法：给每个 series 的 `cat` / `val` 都写死缓存值。

```python
from openpyxl.chart.data_source import (AxDataSource, StrRef, StrData, StrVal,
                                        NumRef, NumData, NumVal, NumDataSource)

s.cat = AxDataSource(strRef=StrRef(f="'单月数据'!$A$51:$A$60",
        strCache=StrData(ptCount=n, pt=[StrVal(idx=i, v=str(v)) for i,v in enumerate(labels)])))

s.val = NumDataSource(numRef=NumRef(f="'单月数据'!$B$51:$B$60",
        numCache=NumData(formatCode="#,##0", ptCount=n,
            pt=[NumVal(idx=i, v=(v if v is not None else 0)) for i,v in enumerate(values)])))
```

注意 `s.val` 必须赋 `NumDataSource(numRef=NumRef(...))`，直接赋 `NumRef` 会报 `Series.val should be NumDataSource`。

### 3 数据标签要显式加

不加 `dLbls` 就只有柱子没有数字，看的人得拿尺子量柱高。

```python
from openpyxl.chart.label import DataLabelList
c.dLbls = DataLabelList()
c.dLbls.showVal = True
c.dLbls.numFmt = "#,##0"          # 百分比系列用 "0.0%"
c.dLbls.position = "outEnd"        # 柱顶部
c.dLbls.showSerName = False
c.dLbls.showCatName = False
c.dLbls.showLegendKey = False
```

不要给每一条线都加标签——10 个分类 × 3 条线上 30 个标签会互相遮挡。**只标主指标（柱子），比率看右轴读数。**

### 4 组合图（柱 + 双折线双轴）

```python
bar = BarChart(); bar.type = "col"
bar.add_data(...); bar.set_categories(...)
line = LineChart(); line.add_data(...)      # 成功率、阅读率两条
line.y_axis.axId = 200
line.y_axis.crosses = "max"; line.y_axis.axPos = "r"
line.y_axis.numFmt = "0%"
bar += line                                  # 合并到同一图形区
ws.add_chart(bar, "A4")
```

合并后再对 bar / line 各自的 series 写缓存，顺序不能反。`add_chart` 要加在图表所在的那张 sheet 上——写成数据 sheet 会把图画到数据页去。

## 二、量级差异大的数据不要塞同一张图

四个渠道发送人数从 7.4 亿到 4 条，相差六个数量级。挤在一张图上，小量级的会被压成贴着底的直线，什么都看不出来。

规矩：**量级差 100 倍以上就不要同图。** 每渠道单独一张图（柱 + 线），再另出一张同量纲的对比图（如各渠道成功率，都是 0%-100%，可以同图）。量级太小的（零星几条）直接不画，在文字里注明为什么。

## 三、页面分组用合并单元格，不要逐行标注

长表要表达“这 20 行属于同一个页面”，有两种做法，选前者：

- **合并单元格**（推荐）：页面名列按块纵向合并，截图列同范围合并，图锚在合并区中央。视觉上自然成组，不需要在图上画一堆红框。
- 逐行红框标注：一行一个框，20 个框在 750 宽的图上糊成一团，比不标更难读。红框只在「要跟人并排讲的核心页」上圈 3-5 个区块，不做全量。

合并的硬约束：

- 同一页面被拆成两段的（中间夹了别的页面），做**两个独立区域**，不许跨越中间那段合并。
- 值只保留在左上角单元格，其余必须为空。
- 合并不跨页面，写代码前先按页面对行分组、逐页确认起止行号，不要按「相邻相同值」简单合。
- 合并后自动筛选会失效。**要么去掉筛选，要么不要在可筛选的明细表上合并**——留一个点了没反应的筛选按钮比没有更糟。

## 四、插图：锚点、缩放、行高的联动

- 图片是浮动对象，不随合并单元格走。要自己算锚点：水平居中于目标列，垂直居中于该页面块的总高度范围。
- **图宽不要写死。** 先读每张图的实际像素尺寸，按「图高不超过块高、图宽不超过列宽」双向约束等比缩放。混入手工截图时尺寸与自动截图差很多（1152×2376 vs 750×1624），写死宽度会拉伸变形。
- 块太矮放不下时，两种选择：①把该块所有行行高抬到 `需要高度 ÷ 行数`（小幅页适用，反正内容本来就少）；②缩图宽。**优先抬行高**，图缩到 60px 宽就看不清了。
- 行高乘积用 `*0.75`（pt ↔ px 换算方向极易搞反，搞反会把行高算成四倍）。
- 图高向下取整（floor）而不是四舍五入，否则 131px 的图会溢出 98pt 的块，垂直居中偏移变负值。
- **手工编辑 xlsx 是下策**：行高、合并区、图片缩放都是生成脚本算出来的，手工改容易破坏结构。要改内容就改生成脚本重跑；必须在现有文件上补图时，先备份一份再动。
- **页面映射一对多时，同一张图要挂到多个块下**：内销把功能拆得比外销细，一张外销图可能同时对应两个内销页面（任务页 ↔ 「我的待办」+「任务中心」）。报数时分开两个数：「几个文件」与「插入几次」，否则看的人会以为多插了图。
- **区域列只填真有对应的页面**：外销截图只进它对应的那个区域列（印尼截图列），其余区域列一律留空，不许把同一张图灌进多个区域列。

## 五、列宽与数字格式

- 大数（亿级）列宽给 16，不要给 11——否则 Excel 只显示 `########`，用户会以为没数据。这不是错误，是列宽不够，但看到的人第一眼会慌。
- 数字统一 `#,##0`，百分比 `0.00%`，空值留空字串而不是 `—`（入库时能识别成 null）。
- 长表（一行一个维度组合）与矩阵表（渠道块 × 指标行 × 期间列）同时出：矩阵给人看，长表给程序和 agent 读。
- 期次列一律写完整区间（`2026/01/08 ~ 2026-05-31`），不写单末日——写 `2026-05-31` 会被读成单月数据。

## 六、内容密度：去重率是质量指标

同一列出现大量重复文本，说明这一列写的是上一层级的内容，不是本行自己的。判定方法：`count(distinct) ÷ count(*)`。

- 低于 30% 就要重写。实测出过 1136 行只有 202 种写法（18%），8 个页面整页 30 行同一句，领导一眼看出是机器刷的。
- 压缩粒度后（一个区块一行）应达到 90% 以上。
- 用合并单元格掩盖重复是错误对策：视觉上不重复了，信息量一点没增加。

三层结构：页面 → 功能区块 → 穷举子功能。子功能项列写区块名，功能介绍列写穷举（顿号串联），**不要加「包含：」前缀，不要补业务价值句**——价值句反复就那几种写法，是重复的主要来源。单区块原子功能上限 6 个，超了就再拆一层。

## 七、交付前必做的读回自检

生成完不能只信脚本自报，必须重新打开 xlsx 核这几项，并把结果写给用户：

```python
import zipfile, hashlib
z = zipfile.ZipFile(path)
# 1 文件头是否 PK（不是就被 DLP 加密了）
open(path,"rb").read(2)
# 2 图片数与唯一内容数
media = [n for n in z.namelist() if n.startswith("xl/media/") and not n.endswith("/")]
uniq = {hashlib.md5(z.read(n)).hexdigest() for n in media}
# 3 合并区数、行数列数（openpyxl 读回）
# 4 锚点行是否落在对应页面块范围内
# 5 图高是否超过块高（溢出）
```

图片数多于唯一内容数是正常的（同一路由的不同状态截出来长得一样），但要逐组报出哪些页面共用，不能只说「正常」。同时要主动确认：每个页面块确实各自插了自己的图，不是一页有、一页空。

## 八、在线表格导入

公司用 docs.vivo.xyz 这类平台时：

- **带嵌入图片的 xlsx 可以直接导入，图片保留。** 先拿一个 3 页的小样本导进去验一次，再上全量。
- 平台表格里手动「插入图片」也可行，但几十张图手插不现实。
- 合并单元格导入后一般会保留，但**合并后筛选会失效**，在线协作场景下提前告知使用者。
- 导完必查三处：合并块有没有散、图有没有跟着块走、小图（60px 宽那些）还能不能认出是什么页面。

## 九、公司 DLP 会对 xlsx 异步透明加密

生成几分钟后文件头会变成 `%TSD-Header-###%`，本机打开无感知，但外发/上传会失败。TSV 不受影响。

- 判断是否被加密看文件头前两字节是否为 `PK`，不要只看能不能打开。
- 生成与校验要连跑，利用加密生效前的时间窗。
- 要发出去要么走公司解密流程，要么改发 TSV 或截图压缩包。

## 十、自认没法验证图表渲染时怎么办

本地 LibreOffice 起不来、又看不到 Excel 界面时，只能在 XML 层核：图表个数、每个 chart 的 `cat` 是否 `strRef` 带 `strCache`、`ptCount` 是否等于分类数、`dLbls` 是否存在、`catAx` 的 `axPos` 是否为 `b`。

## 十一、送进报表的截图先过质量门槛

图插得再整齐，截图本身是三行数据的空壳也没用。插图前先卡两道：

- **数据量**：列表类接口统一返 20 条、`total` 给 200 以上，首屏要满、有分页可翻。同批数据必须真有差异（姓名 15 个以上轮换，手机号尾号、机型、状态、日期、金额各自错开），不许复制粘贴只改名字。体检项里加一条「首屏可见列表项少于 10 个且非本征空态页则不合格」——只验「页面有 50 字内容」会把三行数据的空壳放行。
- **空态**：本征空态页（已移除状态、异常页、信息缺失页）列豁免清单保留，其余页面出现「暂无 / 无数据 / 加载中 / 未检索到 / 请求失败」一律补数据。

人工截的图（弹窗态、结果态、需登录态）放回同一个目录后，会被后续自动重截按文件名全量覆盖。规则：在路由映射与截图脚本里各建一份 `HUMAN_SHOTS` 名单命中跳过，并且**重截后拿字节数与修改时间再核一次**证明没被动过——只靠「脚本会跳过」是口头保证。名单随每次补图增长。

**用户后来自己补的替换图，要连着两件事一起处理**：覆盖进截图目录 **+** 追加进 HUMAN_SHOTS。只做前者，下一轮自动截图就把用户辛苦补的图冲掉了。替换后核一下非白像素占比变化（如 0.73% → 25.31% 才算真的补上了内容），不能只看文件变大。

**裸页面截图不合格的根因不止「数据太少」，还有「没有客户端外壳」。** 浏览器直接截的业务页面没有状态栏与顶部导航，和真机截图放在同一张表里一眼就露馅。截图脚本要能把外壳当一层注入，业务代码一行不改，两套形态不能混用：

| 环境 | 外壳组成 | 备注 |
|---|---|---|
| 企业微信 H5 | 状态栏 + 导航栏（左细线返回箭头、中标题、右「更多」三点） | **没有胶囊**，胶囊是微信小程序专有 |
| 微信小程序 | 状态栏 + 导航栏 + 右上胶囊（白底浅灰细描边，内含 `···` 与 `×`，中间一道浅灰竖线） | 胶囊 87×32 CSS px |

两套都按外壳总高 100 CSS px 做：状态栏 48 + 导航栏 44 + 留白 8，DPR 2 即 200 输出像素。状态栏时间固定 9:41。注入前给 `body` 加同高 `padding-top`，否则内容被外壳压住；固定定位的业务元素要整体下移。一级 Tab 落地页不显示返回箭头，二级以下显示。浏览器插件注入的浮层（翻译浮层、vConsole）要在截图时隐藏——它们不是真机存在的东西。外壳参数写死在注入脚本里，禁止执行者自行微调颜色尺寸圆角。

## 十二、不要给一个活同时开两个写同一目录的执行者

两个 agent 并行做同一份数据的两个版本时，冲突点不在输入（都能只读），而在输出与中间文件：

- 输出文件名必须在指令里写死且不同，别指望执行者自己避开。
- 两边都禁止回写共用的源 TSV——哪边写了，另一边读到的是中间态。
- 共享的图片/源数据目录一律只读，谁也不许动。

同一个机器上并行跑两个处理大量图片的脚本会抢内存与 IO，串行更稳；真要并行就限定在互不依赖的产物上。

**并行改造同一套生成基建会打架。** 两条线同时动同一份 fixtures / 校验脚本 / 路由映射 / 截图目录，一个在补数据一个在重截，结果互相覆盖、双方都报「我改过了但对方说没有」。规矩：同一时间只让一个执行者动基建，其余线只读产物、只写自己不同名的输出文件。派第二份指令前先确认前一个跑完了；没有中途插话能力的执行者宁可不并发派活。
