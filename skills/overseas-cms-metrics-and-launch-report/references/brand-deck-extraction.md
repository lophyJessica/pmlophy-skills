# 从公司现成 PPT 里量出品牌规范，再拿它生成自己的报告

适用：用户甩过来一份公司内部的成熟 PPT（同类项目规划/历史上线报告）并问"为什么不按这种排版来"。
原则：**不要凭审美自己设计版式**。先把那份 PPT 拆成可量化的规范（主色、字体、字号、封面图、标题位置），再用同一套规范重写生成器。

## 1. 先找母版，别急着改生成器

公司里的正确母版通常是：同类项目的年度规划、上一任产品做的同主题报告、公司统一模板。判断标准不是"好看"，而是**同部门、同受众、同类型**。

拿到母版后，下面四件事全在本地量，不需要问用户。

## 2. 量主色：统计形状填充色，**不要读主题配色**

最坑的一点：`ppt/theme/theme1.xml` 的 `clrScheme` 往往还是 Office 默认值（accent1 = `4472C4`、dk2 = `44546A`），**品牌色是逐形状手工填的，不在主题里**。读主题会得到一套完全错误的颜色。

正确做法是把所有幻灯片的形状填充色数一遍，取频率最高的那几个：

```python
from pptx import Presentation
from collections import Counter
fills, fonts, sizes = Counter(), Counter(), Counter()
for s in Presentation(f).slides:
    for sh in s.shapes:
        try:
            if sh.fill.type == 1:                      # solid
                fills[str(sh.fill.fore_color.rgb)] += 1
        except Exception:                              # 图片/图表没有 fill
            pass
        if sh.has_text_frame:
            for p in sh.text_frame.paragraphs:
                for r in p.runs:
                    if r.font.name: fonts[r.font.name] += 1
                    if r.font.size: sizes[r.font.size.pt] += 1
```

经验值：出现频率最高的那个就是品牌主色（实测某份外销 PPT 里 `#415FFF` 出现 56 次），紧跟其后的是深一档（`#3C5CE8`）和浅底（`#EDF0FF`）。字体同理取第一名（实测 `微软雅黑` 613 次），字号分布也顺手拿到（正文主力 12–14pt，页标题 20pt）。

规范直接写成生成器常量：`VIVO = RGBColor(0x41,0x5F,0xFF)` 这类命名，别散落在各页。

## 3. 取封面图：沿 rels 找到 ppt/media

封面的大图（园区照、产品图）通常挂在**版式**而不是幻灯片上，两处都要看：

```python
import zipfile, re
z = zipfile.ZipFile(f)
for rel in ('ppt/slides/_rels/slide1.xml.rels',
            'ppt/slideLayouts/_rels/slideLayout12.xml.rels'):
    data = z.read(rel).decode()
    for m in re.finditer(r'Target="\.\./media/([^"]+)"', data):
        name = m.group(1)
        open('/tmp/brand/' + name, 'wb').write(z.read('ppt/media/' + name))
```

抽出来先用视觉工具确认是哪张（封面大图往往是超宽画幅，2.8:1 以上，正好铺满上半版），再 `add_picture` 复用。

## 4. 量版式坐标：标题贴页顶

```python
for sh in slide.shapes:
    print(sh.name, sh.left/914400, sh.top/914400, sh.width/914400, sh.height/914400)
```

公司内页的典型量法：**标题占位符在 (0.22, 0.27)，宽 12.9、高只有 0.24in** —— 也就是标题是贴近页面顶端的一小条，不是居中大标题。照这个坐标放自己的标题（20pt 足够），页面观感立刻从"文档"变成"公司汇报"。页脚位置同理照抄。

## 5. 内页：bullet 列表要改成卡片网格

纯项目符号列表会被一眼判定为"Word 搬家"，和品牌极简风不匹配。改法：

- 每条要点做一张卡片：浅品牌底（`#EDF0FF`）+ 左侧一条 0.05in 主色竖条 + 圆角矩形
- 网格：≤2 条单列；3 条以上两列，行数 `ceil(n/2)`；卡片高度上限 1.55in
- 卡内二级结构：把长句按分隔符切开，前半做**主色加粗小标题**，后半做深灰正文——这是把大段文字变成"可扫读"的关键。**分隔符必须包含 `｜` `|`，maxlen 不小于 20**，否则会把日期拆断：按固定字符数截断时，`"第一阶段 2025.09 — 2026.03｜打底座"` 会变成 `…2025.09 — 2` / `026.03`，渲染出来是 `2025.09—2 / 026.03`，用户一眼就是"数字很混乱"。日期区间类的一页干脆别用卡片，改成三段式叙述
- 超过 8 条就拆页，不要缩字号硬塞

```python
def split_lead(text, maxlen=22):
    for sep in ("｜", "|", "：", ":", "——", "，", "。"):
        i = text.find(sep)
        if 0 < i <= maxlen:
            return text[:i], text[i+1:].lstrip("：: —｜| ")
    return (text, "") if len(text) <= maxlen else (text[:maxlen], text[maxlen:])
```

## 6. 两个一眼被挑出来的细节

1. **末条如果是总结句**（以"一句话/结论/总结"开头），不要让它混在卡片里当"第 N+1 张卡"——改做底部通栏主色条、白字。判据：`len(bullets) >= 3 and bl[-1][:12]` 命中关键词，就把它从卡片列表摘出来单独画。
2. **页码只出现一次**。右上角放了大号页码、页脚又写 `6 / 27`，会被指"重复且含义不清"——留页脚那个。
3. **状态类页面必须真画颜色，不能只写在文案里**。文案写"公域触达（绿）"而版面全是同色卡片，会被一眼看穿："三色没标出来？"。这类页单独写一个渲染函数：表头四列（业务线 / 已上线 / 在建 / 规划中），每列用**浅色底 + 同色竖条**，上方一行**图例色块**，底部一行**判定口径**（绿=已上线且至少一国在用；黄=代码完成或验收中；灰=只有方案无排期）。空值统一画 `—`，别留白让人猜。

## 7. 参考件只是「一页导出图」时：用视觉量版式，别再找 pptx

用户给的体例参考常常不是整份 PPT，而是**单页导出图**（聊天里发来的一张 PNG，或一个 zip 里只有一张 `xxx_03.png`）。这种情况不要去找 pptx 量形状（找不到），直接对该页做版式取证——**渲染/查看时问清楚这几件**：标题在哪个位置、有没有品牌装饰元素、内容分区用什么小标题、是图多还是表多、有没有页脚页码。

实测某外销同类报告的定式（可直接作为生成器模板）：

1. **左上角两枚蓝色斜条**（`MSO_SHAPE.PARALLELOGRAM`，一深一浅）——品牌标识位，每页都有；
2. **标题贴页顶左对齐**（y≈0.30in），前面带一个「章节名：」的彩色前缀；
3. **标题下一条浅蓝细横线**（高 0.018in，整页宽）分隔标题带；
4. **正文分区块**，每块一个**品牌蓝加粗小标题**（「需求背景：」「需求内容：」「需求价值：」），块内左侧文字 + 右侧表格；
5. **以表格和贴图为主**，长段落很少；
6. 参考页无页脚页码——但我们自己的报告保留页脚（左：报告名，右：页码）。

**标题前缀与标题要放进同一个 textbox、同一段落里的两个 run**（前缀 run 用深品牌色、标题 run 用深灰），不要拆成两个 textbox 靠 `x + 0.02*len(kicker)` 这类估算偏移拼——字体一换就重叠或粘成「需求背景横向组织」这种读不通的假标题。

**每个内容页至少给一张表、一张图或一张截图**。全页只有文字框的版本会被直接打回：「全是文字描述，没有任何贴图」。上线报告的「产品设计方案」段尤其如此——那一段的价值就在界面本身。

## 8. 收尾自检：除了"有没有溢出"，必须多问一句

渲染成 PNG 后逐页看时，除了溢出/截断/字号，**必须再问一次"像不像这个品牌、是不是 Word 搬家"**。只查溢出会交出"技术上没毛病、观感上被否"的东西。

常见评语的对应改法：
- "Word 搬家／不像品牌极简风" → 上卡片网格 + 拆小标题
- "照片和色块硬切" → 在接缝处加一条 0.06in 白/浅色过渡条（渐变要写 XML，先别折腾）
- "右侧数字对不齐" → 数字列右对齐定宽（如 1.05in），标签列固定起点左对齐，不用自适应宽度
- "总结条像第六层" → 通栏色条 + 换底换字号，与卡片明显区分
