# 用 python-pptx 把逐页文案生成真 PPT，并做渲染自检

适用：汇报类 PPT（上线报告、复盘、分享）已经有逐页文案 md，用户要一份能直接讲的 `.pptx`。
核心原则：**PPT 从 md 生成，不在 PPT 里手改字**；生成完必须渲染出来看一遍再交付。

## 1. 环境

系统 Python 是 PEP 668 管制的，直接 pip 会失败。建独立 venv，别污染 Hermes 自己的 venv：

```bash
python3 -m venv /root/venv-ppt
/root/venv-ppt/bin/pip install -q python-pptx
/root/venv-ppt/bin/python -c "import pptx; print(pptx.__version__)"
```

渲染自检需要一个 headless 转换器和字体（不装字体，中文会回退，页面观感会偏，但溢出/重叠仍看得准）：

```bash
apt-get install -y -q --no-install-recommends libreoffice-impress fonts-wqy-microhei
```

## 2. 生成器结构（一份脚本，可反复重跑）

脚本固定放交付目录（如 `deliverables/<批次>/gen_ppt.py`），结构：

1. **解析文案 md**：按 `## 第(\d+)页 · 标题` 切块；块内按 `**页面标题** / **核心一句话** / **页面要点** / **需要的数据与图表** / **备注**` 分段。要点取 `1. 2. 3.` 或 `- ` 开头的行。`**需要的数据/图表**` 和 `**备注**` 是写给讲者的，不进幻灯片。
2. **统一版式助手**：`txbox()`（带 word_wrap、零内边距的行内文本）、`rect()`（去阴影的色块）。
3. **内容页模板**：标题 27pt 深蓝加粗 → 下方 1.5in 短装饰线 → 浅底色块里放「核心一句话」→ 正文要点 → 底部页脚（左标题、右 `页码 / 总页数`）。
4. **封面与目录单独写**，不要用内容页模板套。
5. 16:9：`prs.slide_width = Inches(13.333)`，`prs.slide_height = Inches(7.5)`，空白版式取 `slide_layouts[6]`。

## 3. 防溢出：按内容自动缩字号，不要写死字号

固定字号必然在长文案页爆掉。按「可用高度 / 估算行数」反解字号：

```python
cpl = max(20, int(width_in * 72 / fs * 0.98))   # 每行字符数（中文全角近似）
lines = [math.ceil(len(b) / cpl) for b in bullets]
line_h = fs * 1.42 / 72                          # 行高（英寸）
total = sum(l * line_h + 0.10 for l in lines)
# 从 14.5pt 往下试（14.5→9.5），第一档装得下就用它
```

逐条累加 y 坐标时要按**该条自己的估算行数**推进，不能按平均步长，否则长条会压住下一条。

**缩字号只是兜底**：真装不下就拆页或删冗余要点（见 SKILL.md 的拆页规则），不要靠 9pt 硬塞。

## 4. 封面别只放字

纯左对齐标题的封面会被评价为"未完成"——右侧大片空白。有效做法：左侧标题块 + 右侧 **2–3 个关键数字**（如 `14 个国家地区`、`6 大触达渠道`、`9 个月完成上线`），大字号纯白 + 小字浅蓝说明，数字之间用细线分隔且**线条数量要统一**（三条数字要么每条下都有线，要么都不放，少一条线会被一眼看出）。日期写清含义：`项目周期：2025.09 — 2026.10 ｜ 汇报日期：待定`，别只写一段年份区间让人猜。

副标题用**上线日期**，不用模糊的阶段描述：用户会把“从 0 到 1 上线报告”改成“`2026.10.23 上线报告`”。改标题时封面、页脚、文案 md 的首页三处一起换，并把文件名同步（交付物叫 `XXX-2026.10.23上线报告.pptx`）。

## 5. 渲染自检闭环（必做，别省）

```bash
soffice --headless --convert-to pdf 报告.pptx --outdir /tmp/pptqa
```

再用 pymupdf 把指定页导成 PNG，然后**用视觉工具逐页看**（重点挑最密的一页、表格页、封面）：

```python
import fitz
d = fitz.open('/tmp/pptqa/报告.pdf')
d[24].get_pixmap(dpi=110).save('/tmp/pptqa/p25.png')
```

检查项就四问：文字有没有溢出/截断？字号是否小到看不清？页脚是否被压？作为该受众的一页能不能接受？

常见反馈与对应改法：
- "信息密度过高、每页 6 条太多" → 拆页（进度类一页、缺口类一页）
- "首条与顶部摘要重复" → 删掉正文里和「核心一句话」同义的第一条
- "待补/关键状态没有视觉区分" → 灰色底/色块标注，别用加粗硬顶

## 6. 交付时同步给用户看什么

发文件的同时用文字说清：总页数、每页版式长什么样、**重点看哪几页**（矩阵页/能力全景/玩法页/OKR 页）、这一版还缺什么（真图表、品牌配色、待补数据）。用户可能
无法看图，别只发渲染截图了事——必须用文字复述画面。

## 7. 状态类页面：把「绿 / 黄 / 灰」真的画出来

通用卡片模板会把状态语义抹平——文案写成「公域触达（绿）」，渲染出来还是同一片浅色卡片，用户一眼就问"三色没标出来？"。**凡文案里出现颜色词或「已上线 / 在建 / 规划」三分，「不得走 content\_slide 通用模板，改用专门的矩阵渲染器。**

数据用结构化常量，不从 md 反解：

```python
MATRIX = [
    ("公域触达", [("已上线", "短信 v1.1.0；邮件/富媒体/WhatsApp 官方号 v1.3.0；…"),
                  ("在建", "全量计划可见（方案已定）；印度接入（暂缓）"),
                  ("规划", "—")]),
    # …每条业务线一格状态三元组
]
```

渲染要点：
1. **顶部图例**：三个色块 + 文字（已上线 / 在建 / 规划中·延后），别指望读者自己猜颜色。
2. **表头深色底白字**，行首业务线名用品牌浅色底加重，三列状态格用淡色底 + **左侧 0.045in 色条**（投影时色条比整片淡底更可辨）。
3. **颜色要够深**：绿 `#22A06B` / 黄 `#E89B00` / 灰 `#8C8C8C`；单元格淡底宁可深一档（`#DCF0E4` / `#FCEBCB` / `#E8E8E8`），太浅的底在投影或低亮屏幕上会被当成白底。
4. **空格子写「—」居中对齐**，不要留纯白——留白会被读成"这块没做"。
5. **页脚写判定口径**（绿＝已上线且至少一国在用；黄＝代码完成或在验收，未全量；灰＝只有方案、无排期）。没口径的三色图，评审时第一个被追问。**口径要跟着格子内容走**：灰格一旦填进 roadmap 的"11 月待定 / 12 月待定"这类项，页脚就不能再写"只有方案、无排期"，改成"已列入规划、排期待定（TBD）"——否则图和注解自相矛盾，比不写口径更减分。
6. 单元格文字按长度降字号（>60 字符用 9.5pt），全页只出现一个表格，不要再叠卡片。

另：文案里的「三条业务线」这类计数，要和表里的行数对一遍（四行就别写三条）——渲染前用代码数行数，不靠眼看。

## 8. 增删页与页码重排：按出现顺序全量重编，别用「减一」规则

用户会要求删掉整页（"这页意义不大，我会挨骂"）或把一页拆成两页。改完必须重排页码，否则页脚 `页码 / 总页数` 与 md 的 `## 第N页` 全部对不上。

**踩过的坑**：删掉第 21 页后，用 `n >= 22 → n-1` 逐页减一重排，结果原来的第 22 页变成 21，与后面仍标 21 的页撞号，输出里出现**两个「第21页」**；再修一次又撞。原因是「相对减一」假设了删掉的是最后一页，而实际删的是中间页。

**正确做法——按文档出现顺序全量重编号**（顺序即页码，永不撞号）：

```python
import re
counter = [0]
def renum(m):
    counter[0] += 1
    return '## 第%d页 · ' % counter[0]
s = re.sub(r'## 第\d+页 · ', renum, s)   # 计数器自增，顺序赋号
```

**删页本身也要防哑火**：按标题删除时用「页号 + 标题关键字」匹配，关键字取你记得的那几个字，很容易和实际标题不一致（想删「私域值多少钱」，实际标题是「私域对销量的贡献」→ 正则不命中、静默没删，后面又按错误页数重排）。删之前 `/^## 第21页/` 整段打出来看一眼标题，或用宽一点的关键字，删完立刻 grep 校验：

```bash
grep -E '^## 第[0-9]+页' 文案.md        # 页号必须连续、无重复
ls -la 输出.pptx                       # 再跑一次生成器
python3 -c "import fitz;d=fitz.open('/tmp/pptqa/x.pdf');print(d.page_count)"  # 页数要等于新总页数
```

三步都过再交付：**页号连续无重复 → 生成的 pptx 页数正确 → 页脚显示 N/N 与末页一致**。

**总页数变化会连带影响**：封面/目录页脚、后续所有页的 `页码 / 总页数`、以及任何写死的「共 N 页」表述；拆页后若超出受众上限（全员 ≤30 页），要先砍再拆，而不是拆完超了再回头砍。

**插页同样要重排，而且会打破生成器里的页码锚点**：在中间插入一整页（如新的「预售上线范围」页）后，全量重排只修好了 md，生成器里凡是按页码写死的特殊页渲染器会整体错位——`if num == 13: matrix_slide(...)` 在三色矩阵页被挤到第 14 页后，矩阵页会退回通用卡片模板、而普通的「底层支撑」页被渲染成矩阵。

规矩：**生成器里的特殊页一律不复用页码做键**。优先按页标题关键字匹配（`if "能力全景" in page["title"]`）；确实只能按页码时，插页后必须 `grep -n "if num ==" 生成器` 全部核一遍再重跑，并渲染该页确认没有串页。

## 9. 卡片式内页：小标题拆分别把日期/版本号劈断

把每条要点渲染成「小标题 + 正文」的卡片（浅色卡片 + 左侧色条）比纯项目符号更像企业汇报，但拆分小标题时有坑：

- 优先在 `｜`、`|`、`：`、`——`、`，` 处切，**全角竖线 `｜` 必须在内**（文案里写「第一阶段 2025.09 — 2026.03｜打底座」这种结构很常见）。
- 分隔符的**查找上限要给足（≥34 字符）**，且**超过上限仍找不到就整段当正文、不要硬切**：把 `split_lead()` 的兜底写成 `return "", text`（小标题留空、正文顶格），而不是 `text[:N], text[N:]`。硬切必然劈断长标题——`Q3 KR2「CMS 触达平台与私域导购工作台」进度 80%：…` 的分隔符在第 30 字，上限给 22 就会切出「…私域导购工作 / 台」进度 80%」，引号被拆两半、百分比掉到正文行，用户一眼看出是程序切的。日期、版本号同理（`2025.09—2` / `026.03`）。
- 卡片数量与行列：≤4 条用两行两列，5–8 条用两列多行；**最后一条若是「一句话总结/结论」这类收口句，改渲染成底部通栏色条**，否则它会被读成「第六个并列要点」。
- 卡片统一同色同尺寸，**不要给卡片加序号或深浅差异**——那会暗示优先级，而优先级往往还没跟业务确认（见 SKILL.md 全员汇报红线）。

渲染完抽查一张字最密的卡片页，看小标题是否成句、日期是否完整。

## 10. 架构图 / 分层图的具体几何（16:9，直接可用）

**分层图（栈）**：左侧固定宽 1.95in 的深色层名块（第一行 11pt 序号 + 第二行 12.5pt 层名，白字，`add_textbox` 两段代替 `\n` 才能各自控字号）；右侧浅色内容块 10.40in 宽，字号按内容长度降（<60 字 11.5pt / <90 字 10.5pt / 其余 9.5pt）。层高 0.80in、间距 0.11in，**间距里塞一枚 0.22×(gap-0.03) 的 `MSO_SHAPE.DOWN_ARROW`**（x 对齐层名块右侧），层次关系才立得住；底部留 0.56in 通栏总结条收口。

**每层内容必须拆成模块小方块，不能一行文字带过。** 「五条色带 + 每层一句用 `·` 分隔的长文本」读起来仍是分层清单，用户会直接问"这块做成架构图会不会更直观点"。正确形态是每个模块一个独立小方块（名称 + 可选副标签），**模块数本身就是信息**——渠道层摆 6 个方块，一眼就是"6 大渠道"；写成一行文字，读者得自己数。同层内按维度分色（如公域/私域两色），比加括号标注有效。

几何：层内 n 个方块等分，`gw = (内容区宽 - (n-1)×0.10) / n`；方块高 = 层高 − 0.18in；有副标签的方块上下两段（名 9pt 加粗 + 副标 8pt 浅色），无副标签的单行居中。参考公司内部同类报告的"能力中心 + 下挂模块"结构（每个中心下面挂具体能力），比自创分层样式更容易过评审。

**底部收口条不要取要点数组的第一条**：`bullets[0]` 往往是"整个系统分几层……"这种概述句，渲染出来和副标题重复、且换行成孤字。收口句要么写死成固定文案（"渠道决定能不能发到 / 活动决定发了有没有用 / 数据决定下次怎么发 / 底座决定能不能复制到下一个国家"），要么显式取最后一条结论句。条高 0.44in、字号 8.8pt 能装下四句并列。

**中心辐射架构图**：中心块 4.25×1.45in（品牌色，白字主名 15pt + 浅色副串 10.5pt），左列 4 个入口条（0.50in 高、0.62in 步进），右列 6 个渠道条（0.42in 高、0.52in 步进，最左侧 0.05in 色条 + 公域/私域两色小标签区分）。

**连接件**：`MSO_SHAPE.RIGHT_ARROW` 0.52×0.26in 夹在列与中心之间，箭头下方 8.5pt 写动词（访问 / 下发）；下方依赖行用 `rect(0.5, y, 12.35, 0.03)` 画总线，再用 `MSO_SHAPE.UP_ARROW` 0.26×0.86in 从总线顶接到中心块底部，旁标「调用」。

**依赖框横排等分**：7 个时宽 1.66in + 间隔 0.12in；框顶加一条 0.045in 深色条作视觉锚点；文字 9.5pt，长名（如「牛信 BSP（WhatsApp）」）允许换行。

**图页底部留一行 9pt 灰字写系统边界**（"CMS 负责配置/圈人/编排/报表；消息下发走 SMP；WhatsApp 经 BSP 接入 Meta；活动与卡券归悟空"）——这句话在评审里能挡掉"这些系统都是你们做的吗"。

自检：渲染后看三处——箭头是否真的连上了（不是悬空小色块）、左右两列条目数与文案承诺的渠道数/入口数是否一致、底部边界文字有没有被页脚压住。

**条目数对不上时，先怀疑重叠，而不是漏画。** 右列条数一多，纵向步进累加就会越过下方区块的起始 y，最后一两框被依赖行/总线整个盖住，渲染图上看就是"只有 5 个渠道"。而 PPT 文本结构里六条都在——只提取文本根本查不出来，必须靠渲染图数框。修法是压紧该列的框高与步进（如 6 条：高 0.30in、步进 0.352in、起点 1.78in → 末条底边 3.85in，卡在下区块 3.90in 之前），而不是删掉那条数据。

## 11. 把文字卡片升级成真图表 / 真截图

用户会逐轮提要求：先是"数字很混乱"，再是"三色没标出来"，然后是"加产品架构图"，最后一定是"这里应该有图"。骨架和文案都定稿后，剩下能给观感加分的只有两样：**真图表**和**真界面截图**。

### 11.1 图表页（最值得换的三类）

| 原文字页 | 换成 |
|:--|:--|
| 单期多来源对比（各渠道发送成功率 / 阅读率） | 簇状柱状图 |
| 内外销同期对比（按月） | 簇状柱状图，两组系列 |
| 季度进度趋势（70% → 73% → 85%） | 带数据标记的折线图 |

用 python-pptx 原生图表，不要自己画柱子：

```python
from pptx.chart.data import CategoryChartData
from pptx.enum.chart import XL_CHART_TYPE, XL_LEGEND_POSITION
cd = CategoryChartData()
cd.categories = ["4 月", "5 月", "6 月"]
cd.add_series("内销", (27.21, 26.18, 27.01))
cd.add_series("外销", (11.50, 15.32, 9.68))
gf = s.shapes.add_chart(XL_CHART_TYPE.COLUMN_CLUSTERED,
                        Inches(0.55), Inches(1.62), Inches(8.15), Inches(4.95), cd)
```

必设的七项（不设就一眼业余）：

1. `chart.has_title = True` + 图表标题 11pt 灰，写清**图表在说什么**（"富媒体短信阅读率：内销 vs 外销（2026 年 4—6 月）"）。
2. `legend.position = XL_LEGEND_POSITION.BOTTOM` 且 `legend.include_in_layout = False`（不加这句会挤掉绘图区）。
3. `plot.has_data_labels = True`，字号 9pt。
4. `data_labels.number_format` 必须显式给，三种情形别混：数值已是百分数想显示 `27.21%` → `'0.00"%"'`；数值已是百分数但不带号 → `'0.00'`；数值是整数百分比 70 要显示成 `70%` → `'0"%"'`。`number_format_is_linked = False`。**趋势图给 `'0.00'` 会显示成 70.00 而不是 70%**。
5. 网格线弱化：`value_axis.major_gridlines.format.line.color.rgb = RGBColor(0xE8,0xEB,0xF5)`。
6. 刻度与分类标签统一 9–10pt，否则投影偏小。
7. 图右侧留 3.75in 放 3–4 条要点（0.045in 色条 + 12pt 小标题 + 10pt 正文，步进 1.18in）——纯图无解释，评审会问"所以呢"。

图注/页脚补一句口径（"仅统计 CMS 数据"、"分母为 XX"）。缺口径的图，第一个被追问的不是排版而是数据。

### 11.2 真截图页（用户点名要 CMS / 手机端界面时）

**素材来源**：用户已经推过来的同类上线报告 PPTX 里就是真界面截图，比让他另外截图快得多；项目仓库里也常有成批现成截图（见 §16.2）。

**提取**：按 slide rels 抓 media；**必须排除每页都出现的那张图**（同一 filename 出现在几乎所有 slide、往往只有几 KB，是背景/logo 底板）——不排掉会把底板当截图放进 PPT：

```python
rels = f"ppt/slides/_rels/slide{num}.xml.rels"
imgs = [i for i in re.findall(r'Target="\.\./media/([^"]+)"', z.read(rels).decode())
        if i != SKIP]          # SKIP = 那个每页都出现的底板文件名
```

**选图与配文**：先按 slide 标题建映射（哪页讲什么功能 → 对应哪几张图），再对**要用的那几张用视觉核对一遍内容**，别只信标题——标题写"分享活动"，图里可能是别的东西。配文写"这一步解决什么"，不罗列界面字段。

**放几张**：一页 5 张足够。全员汇报看的是"这套东西长什么样、跑不跑得通"；把 20 张界面全铺上去就成操作手册，反而没人看。

**版式（16:9，实测不撞页脚）**：

- 左半页 **PC 截图**：宽 5.0in，按原图比例算高（PC 截图常见 1479×616 / 679 / 906，比例 2.2–2.4）。纵向叠两张，每张下面 0.03in 处放 9.5pt 灰字说明。
- 右半页 **手机竖图**：高 4.45in，按比例算宽（手机截图典型 738×1600，比例 0.46 → 宽约 2.05in），三张并排、步进 `w + 0.22`，从 x≈6.4 开始正好填满右半页。**两张会显得右轻左重，三张才平衡**。
- **y 坐标必须按每张图的实际高度推进**（`y += h + 0.38`），用固定步进会让第二张的说明文字直接压到页脚。

**渲染自检专看两处**：最后一张图的说明文字有没有被页脚遮住；左右两半的视觉重量是否接近（左重右轻是这批截图页最常见的返工点）。

### 11.3 几张并排时：先定统一高度，再算宽

**同排的截图必须等高**，否则下方说明文字的基线一高一低，视觉自检一眼指出「两图不等高、说明未对齐」。不要各图独立 `h = colw * ih / iw`（高度不同），而是**先反解出一个统一高度 H，宽度再按各自比例算**：

```python
colw = (12.35 - gap * (n - 1)) / n
H = max_h
for path, _ in shots:
    iw, ih = Image.open(path).size
    H = min(H, colw * ih / iw)      # 最宽的那张刚好填满列宽 = 全排唯一高度
for i, (path, cap) in enumerate(shots):
    iw, ih = Image.open(path).size
    w = H * iw / ih                 # 宽度按比例，各图不同但高度一致
    add_picture(path, x + (colw - w) / 2, top, w, H)
    txbox(x, top + H + 0.10, ...)   # 所有说明文字共用同一 y
```

**一页放几张**：2 张并排（列宽 ≈5.98in）是「图内小字还能认出结构」的实用上限；3 张（列宽 ≈3.95in）在投影上只剩色块，视觉自检会回「结构可辨、细节不可读」。**一页 3 张开外的第三张，实际是在牺牲前两张的可读性**。要更多截图就加页，别挤行数。

**截图自带白边不必裁**：实测按 `ImageChops` 裁非白外接框只能去掉 1–4%，因为 CMS 截图本身已经很紧凑。裁剪救不了尺寸，减列才救得了——别为了"放大一点"去做无意义的裁边。

**给一组卡片套外框时，`rect()` 只能画实心块**，直接传 `fill=None` 会 `ValueError: assigned value must be type RGBColor`。用**四条 0.022in 细矩形拼边框**（上下各一条横、左右各一条竖），标签块单独画一枚压在左上角：

```python
for (bx, by, bw, bh) in [(x0, y0, W, 0.022), (x0, y0+H, W, 0.022),
                         (x0, y0, 0.022, H), (x0+W, y0, 0.022, H)]:
    G.rect(s, bx, by, bw, bh, VIVO_D)
```

标签块要留出**恰好一个色条高度的间隙**再压线，贴太紧会被判"标签压住第一张卡"。

**页脚重编号通吃**：`pymupdf` 的新版本会为 `import fitz` 打 deprecated 警告，新脚本直接 `import pymupdf`。

## 12. 改稿验证：备份、逐页 diff、跨页引用

用户对脚本改稿有真实的恐惧（原话大意："我真怕你用脚本，改错了我揍你"）。每次重跑生成器前后做四件事，并把结果用文字报给他：

**① 改前备份，写明回滚点**

```bash
cp 报告.pptx 报告.pptx.bak-before-<改动名>
```

交付说明里点明"不满意随时回滚到这个文件"。

**② 改后逐页 diff——证明只有目标页变了**

```python
from pptx import Presentation
def titles(f):
    out = []
    for s in Presentation(f).slides:
        t = [sh.text_frame.text.strip().replace("\n", " / ")[:40] for sh in s.shapes
             if sh.has_text_frame and sh.text_frame.text.strip()]
        out.append(t[0] if t else "(无文字)")
    return out

old, new = titles("报告.pptx.bak-before-x"), titles("报告.pptx")
for i in range(max(len(old), len(new))):
    o = old[i] if i < len(old) else "—"
    n = new[i] if i < len(new) else "—"
    print(f"P{i+1:02d} | {o[:30]:30s} | {n[:30]:30s} | {'同' if o == n else '★变了'}")
```

预期结果要能一句话说清：「26 页相同、2 页改、1 页新增」。**说不清哪几页变了，就等于没验证。** 新增页会把它后面所有页整体顺移，diff 里表现为"从 P22 起全部变了"——这属于预期，报的时候写明「P23–P29 = 原 P22–P28 顺移」，别让他自己对着表猜。

**③ 正文里的跨页引用不会跟着重排**

`（明细见第 23 页）`、`详见第 N 页` 这类括号由人写的、不会随页码重排自动更新，插页/删页后必然指错。改完 `grep -n "第[0-9]*页" 文案.md` 逐条核。

**④ 被指向的内容若已移走，引用整个删掉**

某页原来列某组明细，改版后不列了，其他页的「明细见第 N 页」就成了死引用——宁可不写，也不留错指针。

## 13. 多列矩阵：先算宽度预算再落笔

N 列 × 单元格宽 + 行名列宽 + 右侧面板宽 必须落在页宽内（16:9 页宽 13.33in，常用可用区 12.35in）：

```
left + lab_w + N × cw  ≤  右侧面板起点 x
```

实测：13 列时 `0.52 + 1.30 + 13×0.545 = 8.91` 刚好卡住；加到第 14 列就必须压到 0.505（`0.52 + 1.30 + 14×0.505 = 8.87`，右侧面板从 9.62 起）。**不算就画，最后一两列会被右侧面板整个盖住**，渲染图上看是"少了两个国家"，而 PPT 文本结构里全在——只能靠渲染图数格子发现。

自检：渲染后数色块列数是否等于数据条数、表头国家名是否与色块逐列对齐。视觉工具问法要具体到"数一下矩阵上方一共有几个国家名，从左到右逐个列出，最后一个是不是 X"，泛问"有没有问题"它常常漏掉整列缺失。

## 14. 追加页：在已定稿的 pptx 上插页，而不是重跑生成器

**什么时候用**：md 与 deck 已经不同步——deck 在这之后又加过页（`## 第N页` 只有 26 段、deck 已经 29 页）。此时重跑生成器会把后来加的页全丢掉。用户说"加两页"时，正确做法是**在现有 pptx 上追加**，其余页一个字节都不碰。

```python
import sys; sys.path.insert(0, DIR)
import gen_ppt_brand as G          # 生成器有 __main__ 保护，import 不会重跑 main()
prs = Presentation(SRC)
# …用 G.txbox / G.rect / G.VIVO 等同款样式助手建新页…
prs.slides.add_slide(prs.slide_layouts[6])
```

`add_slide` 只能加到末尾，位置靠重排 sldIdLst：

```python
lst = prs.slides._sldIdLst
ids = list(lst); new = ids[-3:]; rest = ids[:-3]
order = rest[:5] + [new[0], new[1]] + rest[5:-1] + [new[2]] + rest[-1:]
for el in ids: lst.remove(el)
for el in order: lst.append(el)
```

**下标算错的唯一症状是页序静默错位——不报错**。本次 `rest[5:]` 写成 `rest[5:]` 而漏了 `[-1:]`，结果「未来三年」一口气跑到致谢页后面。加完必须逐页打印标题核对位置，别只看总页数对。

**页脚统一重写**（新页先传 `num=0` 占位，插完再重编号，不要在建页时猜序号）：

```python
import re
for i, sl in enumerate(prs.slides, 1):
    for sh in sl.shapes:
        if sh.has_text_frame and re.fullmatch(r"\d+\s*/\s*\d+", sh.text_frame.text.strip()):
            for p in sh.text_frame.paragraphs:
                for r in p.runs: r.text = f"{i} / {total}"
            break
```

**验证：逐页文本 MD5，证明老页一字未动**（页脚除外，它本来就要变）：

```python
def page_sig(s):
    parts = []
    for sh in s.shapes:
        if sh.has_text_frame:
            t = sh.text_frame.text.strip()
            if re.fullmatch(r"\d+\s*/\s*\d+", t): continue
            parts.append(t)
    return hashlib.md5("|".join(parts).encode()).hexdigest()[:10]

NEW_IDX = {5, 6, 30}                                   # 新页在新文件里的 0-based 下标
mapping = [i for i in range(len(n)) if i not in NEW_IDX]
bad = sum(1 for oi, ni in enumerate(mapping) if o[oi] != n[ni])
```

报给用户的话术固定成一句：「老 N 页一字未动（逐页 MD5 比对，改动 0 处）+ 页脚逐个校验错误 0」。这比任何解释都让他放心。

### 新页自身的两个版式坑（渲染图实测）

- **一页里混用 4 列和 3 列时，3 列那行必须重算宽度拉满**（`(12.35 - 2*0.17) / 3`），直接沿用 4 列的列宽会在右侧空出一列，视觉上左重右空。视觉自检会明确指出"右侧留白较大"。
- **卡片正文的灰别用 `#595959`**：9pt 灰在投影和低亮屏上被判"对比度偏弱"。正文统一 `#424242`，深色底上的辅助字提到 `#DCE2FF`。

## 15. 第二轮改造：改已有页（长文字图形化 / 数据精炼 / 目录重做）

第一轮是「加页」，第二轮是在同一份 deck 上**改写已有页**。做法不同，分节记录。

### 15.1 重建一页 = 清空重画，不要新建页再删旧页

```python
def clear(slide):
    for sh in list(slide.shapes):
        sh._element.getparent().remove(sh._element)

s = prs.slides[num - 1]
clear(s)
# …按新设计重画…
```

新建页再删旧页会让页码全乱，清空重画最稳。脚本名字体现轮次（`add_*_pages.py` → `polish_pages.py`），别把第二轮塞回第一轮脚本——第一轮的输入是它自己产出的那份，重跑会把第二轮覆盖掉。

**改页必须按标题定位，绝不用固定下标。** 上面那句 `prs.slides[num - 1]` 只在「deck 结构从此不变」时成立，而实际流程是反复的：第一轮加完页（3 页变 6 页）、第二轮再去改页，`num` 早已失效。**症状是静默的**——脚本不报错，只是把内容画到了别的页上，而原来那几页原封不动留在文件里，于是同一份 deck 里同时出现「新版已知问题」和「旧版已知问题」两个页面，页数也对不上（35 页而不是 32+3）。

```python
def find_slide(prs, keyword):
    """按标题关键词定位页面；插页后仍指向同一页"""
    for idx, sl in enumerate(prs.slides):
        for sh in sl.shapes:
            if sh.has_text_frame and sh.text_frame.text.strip().startswith(keyword):
                return idx
    raise SystemExit(f"找不到标题以「{keyword}」开头的页")

s = prs.slides[find_slide(prs, "和内销比")]
```

关键字取标题的**前几个字**（`startswith` 比 `in` 稳，正文里出现同名词不会误命中），找不到就 `raise`——**宁可炸掉也不要静默命中第 0 页**。改完先打印全部页标题核对一遍、再比对页数，别只看脚本退出码。

### 15.2 这一轮的验证目标变了：改动页集合 = 计划集合

第一轮证「老页一字未动」，第二轮本来就要改指定几页，验证的是**改动页恰好等于计划集合**：

```python
diff = [i + 1 for i in range(len(sa)) if sa[i] != sb[i]]
print('改动页:', diff)        # 期望 [2, 23, 24, 26, 28]；多一处少一处都要查
```

交付说明里把这句话写死：「这轮只动了 P02/P23/P24/P26/P28 五页，其余 27 页一字未动」。

### 15.3 「数据要精炼」＝ 先找重复页，再一页一结论

别急着合并页数——**先把几页正文并排读一遍，找讲同一件事的地方**。典型：一页写「内外销阅读率对比 + 外销内部渠道对比 + 发送成功率」，另一页写「9 个月累计四渠道对比」，两页都在说「渠道之间差 20 倍」。

改法：重复的那半内容**只留在最合适的一页**（累计规模页留渠道对比，对比页只留「和内销比 + 三个原因」）；每页收口成**一个结论**（顶部大数或底部结论条一句话），别一页塞三个结论。**页数可以不变**——「精炼」去掉的是重复，不是页数。

### 15.4 组合版式里手画柱子，必做三件事

原生图表（§11.1）是首选；但柱子要和侧栏原因卡、底部三列对比拼在一页时，手画 `rect` 反而好排。手画就得补上原生图表自带的东西：

1. **Y 轴刻度参考线**：`for v in (10,20,30): rect(x0, base_y - H*v/vmax, W, 0.008, #E6EAF5)` + 左对齐的 `10%` 小标。没有刻度的柱图，「比例准不准」只能靠柱顶数字自证。
2. **组标签对齐柱组中心**：一组两根柱时，组中心 = `gx + 柱宽/2 + 间距/2`，**不是 `gx`**。标签框写成 `txbox(gx - 0.33, ..., width=1.98, align=CENTER)`；直接写 `txbox(gx, ...)` 整组偏右，视觉自检一眼看出（「4月 标签明显偏右」）。
3. **结论里的倍数按逐月数据逐条核**：写「阅读率是它的 5 倍」前，每个月都除一遍（78.17/11.50=6.8、60.58/15.32=**4.0**、82.16/9.68=8.5）——最低那个月只有 4 倍，就得写「4—8 倍」而不是「5 倍以上」。**累计口径的倍数与单月口径的倍数常常不同，两处都要写明是哪一种**。

同理，量级类表述（「只有千分之几」）也要用分子分母算一遍再写，别凭手感。

### 15.5 CJK 跨行断词

9pt 中文在窄框里会被断在词中间（「30 日复购 / 转化率」「好 / 友状态」「导 / 购」）。缓解按性价比排序：

1. **加宽文本框**——`x + 0.16` / `w - 0.26` 比 `x + 0.22` / `w - 0.44` 明显更少断词
2. **降半号**（9.5 → 9，8.9 也行）
3. 仍断就把该行文案改短

不要为断词反复重排整页——它随字体/字号/框宽变化，交付时附一句「个别词跨行不顺，选中该文本框微调宽度即可」就够。

四列流程页的通用几何（16:9）：列宽 2.955in、列间距 0.17in；每列纵向三段——顶部字母/阶段条 0.82in（底色比卡片深一档 + 灰白小字）→ 中段说明卡 1.30in（浅底，首行 8pt 小标签 + 主名 11pt 加粗 + 说明 9pt）→ 下段"本产品在这里干什么"白底描边卡 1.62in。列间箭头放 `▸` 于顶部条垂直居中处，别放中段。

## 16. 素材定位：缩略图总览 + 项目内的截图仓库

### 16.1 在几十页材料里找「某张图在哪页」——先做缩略图总览

不要逐页渲染再逐页看（N 页 = N 次视觉调用）。把整份材料渲成**一张带页码的网格图**，一次看全：

```python
import pymupdf, io
from PIL import Image, ImageDraw
d = pymupdf.open('材料.pdf')
th = [Image.open(io.BytesIO(d[i].get_pixmap(dpi=42).tobytes("png"))).convert("RGB")
      for i in range(d.page_count)]
w, h = th[0].size; cols, rows = 6, 5
sheet = Image.new("RGB", (cols*w + (cols+1)*6, rows*h + (rows+1)*6), (235, 235, 235))
dr = ImageDraw.Draw(sheet)
for i, im in enumerate(th):
    c, r = i % cols, i // cols
    x, y = 6 + c*(w+6), 6 + r*(h+6)
    sheet.paste(im, (x, y)); dr.text((x+4, y+3), str(i+1), fill=(200, 0, 0))
sheet.save('sheet.png')
```

问视觉工具时**明确形状特征**（"像房子一样有屋顶 / 柱子 / 地基的图形"），并要它只回页码 + 判断依据。42 dpi 够辨认版式形态；认不出文字正是所要的——这一步只做粗筛。定位到候选后再按 150–170 dpi 单独渲染精看。

**总览会给假阳性**：形态相近的页（分层架构 vs 房子图）在缩略图阶段很容易混，候选页必须逐个高清复核再动手。

### 16.2 「多加系统截图」的料从哪来——先摸项目仓库，不要让他重新截

用户提"多加一些系统的截图，参考如下"时，**先按目录统计项目里已有的截图**：

```bash
find <repo> -path ./.git -prune -o \( -iname "*.png" -o -iname "*.jpg" -o -iname "*.jpeg" \) -print \
  | sed 's|/[^/]*$||' | sort | uniq -c | sort -rn | head -20
```

典型分布（截图往往成批躺着，不用另要）：

| 目录 | 内容 |
|:--|:--|
| `08-相关资料/产品审计/<模块>/验收截图/` | 该模块逐功能验收截图，文件名常带功能语义 |
| `08-相关资料/审计报告/截图/` | 功能审计 / 走查截图（菜单、报表、权限等） |

### 16.4 挑图先过一遍「有没有数据」，空态截图不上台

仓库里截图多，但**能用的是少数**：审计截图常在功能刚上线、没真实流量时拍的，主区是「查询无数据 / 暂无数据」或只有筛选区没有表格行；另有一批带人工标注框（红框 / 箭头 / 涂鸦）的，是内部走查用的。这两类放进汇报 PPT 都露怯——尤其空态截图，配文写着"触达量与效果一目了然"，图上却是空的。

筛法：把候选（15–20 张）拼成**带编号的缩略图总览**，一次交给视觉工具，问法要落到判定上：

> 逐张判断：这张有没有真实数据（表格有行、图表有柱子、指标卡有数字）？还是「暂无数据 / 空表格」？按编号明确回「有数据」或「无数据」，并一句话说明画面内容。

总览用 3 列 × N 行、每格 620×420，缩略图下方红字写 `编号. 文件名`（红字只作对照，别截进 PPT）。再顺手留意**长条形截图**（宽高比 >1.9 的整页长图）——它们和多图并排的版式互斥，见 §11.3。

选图与配文规则同 §11.2：按功能语义挑、用视觉核对内容、配文写"这一步解决什么"。

### 16.3 原图整张复用：只裁空白边，图形一个像素不动

上级说"直接用我之前那种 X 图，不要改动"时，交付形态是**把交付材料里那一页的图整块搬进新页**，不是照着重画。两件事要处理：裁掉纸张四周的空白边（图形本身不动），以及把同一页上方的说明文字块切掉（要的是图，不是那一页）。

- **渲染给 300 dpi**（不是粗筛用的 42 dpi）：图要铺满整页宽度，150 dpi 放大后小字发虚。
- **用 `ImageChops` 找非白外接框**，别逐像素判断——阈值放宽到 12 以上，避免把浅色底纹/极浅网格当成内容：

```python
from PIL import Image, ImageChops
bg = Image.new("RGB", im.size, (255, 255, 255))
diff = ImageChops.difference(im, bg).convert("L").point(lambda v: 255 if v > 12 else 0)
l, t, r, b = diff.getbbox()
crop = im.crop((max(0, l-14), max(0, t-14), min(im.width, r+14), min(im.height, b+14)))
```

- **切掉上方说明文字**：逐行统计该行有无墨迹，找连续 ≥30px 的全白行段，取**页面高度 12% 以下**的那个空白段之后的第一个墨迹行 = 图顶部。图与正文之间必有一条明显空白带，用它自动分界，不用手填 y 值。
- **放置时等比缩放**，别拉变形：宽高比算一次，`图比可用区更宽 → 以宽为准`、否则以高为准，然后水平垂直都居中。图形页顶部只留一行标题、不加副标题，把高度全让给图。
- 该页原有的手绘内容先 `clear(slide)` 清掉再贴图，标题/页脚套全篇统一样式。

裁完**反向核对完整性**：渲染出来问视觉工具"最上方的横条、最左侧那一栏、最右侧那一列红字是否都在、有没有被裁掉"。按外接框裁最怕切掉边缘的细描边和悬挂标点——**别自己看着觉得没问题就交付**。
