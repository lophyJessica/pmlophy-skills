# 表格/高亮截图读法（用户视障，读错一个名字就是把人搞错）

适用：用户发来一张**表格截图**（组织名单、对接人表、配置矩阵、价格表），中文小字 + 颜色高亮，用户自己看不到、无法核对。

## 铁律

1. **颜色归属用像素扫描定，人名才交给视觉模型**。不要问模型“哪些格子是高亮”——整张宽表下它的叙述会和像素事实不一致（实测把高亮说在另一行）。
2. **整张宽表一次识别只能拿表头，人名必错**（实测同一批人被读成：谢仲鹏→谢伟鹏、吴慧金→吴建金、郭梦琪→郭攀旗、刘晓婷→刘晓峰、汤琴琴→汤翠琴）。**一次识别的姓名绝不可直接写进交付物**。
3. **宽表（>3000px）在视觉链路里会被降采样**，先切半/切块再喂。
4. **和权威名单对不上时双写 + 进“待确认”**，不自己选一个当真——可能是我读错，也可能本来就是两拨人，只有用户能定。
5. **关键字符串（菜单名 / 步骤名 / 字段名 / 状态值）必须裁出该区域放大再读一次，整图一次识别的结果不得进结论**。曾用整图识别把步骤名读成「受众筛选」，而它实际是「受众圈选」——差一个字就是另一个词，用户会当场驳回。
6. **“给人看的字”和“代码里的值”要分开核**：渠道选项在界面是中文文案（邮件 / 短信 / 富媒体短信），在代码里是枚举（`EMAIL` / `SMS` / `SMART_SMS`）。比对两版界面时先把这两类列开，否则会把「枚举当文案」当成翻译/语言问题（实际是没取源码里的 label）。同理：按钮文案（`确定` vs `提交`）、弹窗标题（`新建触达计划` vs `请选择触达渠道`）都是高发差异点，逐字比。

## 步骤

**① 扫高亮格（像素，不靠模型）** —— 用 `execute_code`（PIL 已装；别用终端 `python3 -c`，会触发审批）：

```python
from PIL import Image
im = Image.open(path).convert("RGB"); w,h = im.size; px = im.load()
mask = [[False]*w for _ in range(h)]
for y in range(h):
    for x in range(w):
        r,g,b = px[x,y]
        if r>190 and g>170 and b<140 and (r-b)>60:   # 黄底
            mask[y][x] = True
# x 轴投影切列块 → 每个列块内 y 轴投影切行块 → 得到高亮单元格 bbox
```

- 阈值按底色调；换颜色先打印几个采样点。
- 采样坑：**落在文字笔画上的点会读成暗色**（黄底上的字是 `(147,141,0)`）——别用单点判断格子是否高亮，用整格像素计数。
- 行标签（如「代表」/「成员」）要**单独裁最左侧列放大 3x 读一次**，别假定高亮都在同一行。

**② 逐格裁 + 放大 4x + 拼成带红色编号 [1]~[n] 的一张图，再一次识别**：提问写死“这是 N 个单元格的放大拼图，格子有红色编号，**只读格子内的文字，不要推测**”。存新文件名防图片缓存。

**③ 表头行/各数据行各自裁条放大 3x 单独读一次**（太宽就左右切半各读一次）。

**④ 交付物里标清来源等级**：“高亮归属＝像素扫描（可靠）” ／ “姓名＝截图转录（可能有出入，以原表为准）”。

**⑤ 用户纠正后**：把正确的写法回填笔记，并把“待确认”收成一行“已确认”，别留垃圾条目。

## 跨来源比对：词不同 ≠ 版本不同

拿同一系统的两处证据对比（例如我们的复刻原型 vs 真系统截图）时，发现同一个位置的用词不同，**先确认这是“命名差异”还是“版本分叉”**，别默认后者。曾把「原型叫受众圈选、真系统叫受众筛选」误报成“两边不是同一版本”，被用户纠正——实际是同一版本的两个来源用了两个词（原型自己的叫法 vs 生产端叫法）。

正确做法：① 先分别校好每个来源自己用的词（裁区域放大读，见铁律 5）；② 再判断是命名不一致还是真的两套东西；③ 报给用户时把两类分开说（“用词不同” / “结构不同”），别混成一句“对不上”。

## 其他教训

用户自己更新笔记时把三条待确认全勾了，并指出“名字对不上是你识别的不准”——**用户的判断优先于我三次 OCR 一致的结果**：三次一致≠正确，只是同一个模型犯同一个错。
