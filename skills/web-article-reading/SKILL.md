# 读取用户发来的网页/文章

> 用户（PM）经常丢链接过来（微信公众号、技术文章、产品评测），要"看看/总结/有没有合适场景/有没有价值"。这是高频任务类。本 skill 记录**可靠的抓取路径**和**踩过的坑**。

## 触发场景
- 用户消息里出现一个 URL（`mp.weixin.qq.com/s/...`、博客、公众号等），配合"看看/搜搜/分析下/对我有没有价值/有没有合适场景"。
- 用户发来**截图/图片**（消息里带 `[Image]` 标记 + `识别下/你看下/这个是什么`）——走下面的"截图/图片输入"章节。

## 抓取路径（按优先级）

### 0. 用户只发了一个标题，没有 URL

飞书会把富文本超链接的 href 剥掉，只把**标题文字**传给我——用户那边看是带链接的，我这边只是一行标题。**不要回问「你发的是链接吗」**，白一轮（他会回「是一个链接啊」）。

直接用标题 `web_search` 找回原文，再从结果里挑一个能整篇读完的站点 `web_extract`。中文文章常能同时搜到多个镜像（人人都是产品经理 / 网易 / 腾讯新闻 / 各类同步站），优先挑正文完整、广告少的那个；公众号原文反而常被反爬截断。

### 1. web_extract（首选——快、无浏览器）
```
web_extract(urls=["<URL>"])
```
- 微信文章常只返回一小段（反爬），若太短或为空 → 进 2。
- 若报 `Web tools are not configured. Set FIRECRAWL_API_KEY...`（Firecrawl 未配置的环境）→ **直接进 2**，别反复试 web 工具。

### 2. curl 移动端 UA 兜底（本会话实测可用）
```bash
timeout 35 curl -sL -m 25 \
  -A "Mozilla/5.0 (iPhone; CPU iPhone OS 16_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/16.0 Mobile/15E148 Safari/604.1" \
  "<URL>" -o /tmp/wx.html
```
- **用移动端 Safari UA**——桌面 UA 更容易拿到残缺/拦截页。成功时文件 3MB 量级。

### 3. 从 HTML 里定位正文（不用 python！）
```bash
# 标题
search_files(pattern='og:title', path='/tmp/wx.html')      # → 拿到文章标题
# 正文容器
search_files(pattern='id="js_content"', path='/tmp/wx.html')  # → 拿到起始行号
# 读那一行（微信正文挤在同一个巨行里）
read_file(path='/tmp/wx.html', offset=<该行号>, limit=1)
```

## 坑（实测）

- **绝不用 python heredoc / `python3 -c` 解析抓到的 HTML**：会触发 Hermes 命令审批，飞书端常点不到批准按钮 → 命令 `BLOCKED` 超时（本会话连续踩 2 次、白烧 2 轮）。用 `search_files` + `read_file` + `grep` 即可完成抽取。
- **微信正文全在单个超长行里**：`js_content` 那个 div 的整篇内容在同一行（如第 3747 行），`read_file` 读该行仍会在中段截断。需要具体段落时，用 `search_files` 按关键词在该文件里定位。
- **抓回来的是 HTML 混排文本**（标签密）——是原始素材，不是成品，需自己提炼。
- **web_search 未配置时别当"工具坏了"**：只要没有 Firecrawl key，web_search/web_extract 就不可用——这是环境配置问题（可在需要时配 FIRECRAWL_API_KEY），不是永久故障；当下用上面的 curl 路径绕开即可。
- **带登录态的设计工具链接（`figma.com/design/...` 这类）抓不到内容，别反复换工具试。** `web_extract` 实际返回的是 Figma 官网营销落地页（「The full-stack creative canvas」之类），设计稿一个字没有——设计文件要账号 + 文件权限，跟反爬无关，换 UA 也绕不过。看到这类链接直接说「读不到，需要你截图或导出」，并问一句他要你拿这份设计稿做什么（评审流程 / 落 PRD / 复刻原型）；同类的还有公司内网设计稿、语雀私有空间、Axure 分享页。别拿「设计稿我看过了」含糊过去。

## 截图/图片输入（用户说"识别下这个/你看下这张"）

用户视障，经常**转发截图**当输入（别的 AI 或搜索引擎的回答、后台界面、聊天记录、报错页）。处理顺序：

1. **先 `vision_analyze(image_url=<消息里那张图的本地路径>)` 逐字提取**，不要凭缩略描述或"看起来像"作答。提问直接要求"逐字识别所有文字（标题/正文/表格/型号对比/底部说明）+ 说明是什么界面"。
2. **判断这是什么来源**——截图里带 `X +1`、`来源：xxx` 这类**引用角标**就是**搜索引擎/AI 生成的二手答案**，不是官方一手材料。汇报时必须把"它是别人 AI 的回答"讲清楚。
3. **二手来源的结论一律标注未核实**，绝不直接当事实转述；有条件时用 web_search/web_extract 核官方口径，**核不动就明说"未经核实/联网工具当前不可用"**，不要用记忆里的印象替它背书。
4. **汇报形态**：先给一句这是什么，再结构化复述内容（视障用户靠文字"看"图，标题/列表层级都要写出来），最后分行列出核实状态。不要复述一遍就说"看到了"。

**表格截图（名单 / 对接人表 / 配置矩阵，尤其中文小字 + 颜色高亮）另走一套方法**：颜色归属用**像素扫描**定（PIL 扫高亮色 → x/y 投影切出单元格 bbox），人名才交给视觉模型，且要**逐格裁 + 放大 4x + 拼成带编号的一张图**再一次识别——**整张宽表一次识别出来的姓名必错**（三字姓名会被同形近字换掉）。**一次识别的姓名绝不可写进交付物**：要么与权威名单（任命书 / 通讯录）交叉核对，要么明写"截图为转录、可能与原表有出入"并进待确认。用户指出读错时，**以用户为准**——同一个模型连读三遍一致也不等于对，只是同一个错犯三次。完整步骤、色阈值与踩坑见 `references/table-screenshot-ocr.md`。

**禁默态控件在截图里与可填态同形，可填性判断只认源码**：占位符「请输入X」、必填红星、红框报错在禁用态照常呈现，而「悬停显示禁止符号」这类提示根本不进画面——截图识别说「可填/必填报错」不等于真能填。判可填性先查源码的 disabled/readonly 属性，或让用户在实机上悬停确认；视觉结论与源码结论冲突时，不要上报成「两种态」或「版本不一致」（曾按矛盾上报，被用户当场纠正「是截图软件截不出来禁止样式」）。

**表格截图还有其他字段对不上时，先分清哪边是权威**：截图里的行列标签（如"代表/成员"）不等于用户关心的口径，用户一句"不用管这两行，只看黄底的"就该把口径收窄，别自己继续推演层级的优先级。

## 汇报口径（用户偏好，别踩）
- 抓完**先给一句话结论/判断**，不要长篇复述原文——用户要的是"这跟我有没有关系/有没有价值"，不是摘抄。
- 用户说"**对我没价值/不用分析了**"就是让你**停**，别再硬展开分析（本会话实测被这句叫停两次）。
- 用户问"**有没有合适的场景**"这类，是要你落到他的实际工作场景做判断（如 CMS/导购 H5），不是泛泛概括文章。
- 内容跟用户无关时（如纯 3D/Blender 教程对他 CMS 工作无价值），直接说"对你没价值，不分析了"，省 token。
