# 项目入职/接盘速通工作流

## 触发条件
- 用户入职新公司,拿到全套项目文档
- 用户接手前 PM 遗留的项目(有文档+代码但没有交互/PRD)
- 用户说"帮我分析这个项目""明天入职""前 PM 留下的文档"

## 三步法

### 1. 文档并行消化(不撑爆上下文)

用 `delegate_task` 派 3 个子 Agent 并行读文档——原文不进主会话:

```
任务A: 立项申请书(项目目标/范围/干系人/经费)
任务B: 需求说明书(业务调研/痛点/用户角色/流程)
任务C: 设计说明书(数据层/算法层/API/页面设计)
```

每个子 Agent 输出 500 字中文摘要。合集不进原文,只进精华。

### 2. 产出 AGENTS.md

基于消化结果创建 `AGENTS.md`,必须包含:

- 项目简介(一句话)
- 核心规范(输出语言/设计原则)
- 系统边界(SSOT 分布——哪些数据是本系统的,哪些是外部的)
- 用户角色(来自需求文档,非自创)
- 关键术语表(库存事实/补货建议/前馈信息/解释链等)
- AI 串联层(输入→处理→输出)
- 约束(NIS: Not In Scope)
- 当前待办(入职第一周的具体任务)
- **不包含:** 页面对照表、代码路径索引(这些代码里的,不是AGENTS的)

路径:`/root/notes/projects/<项目名>/AGENTS.md`

### 3. 识别产品缺口

对比"需求文档说的"vs"实际项目有什么":

| 检查项 | 来源 |
|--------|------|
| PRD 存在吗 | 搜项目目录找 PRD/product/产品需求 文件 |
| 交互原型存在吗 | 搜 .html/.fig/.sketch |
| 用户流程图存在吗 | 搜 mermaid/flowchart/sequenceDiagram |
| 功能清单(用户视角)存在吗 | vs 47 个 REQ(技术视角)的区别 |
| SPD/接口对接完成度 | 读 integration 目录的差异报告 |

**常见缺口:** 前 PM 写了需求说明书+设计说明书,但没写 PRD、没画交互图、没做用户流程图。这是你入职后的产出空间。

## 不该做的

- 不要把原文全文读进主会话(沉)
- 不要在没有官方文档支持的情况下猜测 Hermes 功能
- 不要在没有代码的情况下宣称"页面已完成"

## 老系统全项目摸清（接手已有系统，非文档消化）

接手**整个已有系统**（页面还活着但资料零碎/无 PRD）时，用 **Cursor 内置浏览器**（唯一可用：Codex 不行、ego 是 Mac 本地装不了 Windows）一次性跑完地图→页面→整理三阶段，产出能写 PRD 的结构化材料。完整单提示词结构/只读边界/防跑飞/账号租户上下文见 `references/ai-browser-legacy-takeover.md`。

**复刻已有系统前端到本地 React 项目迭代设计**（不是摸底阅读，是把 CMS/已有 UI fork 到本地当"研究基地"套方法论改）见 `references/ai-fork-existing-ui-to-project.md`——含 React 版复刻提示词 + 合规边界先行的纪律 + "先复刻 1-2 页跑通"防风格漂移。

**可直接发出去的复刻提示词（Cursor 内置浏览器，两版模板）**见 `references/native-html-clone-prompt.md`。发之前先定两件事，定错就是整轮白跑：

1. **产物落点决定技术栈**。进现有原型工程就用 React 版并沿用工程既有栈；独立复刻件才用原生 HTML 版。照搬来源模板的技术约束（"只用原生 HTML、禁 React 与构建工具"）而产物要进 React 工程，两个要求当场对立；**不要在结尾把"这条好像不对"当问题推给用户，发之前就按目标工程的 package.json 与路由改掉**。
2. **浏览器写"唯一允许项 + 禁用清单"**。只写"用 Cursor 内置浏览器"不够，必须同时禁 ego lite / Playwright / Puppeteer / 浏览器插件，否则 agent 去装替代品，一轮时间全花在配环境上。
