# Test Desktop App

真实端到端验证一个打包好的桌面应用——**跑通才算数**，不是 build 通过就行。

## 用途 / 阶段

- 用途：把应用真正跑起来，模拟真实操作走完整流程，验证各环节真的通
- 阶段：打包之后、交付/部署前；或改了核心流程后
- 调用：`/test-desktop-app`（针对当前打包的应用）

## 执行步骤

1. **启动应用**：用项目对应的启动命令（`npm run dev` / `npm run build && 启动产物` / 直接打开打包好的可执行文件），确认应用能起来、窗口正常。
2. **走真实完整流程**：按核心业务路径操作——例如"登录 → 创建 → 操作 → 保存 → 重启后数据还在"。不要只点开看，要真正走通。
3. **验证每个环节真的通**：
   - 按钮点击有响应（不是点了没反应）
   - 状态正确流转（能到达目标态）
   - 数据真的持久化（重启后数据还在，不是只在内存里）
   - 关键页面/功能可达
4. **发现问题 → 记录 → 修复**：报出具体现象（哪一步、什么表现、期望 vs 实际），然后修，修完重测直到全通。

## 验证标准（"真的通"才算数）

- [ ] 应用能启动，窗口正常
- [ ] 核心流程完整走通（登录→核心操作→保存）
- [ ] 重启后数据/状态持久化
- [ ] 无"点了没反应"的按钮 / 无空白页 / 无报错

> 本质：和"实测才算数 / 浏览器验收"的铁律一致——**跑通才算数**。

## Gotchas

- 某些桌面 App 需要真实用户交互（点击/输入），用自动化工具驱动时注意窗口焦点和权限
- Electron 类应用可通过 DevTools Protocol 调试驱动（见各项目具体说明），但目标是"走通流程"，不是"能自动化"就完事
- 验证持久化时，务必**关闭并重启应用**再检查，不要只看运行中的内存态
