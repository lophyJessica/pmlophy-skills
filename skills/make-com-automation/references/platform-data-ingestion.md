# Make 平台数据接入参考

## 判断框架

回答“Make 能不能联网/采集网页/采集自媒体评论”时，先区分：

1. Make 的 HTTP 能力：能向指定 URL 发请求、接收响应、解析数据。
2. 目标平台能力：是否提供公开 API、需要什么资质、是否需要 OAuth、是否有审核。
3. 页面形态：静态 HTML、JavaScript 动态渲染、登录态、验证码、WAF/反爬。

HTTP 模块不是完整浏览器，不应承诺绕过登录、验证码、WAF 或动态渲染。

## 当前查证结论（2026-08-21）

### 公开网页/API

可以用 HTTP GET 读取公开、可直接返回内容的网页或 API；动态渲染网页需要网页采集服务/API或人工输入。

### 抖音评论

抖音开放平台存在“视频评论管理接入方案”，用途包括后台接入抖音账号的实时视频评论、统一查阅、批量获取和评论管理。实际接入仍需核验：

- 开发者/企业主体资质；
- 开放平台应用创建与审核；
- 评论相关接口权限；
- OAuth 授权目标抖音账号；
- API 的具体数据范围、频率和合规要求。

不能仅凭视频链接直接读取评论。满足官方接入条件后，才考虑 Make HTTP 调用官方 API。

官方入口：
- https://open.douyin.com/platform/resource/docs/ability/interaction-management/video-comment-management-solution

### 视频号评论

不要默认存在可自由读取任意视频号评论的公开 API。查到的官方视频号开放能力主要覆盖主页、直播、关联小程序、交易等场景，不能据此推导评论读取权限。

当前更稳妥的 MVP：

```text
人工从视频号后台查看/导出评论
→ 粘贴或上传到飞书/网页表单
→ Make 读取
→ DeepSeek 分析
→ 飞书结果表
```

## 推荐 MVP

先用半自动闭环验证内容价值：

```text
人工收集网页/评论/对标数据
→ 飞书或 VPS 表单输入
→ Make 读取
→ AI 分析
→ 飞书结果表
```

验证结果有价值后，再逐个平台申请官方能力并接入，不要一开始承诺“全平台自动采集”。
