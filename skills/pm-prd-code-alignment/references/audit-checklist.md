# 前端审计检查清单

## 逐页检查项

### 列表页

- [ ] 状态 Tab 数量与枚举是否与 PRD 一致
- [ ] Tab 计数逻辑是否正确（反映筛选项叠加结果）
- [ ] 状态筛选与 Tab 互斥逻辑（选具体状态 Tab 时隐藏状态下拉）
- [ ] 查询条件数量与类型是否与 Demo PRD 一致
- [ ] 展开/收起是否有遗漏的筛选条件
- [ ] 工具条按钮是否超出 Scope（如导入、批量删除等）
- [ ] 表格列定义是否与 Demo PRD §列定义对齐
- [ ] 状态 Tag 配色是否与 Demo PRD §配色表对齐
- [ ] 行内操作按钮是否按状态动态展示
- [ ] 操作按钮是否有不该出现的（disabled 按钮应不渲染）
- [ ] 分页默认值是否正确
- [ ] 空状态展示是否符合规格

### 表单页（新增/编辑）

- [ ] 页面标题是否区分新增/编辑模式
- [ ] 字段控件类型是否与 Demo PRD 一致
- [ ] 编辑模式是否区分草稿态和审核后锁定态
- [ ] 锁定字段是否正确（供应商/仓库/数量/单价锁定，备注/到货日期可编辑）
- [ ] 商品明细行列定义是否与字段清单一致
- [ ] 商品选择弹窗参数是否正确
- [ ] 汇总行计算是否正确
- [ ] 校验规则是否全覆盖（必填、未来日期、数量>0、至少1行、最多50行）
- [ ] "保存"vs"保存并提交"的校验宽松度是否区分
- [ ] 底部操作栏按钮顺序是否正确

### 详情页

- [ ] 页头操作按钮是否按状态矩阵动态展示
- [ ] 按钮是否有多余的（如已完成状态出现"编辑"）
- [ ] 基本信息卡片字段是否只读
- [ ] 商品明细列是否按状态显隐（累计已入库/未入库）
- [ ] 关联单据卡片是否按状态显隐
- [ ] 制单信息卡片是否固定置底
- [ ] 二次确认弹窗文案是否与 Demo PRD 一致
- [ ] 确认按钮文案是否按操作类型映射

## 跨页面检查

- [ ] 状态流转在各页面是否一致
- [ ] 状态配色在各页面是否统一
- [ ] 字段来源是否可追溯（如累计已入库来自 PI 回写）
- [ ] 计算字段是否正确（金额=数量×单价，未入库=采购量-累计入库）

## 实战案例：采购订单审计

### 背景

强盛科技进销存系统，React + TypeScript + Tailwind，5 个页面（列表/新增编辑/详情/导入/导出）。

### 审计发现（13项）

**阻断（4项）：**
1. 状态标签配色全错（待审核=蓝→橙，待入库=琥珀→蓝，部分入库=橙→浅蓝）
2. 导入按钮超出 Scope（主PRD Out of Scope 明确"批量导入创建一期不支持"）
3. 列表页缺少"商品种数"列
4. 展开区缺少"最后修改时间"筛选

**中等（6项）：**
5. 列表行内操作不完整（缺少提交审核/删除/审核/驳回/创建入库单/关闭订单）
6. 详情页确认弹窗按钮文案统一写死"确定操作"
7. 关闭订单未检查草稿入库单（PRD R44）
8. 默认分页10条应为20条
9. 详情页多了未在 Demo PRD 中的"状态时间线"组件
10. 供应商/仓库展示格式不一致

**低（3项）：**
11. 查询区用原生 select 代替 SelectWithSearch（Demo 简化可接受）
12. 汇总行格式措辞微差
13. Mock 供应商前缀 SUP vs Demo 要求的 VEND

### 三向对齐结果

context/04（功能清单）+ context/06（业务流程）+ context/07（项目边界）→ PRD 主文档 → 前端代码：

- 三口径数量分离 ✅
- 超收强控拦截 ✅
- 快照存储 ✅
- 关闭≠作废 ✅
- 两层单据架构 ✅
- 审核后字段锁定 ✅
- 按钮驱动状态变更 ✅
- 导入按钮违规 🔴

### 修复指令

分两轮输出给 Antigravity，用五段式模板。第一轮 6 项（阻断+关键中等），第二轮 4 项（收尾）。
