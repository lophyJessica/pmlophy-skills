# 追一条取数链路：从页面字段到数据来源

用于「这个字段到底从哪来、怎么进来的」这类核实（PRD/口径写了数据来源，要用代码坐实或推翻）。目标是把「取数机制」拆成可验证的几段，而不是笼统地答一句「来自服务端数据库」。

## 追链顺序（逐段收窄，每段都要落 文件:行号）

1. 前端页面 → 它在查什么接口：页面 `.vue/.tsx` 里找 api import 与请求调用，再进 `api/**` 拿完整路径与方法。
2. 接口 → 哪个服务承接：路径前缀先对服务（如 `/admin/web/api` 对 BFF，`/employee/web` 对领域服务）。**根目录 grep 常因中文路径或权限返回 0 命中，不要当成不存在**——下钻到具体子目录、换查找方式交叉验证（Glob / PowerShell Select-String / ripgrep 交替用）。
3. BFF Controller → Service → Dubbo Facade：顺着调用取到真正查数据的那层，记下是查 ES、查 MySQL 还是查 OB（同一列表不同字段可能分别走三套存储）。
4. 返回 VO/DTO：**口径里列的字段，要在 VO 里逐个点名核对**。口径写了十列而 VO 只有十一字段时，缺的那几列往往正是「本期新增」——见下节判断顺序。
5. 写入方是谁：按机制分四类，逐类找证据——外部回调（找回调 Controller + 事件枚举 + MQ 生产者/消费者）、运营导入（找导入接口与失败明细表）、定时任务（找 `@Task`/scheduler 类，频率常在代码外）、查询时回填（找 fill/补全方法）。
6. 定时任务的频率与重试：任务类里没有 cron 就写「代码内未找到，需在调度管理台查」，**不猜数值**；MQ 消费端没 try-catch/死信代码就如实写「框架层处理，配置未见」。

## 判「口径不一致」之前，先分清这一列是哪一类

**拿存量源码去校本期口径，最常见的假不一致是：口径写的是本期目标态，源码是存量现状。** 判断顺序固定：

1. 这一列/这个功能，PRD 或需求稿里明确写成「本期新增 / 本期新增展示列 / 本期新建功能」了吗？写了 → 源码里没有是**预期结果**，不能判不一致。
2. 它是存量页面本来就有、只改了取数口径吗？→ 才拿源码判对错。
3. 拿不准就写成「存量无此能力、本期新增，数据源在 X，实现待开发」，三条都写清，不要二选一。

配套判据：去评审 PRD 的功能清单与页面说明里搜这个字段/功能的编号，有编号且带「新增/补/恢复」字样即为本期新增。先查证再判，否则会把整张对照表判反。

## 数据进 CMS 的方式要分开写，不能合并成一句

同一个列表里，不同列的数据进入方式常不同：回调推送（外部系统推给 CMS）、运营导入（人工上传写库）、查询时回填（按关联表补值）、内部对齐任务（库与索引之间同步）。口径只写「由服务端数据库提供」或「定时任务同步」会掩盖真实机制，而机制错了会直接影响新鲜度解释、延迟归因和开发实现。写成「按字段区分」的一段话，比写机制名更可靠。

「数据同步时间」这类字段要额外确认三点：它挂在行还是账号维度、值是事件时间戳还是作业执行时间、账号维度没有该字段时用什么取。

## 分阶段指令模板（给只能读代码的 agent）

三阶段，每阶段结束必须停：

1. 阶段一定位：接口、服务、表/索引、任务入口，交付一张定位表（模块｜文件与行号｜作用｜置信度），置信度分「有代码证据」「仅命名推断」。
2. 阶段二追链路：交付触发机制表（机制｜服务｜触发方式｜频率｜涉及表｜失败重试与幂等｜证据位置）+ 字段来源表（字段｜行归属｜来源系统｜来源表或接口｜写入的表或索引｜同步时机｜证据位置）。
3. 阶段三出报告与口径替换草稿：报告含结论摘要、定位与两张表、与既有口径逐条对照（一致/不一致/无法核实）、差异边界表（本期新增项与开发待补动作）、待拍板清单。

红线写成固定几条：只读不改源码、不动文档仓库、不猜（找不到写「未找到」、不确定写「待确认」）、不做全库索引（按关键词定位）、不连生产库、范围不扩到相邻模块。

**报告属产出物，指令里要同时给它归档路径并写明「不列入临时清理范围」**——项目里若已有「临时文件收尾前必须删除」的规则，不点名的报告会被一起清掉。

## 验收 agent 交回的东西

- 逐条看它的「不一致」结论，凡是涉及新增列/新增功能的，回到 PRD 核一次是本期还是存量（这是最省返工的一步）。
- 看它有没有把「没搜到」写成「不存在」——中文路径 grep 假阴性高发，要求交叉验证过再下结论。
- 看它标「代码内未找到」的项有没有被悄悄补成具体数值或频率。
- 最后核报告文件是否真在你手里：拿不到就让它把关键节贴出来，**不要把「已生成 + MD5 通过」当成验收**。
