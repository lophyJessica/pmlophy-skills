# Markdown 文档交付到 wiki 平台

## 适用场景

文档本身是 Markdown（评审 PRD、方案、审计报告），但要**粘/导入到公司 wiki**（Confluence、语雀、飞书文档）给别人看。本地渲染正常 ≠ 粘过去正常，平台能力差异是必踩的一关。

用户对这类交付的硬要求：**文档必须保持 Markdown 形态，因为要回写维护**。不要拿「转 HTML 再粘」当解法——转完就回不去了。

## 第一步永远是验平台，不是改文档

粘贴效果不对时，先分清是「平台不认这个语法」还是「文档写法有问题」。按这个顺序逐层问一遍，一层就能定性：

1. 标题（`#`）认不认？
2. 表格（`|...|`）认不认？
3. 列表（`1.` / `-`）认不认？
4. 只有换行不生效？

- 前三者都认、只输在换行 → 结构问题，按下面「页面说明的多行换行」改。
- 连标题都不认 → 跟文档内容无关，问题在粘贴方式：粘成了纯文本，或平台根本不支持直粘 MD（要它自带的 Markdown 宏 / `插入 > 标记`）。

**动手重排前，先单独粘一段两行小表做最小验证**（带 `<br>` 和不带的各一段）。几分钟就能确认平台行为，跳过这步直接按「平台肯定不认」重排全文，可能白改一遍。

## 页面说明的多行换行

常见写法是靠 `<br>` 在一个单元格里分行：`【页面内容】<br>1) xxx<br>2) xxx`。这在 VS Code / GitHub / Typora 预览里正常（支持内联 HTML），**但 Confluence 会把 `<br>` 当普通字符过滤掉，整块挤成一段**。

别指望换别的标签绕过去：Markdown 表格单元格是**内联上下文**，列表是块级元素，`1. xxx` 写进单元格也不会渲染成列表项。两条路都堵。

### 正确形态：每页两张表

```
| 序号 | 操作路径/功能点 | 原型页面 | 备注 |          ← 主表，一页一行，只这里放图
|---|---|---|---|
| 1 | 触达计划 > 配置管理 > 用户行为-行为列表 | ![](data:image/png;base64,...) | |

| 分段 | 内容 |                                     ← 说明表，一条说明一行
|---|---|
| 页面内容 | 列表展示行为ID、行为名称、行为编码、数据源表、用户标识、属性数、状态、更新时间和操作 |
| 页面内容 | 顶部提供行为名称搜索框与状态筛选，右侧提供新建行为按钮 |
| 交互说明 | 按名称搜索为模糊匹配 |
```

要点：

- 每条说明**单独占一个表格行**，单元格里不换行，也就不依赖任何标签。
- 分段名**每行都重复写，不要留空**——MD 表格做不了合并单元格，留空就认不出这行属于哪个段。
- 主表只有一页一行、只在这里放图；说明表只有「分段 / 内容」两列，不放图。
- 页面有多个说明块（同一页列表态/弹窗/权限控制各一块）时，主表出多行，每块后面紧跟它自己的说明表。
- 代价是文档变长、分段名重复。宁可啰嗦，不要挤成一段——用户判据是「很乱很乱」。

### 什么情况下不要拆

拆分前先确认平台真的不认。有些平台（语雀较新版本、部分 Confluence 宏模式）是认 `<br>` 的。**先验再拆**，能保留表格原形态就保留——原形态改动小、和仓库里那份主 PRD 结构一致，维护成本低。

## 图片必须 base64 内嵌

相对路径 `![](./images/x.png)` 粘到 wiki 一定显示不出来（本地路径对方拿不到）。交付版本必须走 base64：

- 用项目里的 `09-脚本工具/embed_images.py` 或同类脚本，把 `![](./images/x.png)` 替换成 `![](data:image/png;base64,...)`。
- 交付文件名固定为 `<原名>-发布版.md` 或 `<原名>-发布版-confluence.md`，跟仓库里的引用版区分开。
- base64 版体积会大很多（几十张图能到几 MB），这是正常的，不要为此压缩图片质量。
- 本地渲染时 base64 不一定显示成图片（编辑器不内联渲染 data URI），用浏览器打开或直接看代码结构核对，不要据此判断转换失败。

## 转换完的自检项

改完结构后逐条核，缺一项都可能带着断链交付：

1. 搜 `<br>` → 必须为 0（如果平台不认）。
2. 搜 `./images/` → 必须为 0（全换成 base64）。
3. 源文件和产出文件的**图片数**必须相等。
4. 源文件和产出文件的**章节标题数**必须相等。
5. 说明表里每一行都有分段名，不能出现空分段单元格。

## 已知平台行为

| 平台 | MD 标题/表格/列表 | `<br>` | 备注 |
|---|---|---|---|
| Confluence（新版编辑器） | 认 | **不认**，过滤成普通字符 | 直粘 MD 源不识别时用自带 Markdown 宏 |
| 语雀 | 认 | 基本认 | 新版支持度更好 |
| 飞书文档 | 认 | **不认** | 表格单元格不支持内联 HTML |
| VS Code / GitHub 预览 | 认 | 认 | 本地正常不代表目标平台正常 |

平台会更新，这张表只当起点——**每次交付前照「第一步」验一遍，以当场结果为准**。
