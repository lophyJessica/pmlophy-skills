# Codex 填充指令模板（单据套件）

架子搭好后，给**每个单据**生成一条这样的五段式指令，丢给 Codex 填占位文件。
一个单据一条指令；有上下游依赖的**先跑上游**（PR→PRO、RCV→质检→PUT、WAVE→PICK）；
并行封顶 2-3 条，**同项目内别同时改同目录**。生成的指令存进项目 `prompt/` 文件夹，命名 `{单据}_Codex填充指令.md`。

把下面 `{{...}}` 占位替换成具体值即可（类型决定套件文件集与 Demo 页命名，见 forge-prd-scaffold 的 4 种套件类型表）。

```
Context:
我在做 {{项目名，如 Forge 进销存/forge-erp}} 的 PRD 套件补全。读者是研发/测试/产品复核。
本次补全「{{单据名}}（{{单据编码，如 RCV/PICK/PR}}）」——{{一句话定位：它在链路里的位置 + 上下游}}。
两依赖已就位，请先读：
- 业务地基 context/：{{按需列章节，如 04-入库流程详解、09-单据命名规则、11-字段校验规范、08-术语口径}}
- 格式模板 templates/：{{对应模板；WMS 若无 templates 则写"结构照 AGENTS.md 的 PRD 套件章"}}
- 参照物套件（结构/表格/语气对齐）：{{同类型已完成套件路径，如 prd-docs/采购管理/采购入库单/（执行类最全 8 件）}}
- 内容锚点：{{已有主PRD 或模块主PRD 路径 + 相关章节，作为唯一事实来源}}

Request:
{{补齐 / 从模块PRD拆出}} prd-docs/{{模块}}/{{单据}}/ 下 {{件数}} 个文件：
{{逐个列出要产出的文件名}}
（占位文件顶部提示头的两行 HTML 注释，写作前删掉）

Output format:
按 AGENTS.md 套件规范：字段清单=SSOT（分组+来源+类型+必填+枚举）；业务规则规格=状态机+校验+权限+计算；
流程/用例带真实示例数据；Demo 写页面结构不重复枚举。业务流程必须含 Mermaid 业务流程图 + 系统时序图（核心规范5）。

红线禁止:
- 不改已有：不动 {{已有主PRD/锚点}}、context/、templates/、参照物、AGENTS.md、DESIGN.md
- 不加不该有：{{执行层单据 → 状态只"草稿→已确认"，严禁"待审核/已审核"；执行类无"新增"入口，必须上游下推；查询页无状态机}}
- 不越界发挥：{{库存过账时点/单号前缀等拿不准的 → 严格按 context，拿不准就标注不确定，别自己拍板别自创}}；术语按 context 口径；Mock 日期用 2026；数据冲突以 context/简历为准，不编造
如信息不足，明确标注不确定性。

Checkpoint:
除非涉及不可逆操作、范围变化或需要我补信息，否则一次做完再汇报，附每个文件要点 + 不确定项标注。
```

## 关键要点（本会话实战归纳）
- **主PRD 已有则不改，只补其余套件**（ERP 退货单就是这种：主PRD 是 V1.0 真内容，Codex 只补 7 件）。
- **模块主PRD 很厚时（如 WMS 入库 252 行）**，指令写"从模块主PRD 拆出本单据内容"，红线注明"引用+细化，不搬走删除模块PRD"。
- **过账时点 / 单号前缀 / 字段来源** 这类我方拿不准的，一律进红线让 Codex "按 context、拿不准就标注"，绝不替它拍板——防幻觉最有效。
- **配套依赖**：五段式模板本体见 `structured-ai-prompt-template` skill；红线素材直接从项目 `AGENTS.md` 的"AI 常见错误"表抽。
