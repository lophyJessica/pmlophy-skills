# 六维走查 → 返修 回环（Forge PRD 实战工作流）

PRD 套件由 Codex/反重力填完后，**不要直接写前端**。走 AGENTS.md 的「走查过关再写前端」。
本文记录本会话验证过的完整回环打法。

## 1. 用并行子 agent 做走查（省 context、抓跨文档问题）

一批填好的单据（本会话 6 个单据 × 8 文件 + 两套 context ≈ 60 文件），
**别自己全读进主上下文**——会爆 context、也慢。按业务链拆成 2-3 路 `delegate_task` 并行：

- 拆分维度 = 业务链（如 ERP退货链 / WMS入库链 / WMS出库链），每路查 1-2 个单据的整套。
- 每个子 agent 的 context 里给全：项目根、待查文件清单、`AGENTS.md` 六维标准的位置、
  权威层级、地基 context 章节、参照物套件、**已知疑点**（让它重点核实）。
- 子 agent toolset 用 `["file","terminal"]`，**只读审查，红线写死"不改任何文件"**，全程中文输出。
- 输出格式统一：`## 总评` + `## 问题清单(严重程度[高阻断/中/低]|文件|问题|修正方向)` +
  `## 地基级问题(需回溯 context/)` + `## 已正确项`。这样主 agent 好合并。

价值：三路各自逐字读 context 原文，能抓出主 agent 一眼看不到的**跨文件/文件内自相矛盾**。
本会话就靠它挖出 context/05 **文件内部**流程图与文本打架（比最初报告的 05↔06 冲突更严重）。

## 2. 合并结果，按"先改什么"分三层

把子 agent 的问题清单合并，**按修复顺序（不是严重程度）重排**：

1. **🔴 地基级(context)** —— 必须最先改，否则下游继续踩、返修白做。
2. **🟠 已填 PRD 返修** —— 地基定稿后才改。
3. **🟡 低级(命名/Mock/参数风格)** —— 顺手带。

## 3. 地基修复：**不需要 Codex，主 agent 自己改**

context 的修复通常是小而精准的改动（走查会给逐行改法）。主 agent 直接 patch VPS 副本、
`show diff` 给用户审、发 corrected 文件让用户拖到 Mac 替换——**绕开 Codex/反重力 瓶颈**
（本会话 Codex 额度耗尽时靠这招继续推进）。典型地基修复：

- **库存三口径记账错误**：出库实扣常被错写成「可用-N」。但可用已在 SO 审核占用时减过一次，
  再按可用扣就是**重复扣、对账错乱**。正确：实扣 = 「现存-N、释放占用-N」，可用不动
  （可用 = 现存 - 占用 - 冻结，出库时现存与占用同步-N，可用不变）。
- **过账时点单一化**：出库链扣减点定在「包装完成 PKG」（数量已锁、可回溯），交运只作订单完结；
  流程图节点、业务规则文本、下游各单据措辞必须全部对齐同一个点。
- 改完让用户先替换 context 到 Mac，**再**跑 PRD 返修（返修要引用修好的地基）。

## 4. PRD 返修：出"返修指令"交给 Codex/反重力

按三条业务链各出一条返修指令（`返修-并-{链名}` 命名，可并行——不同文件夹/项目互不抢写）。
每条指令 = 走查发现的**具体修复清单** + 红线（不改 context/AGENTS/参照物、不重新脑补、执行层无审核流…）。
指令头写清前提「已把修好的 context 替换到项目」。

## 5. 决策先行

返修里凡涉及**业务设计选择**的，先让用户拍板再出指令。本会话三个决策：
- 质检 = 独立单据 or 收货单内环节？→ 归入收货单（按 context），删 `质检单/` 空夹。
- 一期支持分批退货出库吗？→ 不支持，PR:PRO 严格 1:1，删 PRO 分批设计。
- 品牌 = Forge or 强盛科技？→ 保留强盛科技当演示公司名，context 不动。

## 6. 快速验收（抽检，别重读全部）

返修回来后，**grep 抽查关键几处**即可，不必再读全部文件：
```bash
# 例：质检字段收回没 / PRO 分批删干净没 / "可用-N"措辞改对没 / 分层与 Demo 命名
grep -nE '合格数量|qc_no|质检单' 收货单字段清单.md
grep -nE '分批|1:N|已出库|可出库数量' 采购退货出库单主PRD.md 采购退货出库单字段清单.md
grep -rnE '可用库存-N|可用-N' prd-docs/出库管理/波次/ prd-docs/出库管理/拣货单/
grep -E '第[23]层' 采购退货出库单主PRD.md
```
十来分钟出结论，确认全绿再让用户 push + 部署。
