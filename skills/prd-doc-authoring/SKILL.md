# 评审PRD 编写工作流

## 定位（用户2026-09定）
评审PRD = **评审用完整档**：把主PRD(规则) + Demo(页面) 合并成一份，**评审人读它就能审、开发按它就能做**，不用切换多份PRD。
- 评审现场：在原型图上打开原型标注逐个讲角标；评审PRD是把现场固化下来，评审后凭它回看（别人/以后看不到原型标注）。
- **自包含交付件，全文零外引**：评审PRD = 唯一交付件，评审人/开发只看这一份就能干活，**不出现任何 TSV / 字段清单详细稿 / 权威源 / 主PRD 引用**。TSV 是内部梳理工具，交付时删净——用户"谁知道你详细稿啊，我要的是这一个PRD评审后就可以去开发了，全部看这一个PRD"。头部声明写自包含口径（"本件为自包含评审档，覆盖全部需求，评审通过后可直接作为开发依据，无需再查其他文档"）。

## 关键治理三铁律
1. **权限按需**：只有需求分析明确区分了"不同角色所看/所操作不同"、或系统未实现RBAC需页面做角色控制时才写权限；否则标注"由运维/运营/RBAC管控"。AI爱硬加权限，默认不加。
2. **大白话全中文**：目录结构全中文，禁令写 In/Out of Scope、SSOT、RBAC 等英文术语；枚举/代码字段值保留英文给研发对照，但描述必须中文。
3. **功能清单=原型标注角标一一对应**：**功能清单的条数 = 原型标注角标数**，一个角标一个功能一条。

## 章节结构（必有 + 按需）
**必有**：业务总览(做/不做)｜功能清单(序号+功能+**功能描述**+本期?)｜主要流程(含Mermaid图)｜状态流转(单据有才写)｜业务规则(序号|什么情况下|结果)｜页面和操作(每页功能清单表)｜字段清单｜验收标准(输入条件→预期结果)。
**按需**：权限(见治理)、状态机、异常边界——有才写，无则标"不适用"。

## 业务规则表（序号跨表重置）
- 业务规则每张子表(5.1/5.2/…)表头 `序号 | 什么情况下 | 结果`，序号**每张子表各自从1开始，跨表不接续**——用户明确"跨表格后要重置序号从1开始"。
- 编号列写"序号"，规则项写普通数字(1、2、3…)，不用 R01/R02 这种内部编码（和功能清单/页面表一致，全文档无"编号"列头、无字母前缀编码）。

## 页面和操作（五列表格，核心）
每页格式：`| 序号 | 操作路径/功能点 | 原型页面 | 页面说明 | 备注 |`
- 表头五列：**序号 | 操作路径/功能点 | 原型页面 | 页面说明 | 备注**。序号每页独立从1开始(列表1..9、新增1..6、详情1..11)，与二章功能清单序号对应。
- **序号用"序号"字样，不用"#"**——用户明确"列头要改成序号，不是#号代替"。功能清单二章(序号|功能|**功能描述**|本期?)首列同样是"序号"不是"#"。**第三列列名写「功能描述」，禁写「一句话说清」**——那是描述写作要求，不是列名，用户纠正过。
- 表头列名逐字对齐：第2列操作路径/功能点、第3列"原型页面"(不是"截图")、第4列"页面说明"(不是"说明")——用户对列名敏感。
- **操作路径必须具体到功能点**：`线索管理/线索列表-状态页签`、`线索管理/线索列表-新建与导入`——不能都是粗页面名。
- 原型页面 = **整页截屏 + 红虚线框圈选该功能点所在区域**（一功能一行一图，26角标=26张整页向量红框图）。不是区域小图！
- 页面说明 = 该角标对应原型标注块内容搬运(逐字不脑补)。
- 备注列留空，评审遇待确认时手填。
- **不出现"功能清单（F1-F6 共 6 个角标）："这类带角标计数的副标题**——直接进表格（"功能清单"正文章节标题可留，"（x角标）"计数副标题删）。
- **不要在页面顶部另放一张独立整页大图**——它和表格里 L1/F1/D1 行的整页红框图重复(曾被用户指出"大页面和下面表格重复")。直接进表格，每行自带整页红框图。
- 页面级角标(如页面/权限/本页规则)截整页，弹窗类角标用弹窗截图。

## 图的形态与流程图硬规则

**flowchart 首尾必须有开始与结束节点，且开始节点必须在整图最顶端（2026-10-31 用户当场纠正）。**

- 缺开始/结束 = 流程没头没尾，评审会问「从哪里进来、到哪里结束」。
- **开始节点不能在途中**：Mermaid 按连线关系自动布局，把 `STRT(["开始"]) --> 第一个节点` 写在 subgraph **内部**时，它会被自动排到中途（实测跑到判断节点左下方）。正确写法：开始节点写在 `flowchart TD` 之后第一行、**subgraph 外面**，再指向第一个业务节点；结束节点同样写在所有 subgraph 外面、末尾。
- 形状用体育场形 `(["开始"])` / `(["结束"])`（左右半圆的胶囊/椭圆），**不用 `(("开始"))`圆形**；中间业务节点保持方角 `[...]`，评审才分得清出入口。
- 写完不靠想象验收：让用户或 agent 把图渲染出来看一眼开始节点是否真在顶部；Mermaid 自动布局会因回连线（如「不满足则回到提需求」）改变节点位置，出现偏离就把回连线也移到 subgraph 外重排。

## 截图规范
- **截图前先核目标交互能不能被真实触发（2026-10-30 实测踩坑）**：脚本能跑、图能出，
  不代表图里有所要表达的状态。mock 数据不支撑时截出来的是「空验证」——实测要求交「好友标签超过两个显示 +N」的图，mock 里每行最多两个标签，图出来了但那行只是两个标签、没有 +N，agent 自检写「22/22 图存在且有红框」，验收时发现整张图是假的。
  固定前置动作：逐条问「这个交互要出现在图上，需要什么数据前提」→ 到 mock 里核数据存不存在 → 不存在就**先补 mock 数据再截**，补不了就在交付里写「该交互 mock 不支撑，图待补」，不许交一张看不出该交互的图充数。
  验收时看图上有没有那个元素，不看「图文件存在」这个事实。
- 准确：截自真实可运行原型，不脑补；图上内容与说明一致。
- 全面：主页面+关键交互(弹窗/Toast/二次确认/批量/空数据)都要截。
- 文件名中文+对应功能，如 `线索列表页-L2-状态页签与线索池视图.png`。
- **整页 + 单角标红虚线框**（用户强调不展示其他角标框）。
- 批量截图分工见 `references/antigravity-ego-screenshot.md`（反重力+ego lite 备用方案；主路径 Playwright+Pillow 本机自动画框省额度）。

## 字段清单（六列，标题标页面归属）
- 标题必须标明页面归属：`**线索列表页-字段清单**` / `**线索新增/编辑页-字段清单**` / `**线索详情页-字段清单**`——不写笼统"字段清单（列表展示关键字…）"，评审人一眼知是哪页。
- 六列：`字段名称 | 填写格式 | 是否必填 | 字段来源 | 能不能改 | 字段说明`。
  - 字段来源 = 用户手输/用户选择/系统生成/系统计算（用户明确"是手输还是系统生成"）。
  - 填写格式 = 输入约束，如"文本，限100字符""11位数字"；字段说明 = 补充约束，如"与邮箱至少填一个；全局去重"。
- **值全部取自字段权威源**（字段清单详细稿，**TSV 或 md 均可**——命令行字段清单常是 md，不要只认 .tsv，曾因 skill 写死 .tsv 而误判商机无权威源）——评审PRD只搬运/转译，不脑补不造数。措辞可轻度转译(如TSV"文本,上限100"→"文本，限100字符")，语义必须一致，不加新字段/新规则。md 字段清单的列(字段名称|字段来源|取值说明|必填性|新增页|编辑页|字段说明)可直接映射六列。
- **只列业务可见字段，剔除英文技术字段**——评审PRD是给人看的，`crmCustomerId/erpCustomerId/customerSnapshotVersion/customerSnapshotSyncTime/erpProductId/unitPriceSnapshot` 这类跨系统技术标识符**不单独成行**（用户红框指出"怎么还有英文字段名称"看不懂）。技术细节收进所属业务字段的"字段说明"里隐含交代（如"关联客户"说明写"保存客户标识与快照版本(含CRM和ERP双标识)，不以名称作关联键"）。字段表全程不出现英文小写字段名。

## 交付 = base64 内嵌发布版（唯一形态）
- 交付一律**在线预览**（导入语雀/Confluence），不打包zip、不发原文md。
- 用项目里的 `09-脚本工具/embed_images.py`（或本 skill 脚本 `scripts/embed_images.py`）把 md 里 `![](./images/x.png)` 替换成 `data:image/png;base64,...` 生成自包含发布版(`{名}-发布版.md`)，导入任何平台路径不断、图可放大。
- 仓库维护用引用版(md + images/)，发布版只在交付时生成。发布版里有 base64 码是正常的，别直接读md，用渲染器看。
- 语雀/Confluence 导入后图片可点击放大（Cursor/GitHub 预览不支持放大）。

## 可执行脚本（本地 agent 照跑，别手写逻辑）
评审PRD不能靠 agent 每回现写截图/提取逻辑（易卡壳或伪造）。skill 自带两个脚本，agent 只需填参数启动：
- **`scripts/capture_orm.py`**：批量截图整页红框图。读 annotation.config.json 自动构建任务，Playwright 打开线上原型拿 data-anno 锚点坐标 + Pillow 画红虚线框，逐角标出图。用法：`python3 scripts/capture_orm.py --config <项目>/annotations/annotation.config.json --out-dir images --base-url https://pmlophy.com/project/<项目>/# --name-prefix '商机列表页-'`。页面级角标(type=page/page-global)自动截整页无框。
- **`scripts/extract_body.py`**：从标注文件提取页面说明。自动剔除来源行/表格行/待确认段，输出连贯中文说明供评审PRD"页面说明"列。用法：`python3 scripts/extract_body.py annotations/pages/<页>.md...`。
- **`scripts/embed_images.py`**：base64 内嵌生成发布版。

## 生成整页红框图的可行做法（Playwright+Pillow）
优先用 `scripts/capture_orm.py` 脚本跑；以下为原理与坑，脚本卡壳时排查用：
- Playwright 打开页面，对每个角标 `document.querySelector("[data-anno='xxx']")` 拿 bounding box（含 scrollY 偏移）。
- 用 Pillow 在整页图上画红虚线矩形圈住该角标区域（dash=8,gap=4,width=3,padding=6）。每角标一张=底图同(同页)、框位不同。
- 表格高超出视口时整页图=首屏900px(列表是滚动容器，full_page不扩展)；框截到视口底即可。
- 弹窗类角标需触发弹窗后截（如点"转为正式客户"出弹窗——按钮文字可能是"转为正式客户"不是"转客户"）。
- **弹窗触发受业务状态锁定**（商家实测踩坑）：商机合同签订态/赢单/输单终态会锁死推进等动作，弹窗不出现（如"关联合同签署中,商机不可操作"）。此时先识别是"该商机本来就不能触发"（业务正确，换能触发的商机）还是"需要绕过"（用无关联记录、非终态的商机/路由触发）。终态或已关联业务记录不能硬触发——不要靠反复点无用功，改用状态满足条件的对象/页面。
- **双视图/多态页**：页面有看板/列表等视图切换时，不同锚点只在其对应视图渲染（商机看板态取不到列表页签/表格锚点为null）。截图前必须切换到目标视图再取锚点；锚点 null 先判断"是否需切换视图/交互/弹窗"再决定，不直接判定失败。

## 文档头部与修改记录
- **头部分两块**：版本行 + `## 修改记录` 表格。修改记录列 `日期 | 版本 | 修改人 | 修改内容`，在文档最上面（版本行正下方）。
- **命名"修改记录"，不叫"变更台账"**——台账是财务/交易系统术语，评审PRD用它指代文档自身修订史是误称，用户纠正过。
- 修改记录定位 = **这份文档的更新操作记录**，只记"版本/改了什么"。不要把"回写目标/回写完成"这类回写skill字段混进来——那是回写权威源做的事，与文档修订史职责分开。

## 删制作说明句（评审PRD只留业务内容）
用户(2026-09)定：评审PRD的受众是评审人+开发+自己，**不给看"这个内容怎么来的/怎么做出来"**。以下制作过程/来源/how 句一律删，不出现：
- "由原型标注搬运整理而成""与原型标注角标一一对应、共26个""评审时在原型图上讲述角标""每条功能对应一个标注块/角标""每页展示整页截图，下方按功能点列出该页功能清单…"等——全文不出现"角标/标注块/编写规范"行话。编写规范(该章怎么排版)是给作者的，评审人不看，章节开头这类引用说明也删。
- 字段/规则的权威来源在文件头已用"自包含"口径交代（见定位），正文不再指向任何外部文件。

## 迭代纪律
- 用户用 forge-crm 线索管理做验证场（示例即可，不要求其他模块补全）。
- 每版改完 push main，用户 pull 后在 GitHub/语雀看渲染验收。
- 模板在 `04-常用模版/评审PRD模板.md`；**项目内脚本统一放在 `09-脚本工具/`**（`embed_images.py` / `capture_orm.py` / `extract_body.py` / `status_enum_mining.py`），同一套脚本在本 skill `scripts/` 也有一份。用户明确要求脚本集中，**不准再把 .py 散落到模板目录或其他功能目录**。
- 改表(re批次/加列/删行)别手改——用脚本：按页表头重置序号计数、整表替换，改完核验三表序号各自连续、无残留旧表头。
- **改序号务必要确认做过一次后所有表各自从1重排**：一次全局替换 R01-R## 会按出现顺序编成全局连续号(5.2变成6,7,8…)，不是想要的"每表从1"；重排脚本的"表格内"标志必须随 `### N.m` 小节头重置，否则会越过表类型继续累加，把后面功能清单表/字段表的序号一起污染成错值。改完逐表打印序号核验(5.1:1-5、5.2:1-4…、6.1:1-9…)，别只看单页。
- 清理外部引用/编号改号时，全文黑名单检查再 push：TSV、详细稿、权威源、角标、标注块、编号、R0、`#`列表头，一处都不留。
- 字段/数据一律实测/读权威文件确认，不凭记忆下结论（"信息做减法"：评审PRD不造数据）。
