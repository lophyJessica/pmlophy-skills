# AI 业务调研方法论

核心共识（2026-08-20 资料综合）：**AI 不是替代人的判断，而是把"最耗时、最机械、最易出错"的部分自动化，让研究者的时间压缩到"判断"和"对客户的行动"上。** 这跟用户一贯的"人做判断、AI做执行"理念同频。

## 触发场景
- 用户要"用 AI 做业务调研 / 用户研究 / 市场调研 / 交接陌生行业 / 快速了解甲方业务"
- 乙方场景：交接 ERP/WMS 类项目、给甲方做需求调研、生成访谈提纲
- 需要从访谈/评论/工单/行业报告中提炼洞察

## AI 在调研链路里真正擅长的（回报最高、风险最低）

| 环节 | AI 能做什么 | 风险 | 怎么用 |
|---|---|---|---|
| 二手资料/桌面研究 | 快速读行业报告、竞品、财报，提炼结构化要点 | 低 | ✅ 交给 AI 大批量做，最高效区 |
| 大规模编码/标注 | 把人工定的编码表应用到几十份访谈稿 | 低 | ✅ 40份→一致编码，省时最多 |
| 持续反馈分析 | 应用商店评论、工单、NPS、聊天记录（人读不完的量） | 低 | ✅ 解读被丢弃的数据，回报最高 |
| 访谈转录+初筛 | 说话人分离、时间戳、打标签 | 中 | ✅ 自动化+抽查 10% |
| 访谈提纲初稿 | 生成提纲、追问方向、检查诱导性问题 | 中 | ⚠️ 草稿加速器，人至少重写一半 |
| 综合洞察 | 聚类、跨参与者找模式、写第一版叙述 | 高 | ⚠️ 仅供参考，所有主题溯源 |
| 招募筛选 | 起草筛选问卷、识别矛盾回答 | 中 | ⚠️ 仅协助，终审人工 |
| 合成用户/虚拟受访者 | 生成模拟受访者来访谈 | 极高 | ❌ 绝不能作为证据，只用来演练提纲 |

## 4 大失效模式（必须防，乙方最贵）

1. **频率伪装成重要性**——AI 突出"出现最多的"，但价值在"少数放弃常规流程的异常者"。→ 主动问"谁不同意共识？他说了什么？"答不出=摘要不完整。
2. **流畅的发明**——AI 会捏造听起来真实的引语安到没说过话的人头上。→ **每条引语必须带访谈稿编号+时间戳**，源头找不到就不交付。
3. **谄媚式综合**——喂假设+数据，AI 会顺着假设得出"支持你假设"的结论（咨询最贵失败：交付客户想要的但废了）。→ **综合时不喂假设**；检验假设单独跑对抗测试"找出最有力的反驳证据"。
4. **合成用户当证据**——模拟受访者结论完全是模型偏见。→ 只用于演练访谈提纲，绝不作为研究结果。

## 7 步可落地工作流（编码-双校验-综合）

```
1. 人先读 3-5 份访谈/资料，手工搭"编码框架"（源自本数据，非通用模板）
2. AI 用这套框架批量编码（固定手册，运行中不新增类别，框架外标"未分类"——往往最有价值）
3. 15% 样本人工+AI 双编码，测不一致率：<10% 继续；>20% 说明编码手册错（非模型错），回第1步
4. 综合草稿（不喂假设，只给语料库+研究问题）
5. 可追溯性检查：每条主张关联≥2受访者+时间戳，无法追溯即删；仅1位支持标"单条观察"
6. 用行为数据三角验证：访谈说的≠实际做的 → 行为数据优先
7. 人写最终建议（在这个组织/约束/路线图下怎么落地——必须人判断）
```

## 乙方/交接陌生行业的具体用法

**A. 快速建行业认知（AI 桌面研究）**：按固定模板扫描 → 行业术语表 / 核心业务环节 / 主要角色与职责 / 关键业务流程 / 上下游 / 行业痛点与合规 / 竞品与标杆 → 输出"行业速查手册"

**B. 访谈提纲生成**：给 AI 研究目标+已知信息 → 生成提纲初稿+追问方向+检查诱导性问题 → **人至少重写一半**（AI 生成通用，要结合甲方实际业务）

**C. 访谈纪要→结构化**：人先定编码框架 → AI 批量编码 → 双编码校验 → 输出"需求池/痛点清单/优先级"

**D. 三向对齐**：AI 帮把 访谈记录/PRD/现有系统逻辑 对齐，找契约缺口（与原型标注三向对齐审计同理念）

## 访谈问卷落地闭环（2026-08-25 forge-scrm 二期实测）

提纲 → 可填写问卷 → 访谈/回收 → **矛盾标注** → 结论+待确认项。四步增量经验：

1. **提纲转 Word 问卷（给 agent 的 python-docx 指令要点）**：开放题下挂表格答题区（首列问题、次列空单元格，行高 1.5cm，步骤类/反方钢人题加高到 2.5cm）；选择题用 `☐`（多选）/`◯`（单选）前缀逐行列出、留勾选空间；每题标【开放题】【单选题】【多选题】；中文字体必须显式设 eastAsia（否则 Word 乱码）；开头加受访者/日期/访谈人/方式信息栏。产出 docx 走 git 进 requirements/。
2. **回复必须做"矛盾标注"**（问卷高频出现，别当没看见）：勾选与开放题回答冲突（如勾了"行业报告"但要自动的却是"对标账号"）→ 列入待澄清项回访；受访者"直接信采集数据"与既有规则"AI 产物必须审核"的张力 → 澄清是**原始采集数据**（可直接用）还是 **AI 分析/生成结果**（必须审）——两类数据审核边界不同。
3. **需求层级变化识别**（比收集功能清单更重要）：问出"为了一个主题会研究一整天""一周花 30+ 小时手动查资料""价值非常大，非常想要"这类回答 = 需求从**固定流程生成**升级为**开放式研究型 Agent**——架构决策完全不同（要联网/检索/长任务），识别后单独视为一个需求层级，别混进功能清单排期。
4. **P0 双重验证**：单选问"二期只做一件事选哪个" + 反方钢人问"哪个不做先出事"，两题答案指向同一项 = P0 锁定（本实例：双题都指"自动采集"）。P0 之外"价值非常大"的需求（研究助手）排第二档但要在结论里显式保留，防止被 P0 讨论淹没。

## 调研启动前置检查（网易智企 3 问）
1. 调研目标用来做什么决策？（NPS 追踪 vs 需求挖掘——访谈策略完全不同）
2. 样本从哪里来、可信度够不够？（分层抽样，别只抽高活跃老客）
3. 结果有没有明确行动链路？（报告必须能转成可执行动作+责任人+时间）


## 资源充足但任务已收口时

额度、工具或时间充足，不代表必须人为制造任务消耗。先盘点真正未完成的事项；如果主线已经收口，保留资源给未来高价值任务，不要为了“烧额度”扩张范围、重构已跑通系统或开启低价值研究。研究型工作只有在真实决策、真实需求或明确交付目标存在时才启动。

双向钢人法用于帮助用户看清真实取舍，不是用来把用户已经明确提出的方向重新辩回保守方案。若用户问“哪个更适合”，先直接给结论，再补关键条件；不要为了展示完整性而把正反两方平均铺开，更不要在用户已经说明新增需求超出旧方案边界后，继续替旧方案辩护。

正确顺序：

1. 先识别需求是否已经发生层级变化（固定流程 → 开放式研究/联网/动态决策）。
2. 先给当前需求下的主判断。
3. 再说明保留旧系统作为过渡或兜底的组合方案。
4. 只有用户要求比较成本、风险、迁移代价时，才展开完整双向对比。

用户纠正“你这铁人论在跟我实施了”时，说明分析已经从辅助判断变成了反向劝阻；应立即收束，不继续解释方法论。
